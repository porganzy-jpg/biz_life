# 12-my-voice — 내 목소리 TTS

텍스트를 넣으면 **내 목소리로 읽어주는** 도구. 음성 합성(edge-tts)으로 문장을 만든 뒤
직접 학습시킨 RVC 모델로 음색만 내 것으로 바꾼다.

```bash
python say.py "안녕하세요. 안녕히 주무세요."      # 텍스트 → 내 목소리
python fit_check.py 노래.mp3                      # 이 곡이 내 목소리에 맞는지 점수로
python cover.py 노래.mp3 --keep-parts             # 노래의 보컬만 내 목소리로
python mix.py songs/노래_내목소리_파트            # 완성된 곡처럼 믹싱  ← 체감 차이 큼
```

## 얼마나 비슷한가 — 측정 결과

음색 거리는 MFCC 평균 벡터 사이의 거리다. **0에 가까울수록 실제 목소리에 가깝다.**

| 단계 | 음색 거리 |
|---|---|
| 변환 전 합성음 | 58.2 |
| v1 모델 (유튜브 음원만 10.5분, 200에폭) | 36.4 |
| v2 모델 (직접 녹음 절반 포함, 100에폭) | 18.6 |
| **v2 + 문장을 이어붙여 한 번에 변환** | **14.4** |
| **실제 목소리끼리의 거리 (최저선)** | **11.6** |

### 최저선이 0이 아닌 이유

같은 사람이 같은 날 말해도 문장마다 음색이 조금씩 다르다. 목 상태, 말하는 속도, 문장의 내용에 따라
공명이 달라지기 때문이다. 내 녹음 8조각을 서로 비교했을 때 그 변동폭이 **11.6**이었다.
즉 11.6은 "같은 사람이라도 이 정도는 다르다"는 기준선이고, 변환 결과가 이 값에 가까울수록
사람 귀로는 구분하기 어려워진다.

현재 14.4로, 최저선과의 차이는 **2.8**이다. 시작점(58.2)에서 보면 **94%를 좁힌 상태**다.

### 에폭별 비교 (v2)

| 에폭 | 전체 음색 | 문장 끝음 |
|---|---|---|
| 50 | **19.4** | 31.8 |
| 100 | 19.7 | **29.1** |
| 150 | 21.7 | 30.1 |
| 250 | 23.6 | 29.9 |
| 300 | 20.7 | 29.2 |
| (최저선) | 11.6 | 28.3 |

- **에폭이 높다고 좋지 않다.** 데이터가 10분으로 적어 사전학습 모델에서 조금만 조정해도 충분했고,
  오래 돌리면 학습 데이터를 외워버린다(과학습).
- 50에폭은 전체가, 100에폭은 문장 끝음이 낫다. 두 모델 가중치를 25/50/75%로 섞어봤지만
  100에폭 단독보다 나은 조합은 없었다. 그래서 **100에폭을 채택**했다.
- 문장 끝음은 이미 최저선(28.3)에 거의 도달했다. 끝음은 본인 목소리끼리도 변동이 커서 원래 값이 높다.

### 변환 파라미터 — 인덱스 반영도

인덱스 반영도(`index_influence`)를 올리면 학습한 음색에 더 가까워지지만, 값이 높으면
인공적인 공명("울리는" 느낌)이 생길 수 있다. MFCC 거리로는 이 인공음을 잡아내지 못해
네 단계를 만들어 귀로 비교했다(`samples/울림비교/`).

| 샘플 | index | protect | 음색 거리 |
|---|---|---|---|
| **A (채택)** | **1.0** | **0.0** | **9.2** |
| B | 0.6 | 0.0 | 10.0 |
| C | 0.4 | 0.33 | 11.0 |
| D | 0.0 | 0.33 | 11.9 |

A → D 로 갈수록 인공적인 울림은 줄지만 음색은 멀어진다. 들어보고 **A를 채택**했다.
울림이 거슬리면 `--index 0.6` 처럼 낮춰 쓰면 된다.

참고로 "울림"의 원인을 따로 측정해 보니 잔향은 아니었다. 쉼 구간 에너지가 실제 녹음보다
오히려 낮았고(-52dB 대 -39dB), 주파수 대역 차이도 최대 3dB로 작았다. 문장 끝음의 울림도 정상이다.

### 짧은 문장을 이어붙여 변환하는 이유

문장을 하나씩 따로 변환하면 짧은 문장의 음색이 흔들린다. 모델이 참고할 음성 맥락이 부족하기 때문이다.

| 방식 | 평균 | 가장 나쁜 문장 |
|---|---|---|
| 문장별로 변환 | 18.6 | 28.6 (1.8초짜리) |
| **이어붙여 한 번에 변환 후 되자름** | **14.4** | **18.3** |

`say.py` 는 여러 줄을 받으면 자동으로 이 방식을 쓴다. 파일 단위 변환은 `convert_joined.py`.

## 노래 커버 (`cover.py`)

노래 파일을 넣으면 **보컬만** 내 목소리로 바꾼다.

```bash
python cover.py 노래.mp3                  # 음역을 분석해 반음 조정까지 자동
python cover.py 노래.mp3 --pitch -12      # 여성 보컬 → 남성 (한 옥타브 내림)
python cover.py 노래.mp3 --keep-parts     # 분리된 보컬·반주도 남김
```

1. Demucs 로 보컬 / 반주 분리
2. 보컬만 RVC 변환 (원곡 보컬의 음높이 중앙값과 내 목소리 110Hz 를 비교해 반음 자동 계산)
3. 변환 보컬 + 원래 반주 재믹스

CPU 로 돌아가며 **곡 길이의 2~4배** 걸린다(3분 곡이면 10분 안팎). 첫 실행 때 분리 모델 173MB 를 자동으로 받는다.
음량은 `--vocal-gain` / `--inst-gain` 으로 조절한다.

Suno 로 만든 곡에 쓰면 "내가 부른 것처럼" 들리는 결과가 나온다.

## 노래 변환의 한계 — 측정으로 밝힌 것

| 확인한 것 | 결과 |
|---|---|
| 음정 추적 정확도 | **0.06 반음** — 원곡 멜로디를 정확히 따라감 |
| 멜로디 모양 보존 | 상관계수 0.64~0.84, 지정한 이동량과 오프셋 정확히 일치 |
| 표현 변화량 (미세한 목소리 움직임) | 변환본 **3.5** / 실제 목소리 5.24 / 원곡 보컬 5.02 |

음정·박자는 문제가 아니다. **변환본이 사람 목소리보다 매끄럽다**는 것이 핵심이다.
목소리가 순간순간 변하는 미세한 움직임이 사라져 밋밋하게 들리고, 그것이 "가창력이 없다"는 인상을 만든다.

### 시도했다가 실패한 것

| 방법 | 결과 |
|---|---|
| 포먼트 유지 사전 음높이 이동 | 표현 변화량 3.35, 음색 12.9 → 14.4 악화 |
| 원본 보컬 12~35% 섞기 | 표현 변화량 그대로, 음색 13.5 → 24.2 크게 악화 |
| 숨 필터 강화 (respiration 7) | 양쪽 다 악화 |
| 에폭 5종 비교 (50~300) | 100에폭이 노래에서도 최고, 매끄러움은 전부 동일 |

파라미터로는 더 나올 것이 없다. 원인은 **학습 데이터가 전부 말소리(66~151Hz)** 라는 데 있다.
모델은 학습 분포 안에서만 디테일을 재현하고, 노래처럼 모르는 구간에서는 평균적인 출력을 낸다.

### 고음 합성 (`make_highpitch.py`)

내 말소리에서 "내가 높은 음을 내면 날 소리" 를 합성해 학습 데이터에 보탠다.
음높이(성대 진동수)만 올리고 포먼트(성도 공명 = 목소리 지문)는 그대로 둔다.

| 구분 | 음높이 | 음색 거리 |
|---|---|---|
| 원본 말소리 | 116Hz | 기준 |
| +4 반음 | 146Hz | 22.3 |
| +8 반음 | 185Hz | 32.0 |
| +12 반음 | 233Hz | 44.6 |

많이 올릴수록 합성 티가 난다(4반음은 같은 사람으로 들리는 수준, 12반음은 벌어짐).
실제 고음 발성은 숨과 성대 긴장이 달라 완전히 같지 않다. 그래도 "높은 음을 아예 모르는" 지금보다는 낫다.
결과물: `dataset_v3` (24.7분, 음역 66~280Hz). 재학습용.

### 곡 적합도 측정 (`fit_check.py`)

```bash
python fit_check.py 노래.mp3
```

곡 중간 60초의 보컬을 분리해 음역·창법을 재고 필요한 이동량과 적합도를 점수로 낸다.
전곡 변환(10~20분)보다 훨씬 빨라 후보를 미리 거를 때 쓴다.

| 실측 예 | 보컬 중앙값 | 이동량 | 적합도 |
|---|---|---|---|
| 잔잔한 남성 발라드 | 204Hz | -3.5반음 | 83점 (매우 적합) |
| K-pop 여성 보컬 | 472Hz | -18반음 | 45점 (부적합) |
| Le Festin | 328Hz | -19반음 | 낮음 |

**이동량이 작은 곡(남성 저음~중음)을 고르는 것이 품질에 가장 크게 기여한다.**

## 믹싱 (`mix.py`) — 유명인 커버와의 진짜 차이

유튜브의 AI 커버가 잘 들리는 이유 중 **가장 과소평가되는 것이 후반 작업**이다.
변환 직후 소리를 그대로 올리는 커버는 없다. 아래를 거치면 같은 변환 결과도 완성도가 크게 달라진다.

```bash
python mix.py songs/노래_내목소리_파트
python mix.py songs/노래_내목소리_파트 --reverb 0.35 --comp 8
```

| 단계 | 목적 | 해소되는 증상 |
|---|---|---|
| 하이패스 85Hz | 웅웅거리는 저역 제거 | 깔끔하지 않음 |
| EQ (250Hz -3.5dB, 3.5kHz +2.5dB, 11kHz +2dB) | 뭉침 제거, 또렷함·공기감 | 갑갑함 |
| 디에서 | 치찰음(스, 츠) 완화 | 깔끔하지 않음 |
| 컴프레서 | 약한 구간을 끌어올림 | **숨이 모자람** |
| 리버브 | 공간감 부여 | **갑갑함** |
| 리미터 | 최종 음량 정리 | |

ffmpeg 에 내장 리버브가 없어 **감쇠하는 잡음 + 초기 반사로 임펄스 응답을 직접 합성**해 컨볼루션한다.

### 측정된 효과

| | 음량 편차 | 저역 | 중역 |
|---|---|---|---|
| 믹싱 전 | 8.1dB | +50.7 | +31.8 |
| 믹싱 후 | **5.0dB** | +47.9 | +29.3 |

음량 편차가 줄면 약하게 부른 구간이 묻히지 않는다. "숨이 모자란" 느낌의 상당 부분이 여기서 온다.
조절 상한은 리버브 0.4 / 압축 8 정도. 넘기면 부자연스러워진다.

### 유명인 AI 커버와 차이 나는 이유 (정리)

| 요인 | 유명인 모델 | 이 모델 |
|---|---|---|
| 학습 데이터 | 스튜디오 순수 보컬 30분~수 시간, **전부 노래** | 휴대폰 말소리 10분, **노래 0분** |
| 곡 선택 | 대상 가수 음역에 맞는 곡만 | 19반음씩 내려야 하는 곡도 시도 |
| 원본 보컬 | 공식 아카펠라 음원 | mp3 에서 분리 (이미 손상) |
| 후반 작업 | 필수 | `mix.py` 로 해결 |

앞의 세 가지는 데이터와 선곡의 문제이고, 마지막 하나는 도구로 해결된다.

## 한계

- **말은 되지만 합성음으로 노래는 안 된다.** 합성음(edge-tts)에 음정이 없기 때문이다.
  노래는 위 `cover.py` 처럼 **이미 불려진 노래**의 보컬을 바꾸는 방식이어야 한다.
- **음정·박자·창법은 원곡 그대로다.** RVC 는 음색만 바꾼다. 원곡 가수가 잘 부르면 잘 부르는 내 목소리가 된다.
- **억양과 숨은 합성음 것이다.** RVC는 음색만 바꾼다.
  실제 억양이 필요하면 직접 녹음하는 편이 낫다.
- 더 닮게 하려면 **깨끗한 직접 녹음을 늘려 재학습**하는 것이 유일하게 의미 있는 방법이다.
  현재 직접 녹음은 4.9분이고, 10분이 되면 유튜브 음원을 빼고 학습할 수 있다.
