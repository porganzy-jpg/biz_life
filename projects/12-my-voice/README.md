# 12-my-voice — 내 목소리 TTS

텍스트를 넣으면 **내 목소리로 읽어주는** 도구. 음성 합성(edge-tts)으로 문장을 만든 뒤
직접 학습시킨 RVC 모델로 음색만 내 것으로 바꾼다.

```bash
python say.py "안녕하세요. 안녕히 주무세요."      # 텍스트 → 내 목소리
python cover.py 노래.mp3                          # 노래의 보컬만 내 목소리로
```

## 얼마나 비슷한가 — 측정 결과

음색 거리는 MFCC 평균 벡터 사이의 거리다. **0에 가까울수록 실제 목소리에 가깝다.**

| 단계 | 음색 거리 |
|---|---|
| 변환 전 합성음 | 58.2 |
| v1 모델 (유튜브 음원만 10.5분, 200에폭) | 36.4 |
| v2 모델 (직접 녹음 절반 포함, 100에폭) | 18.6 |
| **v2 + 문장을 이어붙여 한 번에 변환** | **14.4** |
| **실제 목소리끼리의 거리 (최저선)** | **11.6** |

### 최저선이 0이 아닌 이유

같은 사람이 같은 날 말해도 문장마다 음색이 조금씩 다르다. 목 상태, 말하는 속도, 문장의 내용에 따라
공명이 달라지기 때문이다. 내 녹음 8조각을 서로 비교했을 때 그 변동폭이 **11.6**이었다.
즉 11.6은 "같은 사람이라도 이 정도는 다르다"는 기준선이고, 변환 결과가 이 값에 가까울수록
사람 귀로는 구분하기 어려워진다.

현재 14.4로, 최저선과의 차이는 **2.8**이다. 시작점(58.2)에서 보면 **94%를 좁힌 상태**다.

### 에폭별 비교 (v2)

| 에폭 | 전체 음색 | 문장 끝음 |
|---|---|---|
| 50 | **19.4** | 31.8 |
| 100 | 19.7 | **29.1** |
| 150 | 21.7 | 30.1 |
| 250 | 23.6 | 29.9 |
| 300 | 20.7 | 29.2 |
| (최저선) | 11.6 | 28.3 |

- **에폭이 높다고 좋지 않다.** 데이터가 10분으로 적어 사전학습 모델에서 조금만 조정해도 충분했고,
  오래 돌리면 학습 데이터를 외워버린다(과학습).
- 50에폭은 전체가, 100에폭은 문장 끝음이 낫다. 두 모델 가중치를 25/50/75%로 섞어봤지만
  100에폭 단독보다 나은 조합은 없었다. 그래서 **100에폭을 채택**했다.
- 문장 끝음은 이미 최저선(28.3)에 거의 도달했다. 끝음은 본인 목소리끼리도 변동이 커서 원래 값이 높다.

### 변환 파라미터 — 인덱스 반영도

인덱스 반영도(`index_influence`)를 올리면 학습한 음색에 더 가까워지지만, 값이 높으면
인공적인 공명("울리는" 느낌)이 생길 수 있다. MFCC 거리로는 이 인공음을 잡아내지 못해
네 단계를 만들어 귀로 비교했다(`samples/울림비교/`).

| 샘플 | index | protect | 음색 거리 |
|---|---|---|---|
| **A (채택)** | **1.0** | **0.0** | **9.2** |
| B | 0.6 | 0.0 | 10.0 |
| C | 0.4 | 0.33 | 11.0 |
| D | 0.0 | 0.33 | 11.9 |

A → D 로 갈수록 인공적인 울림은 줄지만 음색은 멀어진다. 들어보고 **A를 채택**했다.
울림이 거슬리면 `--index 0.6` 처럼 낮춰 쓰면 된다.

참고로 "울림"의 원인을 따로 측정해 보니 잔향은 아니었다. 쉼 구간 에너지가 실제 녹음보다
오히려 낮았고(-52dB 대 -39dB), 주파수 대역 차이도 최대 3dB로 작았다. 문장 끝음의 울림도 정상이다.

### 짧은 문장을 이어붙여 변환하는 이유

문장을 하나씩 따로 변환하면 짧은 문장의 음색이 흔들린다. 모델이 참고할 음성 맥락이 부족하기 때문이다.

| 방식 | 평균 | 가장 나쁜 문장 |
|---|---|---|
| 문장별로 변환 | 18.6 | 28.6 (1.8초짜리) |
| **이어붙여 한 번에 변환 후 되자름** | **14.4** | **18.3** |

`say.py` 는 여러 줄을 받으면 자동으로 이 방식을 쓴다. 파일 단위 변환은 `convert_joined.py`.

## 설치 (다른 PC에서 쓸 때)

**Python 3.13에서는 안 된다.** 의존 패키지(pyworld, fairseq 계열)가 빌드되지 않는다.
3.11 전용 가상환경을 만들어야 하고, 관리자 권한은 필요 없다.

```bash
pip install uv
uv venv --python 3.11 .venv
uv pip install --python .venv/Scripts/python.exe torch torchaudio --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
```

ffmpeg 도 필요하다. `say.py` 상단의 `FFMPEG_DIR` 을 설치 경로에 맞게 고치면 된다.

첫 실행 때 HuBERT(약 190MB)와 RMVPE(약 180MB)를 자동으로 내려받는다.

## 노래 커버 (`cover.py`)

노래 파일을 넣으면 **보컬만** 내 목소리로 바꾼다.

```bash
python cover.py 노래.mp3                  # 음역을 분석해 반음 조정까지 자동
python cover.py 노래.mp3 --pitch -12      # 여성 보컬 → 남성 (한 옥타브 내림)
python cover.py 노래.mp3 --keep-parts     # 분리된 보컬·반주도 남김
```

1. Demucs 로 보컬 / 반주 분리
2. 보컬만 RVC 변환 (원곡 보컬의 음높이 중앙값과 내 목소리 110Hz 를 비교해 반음 자동 계산)
3. 변환 보컬 + 원래 반주 재믹스

CPU 로 돌아가며 **곡 길이의 2~4배** 걸린다(3분 곡이면 10분 안팎). 첫 실행 때 분리 모델 173MB 를 자동으로 받는다.
음량은 `--vocal-gain` / `--inst-gain` 으로 조절한다.

Suno 로 만든 곡에 쓰면 "내가 부른 것처럼" 들리는 결과가 나온다.

## 한계

- **말은 되지만 합성음으로 노래는 안 된다.** 합성음(edge-tts)에 음정이 없기 때문이다.
  노래는 위 `cover.py` 처럼 **이미 불려진 노래**의 보컬을 바꾸는 방식이어야 한다.
- **음정·박자·창법은 원곡 그대로다.** RVC 는 음색만 바꾼다. 원곡 가수가 잘 부르면 잘 부르는 내 목소리가 된다.
- **억양과 숨은 합성음 것이다.** RVC는 음색만 바꾼다.
  실제 억양이 필요하면 직접 녹음하는 편이 낫다.
- 더 닮게 하려면 **깨끗한 직접 녹음을 늘려 재학습**하는 것이 유일하게 의미 있는 방법이다.
  현재 직접 녹음은 4.9분이고, 10분이 되면 유튜브 음원을 빼고 학습할 수 있다.
