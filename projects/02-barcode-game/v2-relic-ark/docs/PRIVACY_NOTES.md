# 개인 정보 메모 — 스캔 기록 최소화 (제안, 2026-10-13)

> 작성: 개발(서버). **제안이다. 구현은 결정 뒤에 한다**(DECISIONS 에 한 줄 필요).
> 원칙: 바코드 기록은 **놀이에 필요한 만큼만** 남긴다. 한 사람이 언제 무엇을 샀는지 알 수 있는 원시 기록을 오래 쌓지 않는다.

## 1. 지금 무엇을 남기나 (server.py 실측)

| 표·필드 | 내용 | 놀이에 쓰는 곳 | 개인을 드러낼 위험 |
|---|---|---|---|
| `scans` | uid · 바코드 · 갈래 · 희귀도 · 배율 · 시각(초) · 날 · 출처(camera/manual, S24) | 하루 상한, 재스캔 감쇠(7일 창), 문어 선물(어제 갈래), 소문·단서 문턱(갈래 누적), 원정 최근 갈래(7일), 희귀도 요약, 주간 일지 | **높음**: 시각까지 남은 구매·소지 이력 |
| `arks.state` | 방주 저장(선반 물건 바코드, 바코드별 고정 갈래·종류, 주민에게 준 기록 등) | 게임 상태 그 자체 | 중간: 바코드 목록(시각은 날 단위) |
| `subtype_votes` | uid · 바코드 · 갈래 · 고른 종류 · 시각 | 다른 방주 이름 미리 고르기(서로 다른 방주 수만 센다) | 낮음~중간: uid 가 남는다 |
| `family_votes` | uid · 제조사 7자리 · 고른 갈래 · 시각 | 지금은 쓰지 않는다(쌓이기만) | 낮음 |
| `logs` | uid · 종류 · 내용(JSON) · 시각 | 지표(H1~H5)·디버깅 | 중간: 스캔 로그에 바코드가 들어 있다 |

손으로 친 스캔(`source: "manual"`)은 전역 투표·집계에 넣지 않는다(S24). 개인 놀이에는 그대로 센다.

## 2. 제안 — 보관 기한

| 대상 | 기한 | 그 뒤 |
|---|---|---|
| `scans` 원시 행 | **90일** | 날·갈래·희귀도 **개수표**(`scan_counts`: uid · 날 · 갈래 · 희귀도 · 개수)로 줄이고 원시 행은 지운다. 바코드·초 단위 시각은 남기지 않는다 |
| 재스캔 감쇠·하루 상한 | 영향 없음 | 7일 창·오늘 하루만 쓰므로 90일이면 충분하다 |
| 소문·단서 문턱, 희귀도 요약 | 개수표로 계산 | `scan_counts()` 를 개수표 + 90일 이내 원시 행 합으로 바꾼다 |
| `logs` 의 scan 종류 | **30일** | 바코드 필드를 지우고 종류·날만 남긴다(지표는 날 단위로 충분) |
| `subtype_votes` | 무기한(집계용) | **uid 를 방주별 해시로 바꾼다**(서로 다른 방주 수를 세는 데만 쓰므로 원래 uid 는 필요 없다) |
| `family_votes` | 지금 쓰지 않음 | 쓰는 곳이 생길 때까지 **새로 쌓지 않기**를 권한다 |
| 방주 저장 속 바코드 | 게임 상태라 유지 | 방주를 지우면(계정 삭제) 함께 지운다. 시각은 이미 날 단위다 |

## 3. 함께 정할 것

1. 계정 삭제 경로(복구 코드 화면의 「방주 지우기」): `arks`·`scans`·`logs`·`codes` 의 그 uid 행을 지우고, 투표는 해시라 남긴다.
2. 지표(H1~H5)를 날 단위 개수표만으로 계산할 수 있는지 PM이 확인한다.
3. 상점 출시 전에 개인정보 처리방침 문안을 만든다(수집 항목·기한·삭제 방법).

## 4. 구현 메모 (결정 뒤)

- `init_db` 에 `scan_counts` 표를 만들고, 하루 한 번(서버 시작 시 + 첫 요청 시) 90일 지난 행을 접어 넣는 `prune_scans()` 를 둔다. 멱등이어야 한다.
- `scan_counts(uid)` 와 `/api/collection` 의 희귀도 요약을 개수표 + 원시 행 합으로 바꾼다.
- 테스트: 접기 전후에 문턱·도감 숫자가 같고, 접은 뒤에는 바코드 원시 행이 없는지 본다.
