## 2. 위험

1. **콘텐츠 공급**: 30일 재미(3.9)가 14일(4.1)보다 낮다. 사슬이 바닥나기 때문이다.
   - 지금 사슬 여섯(3~4매듭)과 기억 둘이면 14일에는 넉넉하다.
   - 30일까지 가려면 사람마다 **두 번째 사슬**이나 매듭 +2, 학자·교섭가 사슬, 꼬리표 방문자 +8이 필요하다(시나리오 몫, 약 40매듭).
2. **"지금" 모델이 후하다**: A 숫자도 0.3쯤 낮춰 읽어야 한다. 그래도 지금보다 +1.0 이상 높다.
3. **같은 답 비율은 필요의 날마다 바뀜에 기대고 있다.** 시드 굴림이 화면에서 "변덕"으로 읽히면 안 된다. 그래서 필요는 아침 방송 한 줄로 미리 알린다("○○ 님이 오늘 따뜻한 걸 찾으십니다").
4. **3초 규칙**: 하루 6번 찍으면 「어디로」를 6번 고른다. 피로하면 "선반"만 누르게 된다. 대책 두 가지:
   - 제안 1순위를 크게 보여 준다.
   - 같은 세션 안에서 둘째부터는 줄을 작게 보여 준다. 그러면 기본값이 선반으로 남아도 강요가 없다.
5. **꾸밈 → 긴목 1.3배**: 꾸밈의 대가가 위협이 되는 것은 좋다. 다만 첫 주 보장 긴목(threats.json)과 겹치면 같은 생물이 너무 자주 온다. 첫 주에는 1.0으로 둔다.
6. **sim의 단순화**: 매칭은 갈래 단위(시나리오는 하위 종류까지), 주민·방 수는 곡선 입력, 플레이어는 늘 최선을 고른다고 가정했다. 하위 종류 매칭을 넣으면 맞는 일이 줄어 같은 답 비율이 조금 오를 것으로 추정한다.

## 4. MVP — 먼저 만들어 볼 한 조각

**"주기 + 필요 + 사슬 둘"** (꾸밈·방문자·습격 연결은 뒤로)
1. 카드 아래 「어디로」 줄. 사람 셋(제안 순서 = 필요 > 좋아함) + 선반.
2. 주민 셋(요리사·기술자·정찰병)의 오늘 필요 + 좋아함. 문장은 resident_tastes.json에서 쓴다.
3. 사슬 둘: arc_cook_seat(4매듭), arc_scout_window(4매듭).
4. 측정: 7일 플레이테스트를 같은 가정 물건으로 다시 돌려 아래를 본다.
   - 같은 답 비율
   - 사람 비트/일
   - 4~7일 재미

**합격선**: 4~7일 재미 3.5 이상, 같은 답 비율 40% 미만(MVP는 꾸밈이 없어 대상이 적다).

**왜 이 조각인가**: 패널 다섯이 공통으로 짚은 것이 "내가 찍은 것이 사람에게 간다"였다. 꾸밈·방문자는 그 위에 얹는 두 번째 고리라, 첫 고리가 재미있는지 먼저 본다.
