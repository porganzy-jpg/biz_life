코드(.py/.js/.html)는 한 줄도 건드리지 않았다. `docs/TASKS.md`의 「요청함」에만 개발 요청 4줄을 추가했다.

### 1-1. `data/events_tribes.json`
- 스키마: 기존 `data/events.json`과 동일한 필드(`id`, `name`, `faction`, `severity`, `text`, `counter_tags`, `counter_room`, `on_fail`, `on_counter`, `timer_sec`, 선택 `positive`) + **`tribe`** 1개 추가. 최상위는 `events.json`과 같은 **배열**이라 그대로 이어 붙일 수 있다.
- `faction`은 21장 모두 `"tribe"`로 통일.
- `tribe` 값은 영문 슬러그(코드베이스의 id 관례). 매핑:

| tribe | 부족 | 카드 3장 |
|---|---|---|
| `wayfarer` | 길손(선로) | 지나가는 줄 / 노래 값 / 눈이 된 개 |
| `shelf` | 진열대 | 재고 감사관 / 손목의 성문 / 담보 상자 |
| `flame` | 불꽃 | 빚 징수원 / 잠든 조상 / 진동으로 말하는 사절 |
| `white` | 하얀 | 유리 너머의 문진 / 격리 요구 / 차가운 상자 |
| `archive` | 서고 | 죄의 낭독 초대 / 검은 명단 / 성문은 값이다 |
| `greenhouse` | 온실 | 몰래 사는 씨앗 / 돌아갈 아이 / 문턱까지만 |
| `tower` | 탑 | 거울 신호 / 내려온 까마귀 / 보고만 있었다 |

- 심각도 분포: 0×4, 1×9, 2×7, 3×1(「격리 요구」 — 기존 최고치 2를 처음 넘는 카드. 의도적으로 이 스프린트 유일한 3). `positive: true` 8장 — 부족 접촉이 전부 위협으로만 읽히지 않게 했다.
- `counter_tags`는 **기존 태그 어휘만** 사용했다(교섭·교역·지식·해독·치료·사기·보존·방어·전력·부품·탐사·온실·청사진). 21장 전부 `data/roles.json`의 어떤 역할이든 자동 대항이 걸린다 = 새 태그 추가 없이 바로 굴러간다.
- `counter_room`은 현재 존재하는 4개 방(`pantry`/`well`/`infirmary`/`library`)과 `null`만 사용.
- `on_fail`/`on_counter`의 키는 `server.py`가 실제로 적용하는 자원 키(`food/water/med/power/parts/morale/cloth/trade/knowledge/scrap`)와 특수 키(`injured`, `resident`, `capture`, `free_pack`)만 썼다. 예외 하나: 「문턱까지만」의 `on_counter`에 **`spot_clue`: `"spot_greenhouse_cafe"`** 를 넣었다. `engine/storyteller.resolve()`는 int가 아닌 값을 그대로 `applied`로 통과시키고 `static/app.js`는 `키: 값` 형태로 안전하게 출력하므로 **지금 붙여도 깨지지 않는다.** 스팟 단서 시스템이 생기면 그대로 훅으로 쓰면 된다.

### 1-2. `data/dialogue.json`
- 구조: `{"_comment", "_when_tags", "reader": [...], "gardener": [...]}`. 각 줄은 `{"when", "text"}`.
- `when` 태그 19종: `scan_unknown, scan_book, scan_food, build, event_fail, event_counter, spot_found, spot_deep, night, low_food, first_ally, betrayal, imprint, animal_death, tribe_meet, debt, trade, surface_trip, ending_hint`. 같은 태그에 여러 줄이 있으면 무작위로 하나 고르는 용도(리더는 `scan_unknown`·`build`가 2줄).
- 리더: 명령형·약속형·보상형. "쌓아라 / 지어라 / 내가 약속한다 / 장부를 잊는 법이 없다". 광고와 설교가 섞인 문장. `scan_unknown`에서 말을 더듬는 줄을 넣어 「리더는 전지하다」 신화가 실제로는 상품 목록임을 규칙으로 흘린다(MYTH_ORIGINS §8).
- 정원사: 20줄 전부 물음으로 끝난다(자동 검사로 확인). 단정·명령·약속 문장 0. 물·물고기·바람·이끼·그림자로만 말한다. 업/연기의 논리(놓음, 이어짐, 심판자 없음)는 개념으로만 들어가 있고 어떤 전통의 이름도 쓰지 않았다.

### 1-3. `data/spots.json`
- 배열 6개. 필드: `id`, `name`, `discovery_text`(3~4문장), `clue_text`(1~2문장), `resource`, `danger_note`, `tribe_hint`.
- `id`는 `data/world_prompts.json`의 `healing[].id`와 **완전히 동일한 순서·철자**(`spot_flooded_train`, `spot_goldfish_canal`, `spot_greenhouse_cafe`, `spot_forest_train_door`, `spot_rooftop_garden`, `spot_lantern_river`). 생성될 일러스트와 텍스트가 자동으로 짝이 맞는다.
- `resource`는 `{"key", "ko", "gain"}` 객체. `gain`은 실제 자원 키만 쓴다(예: `{"water": 4}`, `{"morale": 6}`). 고유 자원 개념(비단잉어·씨앗·약초)은 `key`/`ko`로 남기고 당장의 수치 효과는 기존 자원으로 환산했다 — 새 자원 타입을 만들지 않아 개발 부담이 0이다.
- `danger_note`는 전부 **돌아오는 길**의 위험이다(CONCEPT_HEALING_SPOTS §2 "위험은 돌아오는 길에 있다"). 빛 게이지·포자·밤의 공룡·짐의 무게로 갈랐다.
- `tribe_hint`는 부족의 가치관이 왜 그 스팟을 먼저 알게 했는지까지 적었다(예: 탑 부족은 옥상 정원을 200년 내려다봤지만 내려간 적이 없다).

## 3. 미완·리스크

1. **`tribe` 부족 표기가 UI에 안 나온다.** `static/app.js:18`의 `FAC_KO`에 `tribe` 키가 없어 사건 쪽지 머리말이 `undefined · 심각도 n`으로 뜬다. **개발이 한 줄 추가해야 화면이 깨지지 않는다.** (요청 1)
2. **`events_tribes.json`은 아직 아무도 읽지 않는다.** `engine/storyteller.load_events()`가 `data/events.json`만 로드한다. 병합 전에는 게임에 21장이 등장하지 않는다. (요청 2)
3. **`capture: "dog"`/`"crow"`가 미구현.** 기존 `capture: "magpie"`와 같은 처리 경로라 크래시는 없지만, 반려 시스템(TRUST_AND_COMPANIONS §4)이 붙기 전까지는 결과창에 문자열로만 표시된다. 짐승 신뢰 서사의 핵심이므로 스프린트 2 후보.
4. **`spot_clue` 훅이 미구현.** 스팟 단서 → 원정 → 발견의 루프가 아직 없다. `spots.json`의 `clue_text`/`discovery_text`는 그 루프를 전제로 쓰였다.
5. **심각도 3이 처음 등장.** `engine/storyteller.weight_for()`는 `severity >= 2`만 초반 가중치를 낮춘다. 3이 1일차에 뜨지는 않지만 밸런스 검토가 필요하다. 「격리 요구」는 `on_fail` 사기 −4로 이 데이터셋에서 가장 아픈 카드다.
6. **대사 트리거 부재.** `dialogue.json`의 `when` 태그를 실제로 발화시키는 코드가 없다. 태그 이름은 내가 임의로 정한 것이라, 개발이 다른 이름을 쓰면 `_when_tags`를 맞춰 고치겠다.
7. **부족별 사건이 "한 번뿐인 첫 접촉"으로 설계됐다.** 지금 엔진은 같은 카드를 반복해서 뽑는다(스모크 테스트 4일차에 「보고만 있었다」 재등장). 첫 접촉 카드는 부족당 1회 소모형이거나 이후 "재접촉" 변형이 필요하다.
8. **`resource.gain`은 가안이다.** 스팟 보상 수치(맑은 물 4, 사기 6 등)는 실제 경제 곡선을 보지 못한 상태의 추정치다. 개발이 조정해도 서사에 영향 없다.

## 4. 개발 에이전트에게 요청할 것 (`docs/TASKS.md` 「요청함」에도 기재)

1. `static/app.js` `FAC_KO`에 `tribe: '부족'` 추가. 가능하면 `TRIBE_KO = {wayfarer:'길손', shelf:'진열대', flame:'불꽃', white:'하얀', archive:'서고', greenhouse:'온실', tower:'탑'}`를 만들어 쪽지에 `길손 · 심각도 1`로 표기.
2. `engine/storyteller.load_events()`가 `data/events.json`과 `data/events_tribes.json`을 **합쳐서** 로드하도록. 두 파일 모두 같은 스키마의 배열이라 리스트 연결만 하면 된다. (첫 접촉 카드는 1회 소모 플래그를 주는 편이 서사에 맞다 — 리스크 7)
3. `data/events_schema.json`(S1-B 산출물)에 `tribe`(선택, 문자열 슬러그)와 `on_*`의 통과형 키(`capture`, `free_pack`, `spot_clue`)를 명시해 주면 이후 시나리오가 그 스키마에 맞춰 쓴다.
4. `data/dialogue.json` 발화 훅: 스캔 결과창·건설·사건 결과·야간에 `when` 태그로 한 줄 띄우기. 태그 이름 변경이 필요하면 알려 주면 데이터를 맞춘다.
5. (스프린트 2) `capture: "dog"|"crow"`를 반려 짐승 획득으로, `spot_clue: "<spot id>"`를 `data/spots.json` 단서 해금으로 연결.
