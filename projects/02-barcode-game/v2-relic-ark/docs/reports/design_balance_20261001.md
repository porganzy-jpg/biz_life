## 1. 급한 것부터 — 방어 공식 (개발이 기다리던 것)

### 1-1. 현행 공식의 결함

`engine/combat.py`는 관문 통과에 **+3.0을 점수로** 준다. 실제 값을 넣어 보면:

```
보통 배치(방 1.0 + 주민 셋 3.0 + 태그 1.5 + 관문 3.0) = 8.5  대  need 3~6
```

→ **어떤 배치든 margin +2.5 이상이라 항상 막는다.** 관문을 놓치면 5.5 대 3~6이라 거의 항상 금이다.
즉 **결과가 관문 하나로만 갈리고, 사람·각인·도구·방 레벨이 결과를 전혀 바꾸지 못한다.**
사용자 요구("사람을 옮긴 보람이 수치로 나와야 한다")와 정면으로 어긋나고 B3 위반이다.

두 번째 결함: 생물의 `role_tags`에 걸리는 역할이 **정찰병과 기술자 둘뿐**이다(swarm[방어,부품]·longneck[전력]·warden[전력,방어]·claws[탐사] ∩ roles.json counter_tags). 요리사·의무병·농부·학자·교섭가·아이는 전투에서 영원히 0점이고, 최적 배치는 "기술자와 정찰병 몰아넣기" 하나로 수렴한다.

### 1-2. 고친 구조

```
관문 = 올바른 행동.  점수 = 배치의 두께.  단위가 다르므로 더하지 않는다.

score = 방 바탕[Lv] + Σ사람(0.5+0.1×담) + Σ역할 친화 + Σ각인 1.5 + min(Σ도구, 3.0)
need  = 등급 기본값 + 생물 보정(±0.5) + severity(0~2)

관문 통과:  margin ≥ 0 막음 / ≥ −4.5 금 / 그 밖 상실
관문 실패:  margin ≥ −1.0 금 / 그 밖 상실      ← **막는 것은 불가능**
상실 보호:  등급 1 전면 / 등급 2 사람이 있으면 / 등급 3~ 없음
```

**관문을 놓치면 아무리 좋은 배치여도 막을 수 없다.** 이것이 "종마다 막는 법이 다르다"를 공식이 아니라 규칙으로 강제하는 유일한 장치다. 긴목(불을 끈다)·문지기(소리를 죽인다)가 여기 산다.

### 1-3. 계수와 근거

| 항목 | 값 | 근거 |
|---|---|---|
| 방 바탕 | 1.0 / 1.5 / 2.0 | 레벨 전체 폭 +1.0 < 각인 하나 1.5 (B6) |
| 사람 | 0.5 + 0.1×담, 부상 ×0.5 | 담 5 = 1.0. **현행 코드값을 그대로 승인** |
| 역할 친화 | 강 1.5 / 약 0.75 | 맞는 사람 둘(3.0) = 아무나 셋(3.0) → 교환 가능해야 선택이 생긴다 |
| 각인 일치 | 1.5 | 각인은 얻어 낸 변화라 강한 역할 일치와 같은 무게 |
| 도구 합계 **상한 3.0** | 신규 | 상한이 없으면 도구만 깔고 사람을 안 옮긴다 → G1(분 단위 할 일)이 죽는다 |
| 보강대·그물 | 2.0 → **1.5** | 2.0이면 둘 합쳐 4.0 > 맞는 사람 둘 3.0. 도구가 사람을 이기면 안 된다 |
| 금 구간 | **4.5** | 시뮬레이션으로 정했다(1-5절) |

### 1-4. 역할 친화표 (신규)

| 생물 | 강(1.5) | 약(0.75) |
|---|---|---|
| 작은 떼 | 기술자(이음매를 안다)·요리사(좁은 데를 막아 본 손) | 의무병·농부·아이 |
| 긴목 | 기술자(전원을 내린다)·정찰병(어둠에 익숙) | 학자·교섭가 |
| 문지기 | 교섭가(사람을 모은다)·농부(숨을 참는다) | 학자·요리사·아이 |
| 손톱 무리 | 정찰병(밖을 안다)·의무병(이음매를 꿰맨다) | 기술자·농부 |
| 거울눈 | 기술자·학자(이것이 긴목이 아님을 안다) | 정찰병·교섭가 |
| 곧은치 | 의무병(약재로 물을 흐린다)·요리사 | 기술자·농부 |
| 덮개 | 교섭가(사람을 붙잡아 둔다)·농부 | 학자·아이 |
| 바늘 | 정찰병·기술자(외부 해치를 연다) | 농부·요리사 |
| 큰 입 | 요리사·농부(기른 것을 내준다) | 교섭가·의무병 |
| 따라온 것 | 학자(어느 유물인지 안다)·교섭가 | 정찰병·아이 |
| 윗물 아이 | 기술자·아이(아이가 아이를 부른다) | 의무병·정찰병 |

여덟 역할이 **전부** 어딘가에서 강을 갖는다. 같은 사람이 모든 습격의 정답일 수 없다.

**등장 등급**(`threats.json.min_grade`): 거울눈은 **등급 3 전에 절대 나오지 않는다** — 긴목의 "불을 끈다"를 충분히 익힌 뒤라야 그것이 오답이 되는 경험이 성립한다. 덮개(주된 동사가 최악수)는 등급 4, 따라온 것은 등급 5.

### 1-5. 금 구간을 4.5로 정한 과정 (B2)

| 금 구간 | 등급 3·4·5 방 상실률 | 판정 |
|---|---|---|
| 2.0 (최초안) | 17 / 18 / 23 % | 목표(≤5%) 크게 초과. 아늑한 생존물이 아니다 |
| 3.5 | 8 / 12 / 12 % | 여전히 초과 |
| **4.5** | **5 / 3 / 3 %** | 채택 |

뜻은 "네 사람 몫 넘게 모자라야 방을 잃는다". 그 정도면 플레이어도 질 만했다고 납득한다.
함께, 관문 실패 시 금 문턱을 +2.0 → **−1.0**으로 내렸다. +2.0이면 "잘 배치했는데 불을 안 껐다"가 곧바로 영구 손실이라, 규칙을 배우는 대가가 너무 컸다.

## 2. 위협 등급 1~5

**등급은 거점 최심부 깊이로만 정해진다. 날짜·주민 수·자원량은 등급을 올리지 않는다.**
난이도를 시간이 밀면 조급해지고, 플레이어가 당기면 아늑함이 남는다(B4). 띄엄띄엄 하는 사람은 얕은 곳에 오래 머물고, 그에게는 센 것이 오지 않는다 — 뒤처지는 벌이 아니라 그 사람의 속도다.

| 등급 | 깊이 | need | 위협 오는 날 | **조용한 날** | 보상(막음) |
|---|---|---|---|---|---|
| 1 | 0m | 2.5 | 17% | **83%** | 부품1 |
| 2 | 60m | 3.5 | 27% | 73% | 부품1 직물1 |
| 3 | 120m | 4.5 | 34% | 66% | +유물 1장(쓸만함↑) |
| 4 | 180m | 6.5 | 41% | 59% | +유물 1장(귀함↑) |
| 5 | 180m + 방 10칸 | 8.0 | 43% | **57%** | +유물 1장(진귀함↑) |

- **모든 등급에서 조용한 날이 과반**이다. 이 선이 0.5 아래로 내려가면 안 된다(COMBAT_AND_DEFENSE §6-1).
- need 간격이 1.0·1.0·2.0·1.5로 **일정하지 않다.** 플레이어의 힘이 등간격으로 늘지 않기 때문이다 — 방 Lv2와 두 번째 도구가 한꺼번에 들어오는 3→4 구간에서 크게 세지므로 need도 거기서 크게 뛴다. 등간격 1.5로 뒀을 때 등급 2 막음 비율이 49%까지 떨어졌다.
- 등급 5를 막아도 재료 7개 — 보통 플레이어 하루 수입의 20%다. **습격은 수입이 아니라 사건**이다.
- 1막에 등급 1~5가 전부 나온다. 거점이 해구에 닿지 못하므로 등급 6은 없다.

1   swarm     0   3.0   금(1.0)   막음(3.0)  막음(4.0)   막음(7.1)  막음(4.0)  막음(4.8)  막음(7.1)
2   swarm     0   4.0   상실(1.0)  금(3.0)   막음(4.0)   막음(7.1)  막음(5.5)  막음(6.2)  막음(10.1)

> **배치에 따라 결과가 갈린 경우: 106/106 = 100%** (위협 열하나 × 전 severity, 목표 40% 이상)
> 사용자 요구 "같은 습격이 배치에 따라 결과가 갈려야 한다"에 대한 직접 답이다.

### 표 D2. 관문을 **안 했을 때** — 불을 안 껐다 / 전원을 안 내렸다

| 등급 | 생물 | need | 최선의 배치로도 | 점수 |
|---|---|---|---|---|
| 3 | 긴목 | 4.5 | **금** | 7.9 |
| 4 | 긴목 | 6.5 | **금** | 9.0 |
| 5 | 문지기 | 8.5 | **금** | 9.5 |

점수가 need를 훨씬 넘어도 **막음은 없다.** 올바른 행동이 아니면 최선의 결과가 금이다.

### 표 D4. 실제 플레이에 가까운 분포

배치 선택 확률(깊은 곳에 있는 사람일수록 더 잘 배치한다) · 관문 성공률(60→92%) · 생물 빈도를 모두 반영.

| 등급 | 막음 | 금 | **상실** | 목표 |
|---|---|---|---|---|
| 1 | 76% | 24% | **0%** | 상실 0 |
| 2 | 58% | 38% | **4%** | ≤5% |
| 3 | 64% | 31% | **5%** | ≤5% |
| 4 | 72% | 25% | **3%** | ≤5% |
| 5 | 67% | 30% | **3%** | ≤5% |

막음 58~76%(목표 60~75%), **상실 최대 5%.** B4를 만족한다. 등급 2가 58%로 목표를 2%p 밑도는데, 그 구간은 적은 세졌는데 플레이어는 아직 Lv1 방·도구 하나뿐인 자리라 그대로 둔다 — 상실이 4%로 묶여 있어 체감은 '아슬아슬했다'이지 '빼앗겼다'가 아니다.

### 표 D5. 두 번째 정답이 있는가 (등급 4, 작은 떼, sev1 / need 8.0)

| 길 | 점수 | 결과 |
|---|---|---|
| 맞는 사람 둘 + 평범 하나 | 7.60 | 금 |
| 평범 셋 + 보강대 + 그물 | 7.50 | 금 |

## 4. 경제

### 4-1. 전제 — 하루는 실제 24시간이다 (PM 확정)

접속 시간이 아니라 달력으로 흐른다. 오프라인 생산은 24시간치까지만 쌓이고(현행 `MAX_OFFLINE_TICKS=3`), 스캔 20회는 이월되지 않는다.

### 4-2. 지금 게임의 상태 (코드 실측)

- **소비가 전혀 없다.** `tick_production`은 더하기만 한다. 음수 흐름은 사건 카드뿐이다.
- 20회 스캔 = 하루 **80~120 자원**. 방 레벨업 비용은 6~8. **열심인 사람은 2일차에 전부 끝낸다.**
- 식량이 30일차에 **627**까지 분다(소비 6/일, 수입 15/일).

→ 곡선이 성립할 수 없는 상태였다. 장치 셋을 넣었다.

| 장치 | 내용 | 효과 |
|---|---|---|
| **소비** | 주민당 하루 식량 0.6·물 0.6 | 온실 Lv1 + 정수실 Lv1이 기본 인원을 정확히 먹인다 |
| **보관 상한** | 창고 선반 × 6 (24/36/72/120) | 식량 627 → 72. **식량이 차면 다른 카테고리를 찍을 이유가 생긴다**(H2를 가격이 아니라 구조로 민다) |
| **일일 체감 곡선** | 1~6회 ×1.0 / 7~12 ×0.7 / 13~20 ×0.4 | 유효 스캔 20→13.4, 8→7.4, 3→3.0. 격차 6.7배 → 4.5배 |

경계 6은 지표 H1(하루 유효 스캔 6회)과 같은 수다. **목표 지점까지는 깎지 않는다** — 체감 곡선은 벌이 아니라 상한이어야 한다.

**굶어도 아무도 죽지 않는다.** 사기만 하루 −1 내려간다(B4).

### 4-3. 전력은 재고가 아니라 공급량이다 (설계 변경 제안)

저장되지 않는다. 발전실이 매일 공급(2/4/7/10), 조명·격벽·소리 가리개가 점유한다.
**방 12칸 × 조명 1 > Lv3 공급 10 — 끝까지 다 켤 수 없다.** 결함이 아니라 설계다.
어두운 방은 생산 ×0.5·사기 −0.3이지만 **긴목 관문을 공짜로 통과**한다 → "긴목이 자주 오는 층은 어둡게 두고 살자"가 두 번째 정답이 된다(B3).

2. 스캔 20회는 **이월되지 않는다.** 이것이 유일한 기회비용이다.
3. **건너뛴 날의 습격은 판정하지 않고 지나간다.** 없는 사이에 방을 잃는 것은 아늑한 생존물에서 가장 해서는 안 되는 일이다. 흔적(금 간 유리)만 남긴다.

## 6. 장비 — 순수 상위 호환 셋을 고쳤다

`ROOMS_AND_ITEMS` §3-3의 현행 표는 네 슬롯 중 **셋이** DECISIONS 2026-10-01("모든 장비에 대가가 있다")을 어기고 있었다.

| 슬롯 | 어긴 것 | 붙인 대가 |
|---|---|---|
| 머리 3 | 창이 넓은 헬멧(눈+2,담+1)이 기운 두건(눈+1)의 순수 상위 | **손 −1** |
| 몸 3 | 보강 잠수복이 앞 둘의 순수 상위 | **원정 행동 −1** |
| 손 3 | 정밀 장갑(손+2)이 맨손(0)의 순수 상위 | **담 −1** |
| 등 3 | — (유일하게 지키고 있었다) | 숨 −1 유지 |

3단계는 "더 센 것"이 아니라 **더 치우친 것**이다. 정밀 장갑(담 −1)을 낀 기술자는 습격 때 다른 방으로 빼야 한다 — **장비가 배치를 강제한다.**
주민 10명 × 4슬롯 전부 3단계 = 부품 180. 보통 플레이어 30일 부품 수입의 세 배가 넘는다 → **1막 안에 전원 풀장비는 불가능**하고, 누구에게 무엇을 줄지가 실제 결정이 된다(B3).

## 7. 임시값 — 아직 근거가 없는 것 (B7)

| 임시값 | 지금 값 | 무엇을 재면 확정되나 |
|---|---|---|
| **스캔 카테고리 분포** ★가장 약하다. 경제 전체가 여기 걸려 있다 | 식품 35 / 음료 20 / 담배주류 10 / 미확인 10 / 나머지 각 5% | 실사용자 10명 × 3일의 `scans` 테이블. 추가 계측 없이 바로 뽑힌다. **바뀌면 비용표 전체를 다시 돌려야 한다** |
| 심해 각인 세 종 | `crack_seen`·`knock_heard`·`saved_breath` | `data/imprints.json`에 **아직 없다**(현재 8종). 시나리오 등재 전까지 각인 항은 항상 0 |
| 손톱 무리 가중치 | 낮게 | 원정 미구현 → 관문이 항상 통과 = 공짜 승리. 원정 붙으면 3~4로 |
| 관문 성공률 | 60→92%(등급별 가정) | 실플레이에서 불 끄기·전원 내리기를 실제 몇 % 해내는지 |
| 원정 산출 | 1회 6~10 재료 | 미구현. 붙으면 스캔 비중·claws 가중치를 함께 다시 돌린다 |
| 바코드 풀 크기 | 열심 160 / 보통 90 / 띄엄 55 | `scans` 테이블의 1인당 고유 바코드 수 |

**어떤 가정이 깨지면 다시 봐야 하나**
1. 카테고리 분포가 크게 다르면 → 비용표 전체 재계산
2. 하루 = 24시간 전제가 바뀌면 → 경제 곡선 전체 재계산
3. 원정이 붙으면 → 수입 비중·손톱 무리 가중치·공기 게이지
4. 주민 사망을 넣기로 하면 → B4 전제가 무너지므로 상실 보호부터 다시

## 9. 교본 원칙 적용

- **B1** 모든 값에 `_basis`. 네 json 전부.
- **B2** 30일·60일 × 플레이 3종 + 방어 판정 전수(56조합)를 돌렸다. 금 구간은 **시뮬레이션 결과를 보고 2.0→3.5→4.5로 두 번 고쳤고**, need 등간격도 돌려 보고 폐기했다.
- **B3** 점수에 닿는 길을 넷으로 갈랐고(사람·도구·각인·방) 1.5 안에 모였음을 표 D5로 보였다. 역할 친화표로 여덟 역할 전부에 자리를 줬다.
- **B4** 상실률 ≤6%, 등급 1~2 보호, 굶어도 사망 없음, 조용한 날 과반, 결석해도 재고 안 줄음, 격차 1.2배.
- **B5** 보관 상한이 "식량이 차면 다른 걸 찍어라"를 **구조로** 만든다. 다양성 보너스는 보조.
- **B6** 방 레벨 전체 폭(+1.0) < 각인 하나(1.5). 스탯은 장비로만 조금 움직인다.
- **B7** 7절에 임시값 6개와 측정 방법.

**원칙과 다르게 한 곳**: B4는 "부족함은 선택의 이유지 처벌이 아니다"라고 했지만, **부품만은 의도적으로 늘 빠듯하게** 뒀다. 전자 카테고리를 찍을 이유가 그것 하나뿐이고(B5), 부품이 모자라도 식량·물·사기는 멀쩡해서 **조급해지지 않고 다만 기다리게** 되기 때문이다. 마르는 자원과 넉넉한 자원을 분리한 것이 이 타협의 핵심이다.
