## 2. 설계 판단과 교본
- **D2 숫자는 화면으로**: 공기는 `air_band` 띠(초가 아니라 줍기마다 준다), 손은 칸 그림(상자 2칸), 위험은 숨기 버튼 옆 % 하나(서버 `p_hide`). 화면은 아무것도 계산하지 않는다 — 결과·줍기 내용·갈림길·위험은 전부 서버가 준다.
- **D6 결정성**: 바닥·소품은 `terrain_seed` 로만 정해진다(같은 목적지 = 같은 땅). 문장 선택도 원정 id 로 결정적.
- **D7 데이터가 규칙을 든다**: 에셋은 manifest id, 캐릭터 행은 `meta.json rows/s15_rows`, 잠수복 겹은 `meta.suit_layer` 경로 틀, 문장은 `/api/text/moments` 의 서버 id 키. 한국어 문장은 코드에 없다(키가 없으면 빈 칸 + 그림 기호).
- **D8 성능**: GTX 1050(ANGLE D3D11) 실측 **60 fps, 드로우콜 62**(1280×800·844×390 동일). 그림자 맵 끔(무광층에 해가 없다 — 발밑 원판으로), 점광원은 랜턴 하나 + GLB 등 몇 개(세기 고정 클램프 D10). 에셋 합계 0.4 MB.
- **D9 벽 대신 위험**: 길 찾기 없이 직선 + 격자 가장자리 자르기. 문 쪽(벽)으로는 가지 않는다.
- **D10**: 정사영이라 안개 밀도 대신 선형 안개를 카메라 깊이에 맞췄다. GLB 재정규화 안 함.
- **P3 감정의 가속도 / nudge**: 반짝이는 줍기는 안개 너머에서도 보여 손을 부른다. 위험 그림자(배경 `danger_shadow`)가 랜턴 곁을 지나간다. 귀환 때 관리실 목소리가 **다시 들린다**(문턱에서 끊겼던 것 — J3).
- **M10·B4 압박 없음**: 화면에 머문 시간은 아무것도 깎지 않는다. 보내 두기 뒤에는 알림·개입 없이 보기만(들여다보기, 진행도 보간 위치). 폴링 30초.
- 하루 사이클(`PHASES`)·"해가 기웁니다"·스캔 카트·전원 버튼은 물속판에 넣지 않았다(EXPEDITION §3-6 표).
- **카우스틱은 넣지 않았다**(선택 항목): 무광층에는 해가 없어 수면 빛무늬가 세계 규칙과 어긋난다. 대신 바다 눈과 랜턴 빛 모양으로 물을 보였다.
- **캐릭터 표현**: world3d 는 GLB(Quaternius)였지만 DECISIONS 2026-10-01("캐릭터는 도트, 배경은 3D")에 따라 P2 도트 빌보드를 썼다. 정수 배율(1280×800 ×2, 844×390 ×1), 최근접 보간, 발 원점 = 셀 발선. 물속은 옆모습만(`swim_side` 반전·`swim_idle`·`carry_box_swim`), 문에 닿으면 `return_tired`. `hatch_exit` 은 출발 표지 GLB 사다리와 두 번 보여서 쓰지 않았다. 겹은 기본 시트 + `suit/<role>_a.png`(머리·얼굴 패치는 base.js 도 아직 안 얹는다 — 거점이 얹으면 같은 순서로 맞춘다). 겹이 없을 때를 위한 도트 투구 대체물(`drawHelmets`)이 남아 있다.

## 4. 자가 검수(02_DEV §5)
1. **새 숫자가 화면의 무엇으로 보이나** — 공기 = 띠(줍기마다 한 칸), 손 = 칸 그림, 위험 = 숨기 버튼의 % 하나, 돌아올 시각 = 시계 한 줄. 다른 숫자는 없다.
2. **첫 3분 루프의 탭 수** — 튜토리얼 원정은 「따라 나가기」 1 + 반짝이 3 = **탭 4**(EXPEDITION §7 J4 "탭 3회" + 따라 나가기 선택 1). 「보내 두기」 를 누르면 1탭으로 끝난다. 갈림길이 없는 튜토리얼은 셋째 줍기 3초 뒤 자동으로 손을 놓고 바로 귀환 카드가 뜬다.
3. **같은 입력 = 같은 결과** — 땅·소품 = `terrain_seed`, 결과 = 서버 시드, 문장 선택 = 원정 id 해시.
4. **폰 가로 720px에서 손가락 조작** — 버튼 최소 높이 44px, 반짝이는 화면 44px 안이면 잡힌다. 844×390에서 카드·서술이 겹치지 않는다(고르기 카드가 뜨면 서술이 위로 올라간다).
5. **회귀 로그** — world.html·/base 에러 0(§3). 스캔·건설·사건·주민·도감·시뮬·마이그레이션 7항목은 이번에 서버·거점 코드를 건드리지 않아 따로 돌리지 않았다(서버 담당 S15-A 몫).

07 §7: AI 생성물 없음(코드만). 보여줄 컷: `dev_S15C_1280_4_danger.png`(랜턴 곁을 지나가는 큰 그림자).

## 5. 미완 · 리스크
- **발견 연출은 실서버로 못 봤다**(단서 원정 조건). 귀환 결과에 발견 자리 좌표가 없어서, 그 기기에서 장면을 열었을 때 받은 `scene.discovers.pos` 를 `sessionStorage` 에 기억해 쓴다. 다른 기기·첫 열기가 귀환이면 기본 자리(문에서 30 m)에 등대를 세운다 → 서버가 `expedition_return.discovered.pos` 를 실어 주면 정확해진다(요청 아래).
- **이름 없는 버튼 둘**: 귀환 카드 닫기·발견 카드 계속이 그림 기호(⌂ ▸)다. 문장 키 요청함에 올림.
- **줍기 거리**: 실서버 첫 줍기까지 14 m 안팎이라 걷는 데 20초 걸린다(0.7 m/s, 무게추 걸음). 튜토리얼은 10초씩이라 괜찮다. 일반 원정의 따라 나가기는 약 1분 — 사양(1~2분) 안이지만 길면 서버가 앞머리 줍기 자리를 문 쪽으로 당기면 된다.
- **들여다보기 경로**: `waypoints` 를 진행도로 보간한다. 고리가 짧아서 10시간 원정은 아주 천천히 걷는다(그대로 사양).
- **기기 저장**: 걸은 곳(안개)은 `localStorage` 라 기기마다 다르다. 서버가 "이미 걸은 곳"을 주면 그쪽을 쓰도록 `walked` 를 바꾸면 된다(계약 §6에 아직 없다).
- **스크래치패드 충돌 가능성**: 처음에 스크래치패드 `harness.py`(텍스트 엔드포인트 임시 하네스, 8012)를 같은 이름으로 만들었다 — 다른 에이전트 파일이 같은 이름이었다면 덮어썼을 수 있다. 이후 내 검증 파일은 `scratchpad/s15c/` 로 옮겼다. 하네스·8012/8013 프로세스는 모두 내렸다.
- ★개발 훅: `?mock=1`(모의 API), `?debug`(로그·fps), `?yaw=`(땅 회전), `window.EXPED` — 배포 전 제거 목록.
