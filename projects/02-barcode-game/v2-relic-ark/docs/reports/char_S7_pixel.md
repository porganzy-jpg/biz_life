### 0-4. 결론 — 이번에 왜 직접 찍었나
- **우리가 필요한 것(걸어 다니는 탑다운/정면 경질 헬멧 잠수부)과 정확히 같은 CC0 팩은 존재하지 않는다.** CC0 잠수부(1·2번)는 전부 **헤엄치는 측면**이다. 걷기 사이클은 어차피 우리가 그린다.
- 더 큰 이유: **배경이 우리 렌더이고 팔레트가 우리 것이다.** 남의 팩을 들여오면 팔레트·선 두께·명도 설계를 전부 다시 맞춰야 해서, 재채색 비용이 신규 작화 비용에 근접한다(32~48px 기준 캐릭터 하나 프레임당 1~2천 픽셀).
- **쓴다면 이 둘만**: ① ansimuz Underwater Diving — 기포·수중 FX·타일을 **원정/바깥 화면**에 그대로(CC0, 표기 불필요) ② 0x72 DungeonTileset II — 4방향 걷기 **타이밍 참고**(프레임 수·발 접지 순서).
- 어느 쪽이든 쓰면 `assets3d/README`의 CC0 출처 목록에 올린다(07 §6 공개 관리표 기준: CC0 3D/2D는 Steam 공개 대상 아님).

## 1. 할 일 2 — 만든 것

### 1-2. 2.5D 다섯 조건을 어떻게 지켰나

| 조건 | 구현 | 코드 위치 |
|---|---|---|
| 1. 정수 배율·최근접 | `SCALE = {p1:4, p2:3, p3:2, p4:2, p5:3, p6:3}`. 전 출력이 `Image.NEAREST`. P4는 원본을 56→**64px로 늘려** ×2에서 128px이 되게 했다(다른 방향과 키를 맞추려고) | `SCALE`, `up()` |
| 2. 방의 빛 | 천장 등불이 비춘 **벽색을 샘플링해 틴트**를 뽑고(평균 1.0 정규화) 위를 +13%, 아래를 −32%, 광원 반대쪽을 −7% | `lamp_tint()`, `room_light()` |
| 3. 접지 그림자 | 발밑 부드러운 타원(가우시안), 폭 = 스프라이트 78% | `ground_shadow()` |
| 4. 배경에서 팔레트 추출 | 렌더 크롭을 16색 median-cut으로 양자화 → 각 팔레트 색을 **명도가 가까운 배경색 쪽으로 20% 당긴다**. 다만 당기기만 하면 벽에 묻혀 사라지므로 **방 평균색을 기준으로 대비를 1.26배 다시 벌렸다** | `harmonize()` |
| 5. 깊이 1.7m | 벽에서 한 뼘 앞 바닥선(`SCENE_FLOOR=248`)에 세우고 앞뒤 겹치는 소품을 두지 않았다 | `SCENE_BOX/FLOOR/CX` |

> 4번은 지시와 **다르게 한 곳**이다. 배경에서 뽑은 색을 그대로 쓰면 1차 결과에서 캐릭터가 벽과 같은 갈색이 되어 **형체가 사라졌다**(실제로 그 상태의 `scene_all.png`을 눈으로 확인하고 되돌렸다). 하여 "추출해서 당기되, 방 평균색 기준으로 대비는 다시 벌린다"로 수정했다. 근거: 공통 교본 §3-6(모호하면 더 단순하고 읽히는 쪽), 직군 교본 C1(3초 실루엣).

## 3. 적용한 교본 원칙

- **P1(보편적 원형)** — 도트는 "뒤지기·둥지 만들기"의 원형을 가장 싸게 수십 명 규모로 보여 준다. 방 배치 전투(`COMBAT_AND_DEFENSE` §3-4)는 **방마다 사람이 보여야** 성립하므로, 한 화면에 여러 명을 띄울 수 있는 해상도가 곧 시스템 요건이다. 그래서 32·48px을 후보에 남겼다.
- **P2(30초에 이해)** — 헬멧·목 실링·공기통·허리 랜턴 네 개를 전 방향 공통 실루엣으로 고정해, 한 장만 봐도 "심해에 사는 사람"이 읽히게 했다.
- **P3(감정의 가속도)** — 차가운 색을 **헬멧 유리와 물빛 가장자리에만** 허용했다. 따뜻한 방 안에 그 사람만 바다를 한 조각 달고 있다.
- **C1(3초 실루엣)** — P5를 두 번 재설계한 이유가 이것이다. 둥근 타원만 쓰면 짐승 덩어리가 된다. **각진 어깨판 + 둥근 헬멧**의 대비가 "잠수부"를 만든다.
- **C10(얼굴 없는 얼굴을 피한다)** + **DECISIONS 2026-09-27(얼굴을 전부 그린다)** — P1·P2·P3·P4·P6 전부 눈·눈썹·입을 넣었다. `REF_ART_FLAT_FOLK` §0의 오독("얼굴 최소")을 반복하지 않았다.
- **REF_ART_FLAT_FOLK §1-5(장식 무늬가 디테일을 대신한다)** — 목 실링의 물결 반복, 옷단의 기운 자국(`R` 적갈 박음질)으로 디테일을 대신했다. 역할마다 무늬를 바꾸면 70px에서도 구분된다.
- **07 W2(작게 만들고 눈으로 확인, 최대 3회)** — **이탈.** 3회가 아니라 7회 고쳤다. 이유: 3회차까지는 "읽히는가"만 봤고, 4회차부터 "징그럽지 않은가"라는 이번 과제의 진짜 기준으로 다시 봤기 때문이다. 합격 기준 ③이 전부라고 지시받았으므로 회수 상한보다 그쪽을 우선했다.
- **07 §6(AI 공개 관리표)** — **이번 산출물은 공개 대상이 아니다.** 생성 AI를 한 번도 호출하지 않았다(Pollinations·Colab 미사용). 전부 절차적 드로잉이고, 코드 AI는 2026 Steam 규칙상 공개 대상이 아니다. 관리표에 새 줄을 추가할 필요 없음.
- **07 W6(매 스프린트 보여줄 것 1개)** — `scene_all.png`과 `charpixel.html`의 걷기 무대가 데브로그용 클립 재료다.

## 4. 직군 교본 §5 자가 검수 5문항

1. **검은 실루엣으로도 8역할이 갈리는가** — 아직 아니다. 이번은 **정찰병 한 명 ×6 방향**이고 8역할은 채택 후다. 다만 각 방향의 확장 경로는 §1-3에 적었고, P5만 "8역할 무리, 4~5종 한계"로 정직하게 적었다.
2. **큰 눈·창백함·부족 적응이 보이는가** — 큰 눈은 P2·P3·P6에서 분명하다. **창백한 피부는 의도적으로 완화했다** — 흰 피부가 흰 가면으로 읽혀 "징그럽다"의 직접 원인이 됐기 때문이다(DECISIONS 2026-09-27 "캐릭터에 입을 넣고 피부를 따뜻하게 한다"). 어둠 적응은 **큰 눈과 랜턴 의존**으로 표현하고 피부는 따뜻한 쪽으로 간다.
3. **각인 3개가 겹쳐도 읽히는가** — 미검증. 각인 파츠는 채택 후 작업. 다만 P2·P3·P6은 목·허리·머리 세 부위가 비어 있어 자리가 있다.
4. **짐승이 사람보다 가깝고 따뜻해 보이는가** — 이번 범위 밖(짐승 미제작).
5. **발 원점·1.6m·+Z·클립 7종** — GLB 규약은 3D 전용이고 이번은 2D 도트다. 대응 규약을 새로 세웠다: **발 = 이미지 맨 아래 줄, 1.6m = 132px(배경 주민 실측), 정면만, 정수 배율 고정**(`meta.json`에 박았다).

## 5. 미완 · 리스크

1. **배경 플레이트에 구 캐릭터가 이미 그려져 있다.** `section_room_zoom.png`에는 이전 화풍의 주민이 들어 있어, 합성 컷 오른쪽 끝에 옛 캐릭터가 보인다. 도트와 나란히 놓이면 판단이 흐려진다 → 배경 담당에게 **사람 없는 방 플레이트** 요청(§6).
2. **P5는 밝은 방에서 실패한다.** 어두운 물속·에어락·원정 화면에서는 강할 수 있으나, 1막 주 무대가 등불 켜진 방이므로 **주인공 화풍 후보로는 탈락**을 권한다.
3. **P1의 얼굴 밀도.** 32px에 눈·눈썹·입을 전부 넣으면 과밀하다. 채택 시 "눈썹 생략 + 실루엣 강화" 변형을 하나 더 만들어야 한다(지금은 과제 제약상 전부 넣었다).
4. **8역할·각인·방향(뒷모습) 미제작.** 채택된 한 방향에 대해서만 다음 스프린트에서 확장하는 것이 맞다. 여섯 전부를 8역할로 펼치면 낭비다.
5. **걷기 3프레임은 "걷는다는 느낌"까지만.** 발 접지·팔 반대 스윙은 들어 있으나 프레임 수가 적어 부드럽지 않다. 채택 후 4~6프레임으로.
6. **배율 불일치.** P2·P5는 ×3=144px, 나머지는 126~128px이다. 정수 배율 제약 때문에 ±12%는 불가피하다. 채택 후 해당 방향의 원본 높이를 44px(×3=132) 등으로 조정하면 정확히 맞출 수 있다.
7. **CC0 팩은 실제로 내려받지 않았다.** 조사만 했고 라이선스는 페이지 문구로 확인했다. 실제 도입 시 **파일을 열어 해상도를 확인**하고 `assets3d/README`에 출처를 등재해야 한다.
