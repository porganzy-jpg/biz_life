### 1-1. 체형 — 무엇을 얼마나 바꿨나

| | 체형 A | 체형 B | 아이 A | 아이 B |
|---|---|---|---|---|
| 어깨 폭 | 17px | **15px** | 14px | 12px |
| 팔꿈치 아래 | 그대로 | **좌우 1px 안으로** | 그대로 | 1px 안으로 |
| 맨머리 키 | 44px = 1.600m | **44px = 1.600m** | 33px = 1.200m | 33px = 1.200m |
| 발 기준선 · 머리 크기 · 얼굴 자리 · 색 | — | **전부 같다** | — | 같다 |

**중간에 한 번 틀렸고 눈으로 재서 고쳤다.** 처음에는 몸통 타원을 허리에서 좌우로 깎았는데, 폭을 실제로 재 보니
**바깥선이 하나도 바뀌지 않았다** — 팔(`ax_l..ax_l+3`)이 그 자리를 통째로 덮기 때문이다.

```
체형 A  y35:20-46  y40:20-46  y45:20-46  y47:20-45     ← 어깨에서 허리까지 폭이 같다
체형 B  y35:21-46  y40:21-46  y45:22-46  y47:22-44     ← 어깨 21 → 허리 22 로 좁아진다
```

그래서 **허리선은 팔이 만든다**로 설계를 바꿨다(팔꿈치 아래를 1px 안으로). 몸통 깎기는 남겨 두었지만
실루엣에 기여하는 것은 팔이다. 이 과정은 `check/bodyAB.png` 의 「겹쳐 보기」(붉은 칸 = A에만 있는 픽셀)에 남겼다.

### 1-2. 머리 6종 · 얼굴 3종 — 왜 「패치」인가

머리와 얼굴을 본체에서 떼어내되, **기본 조합(short + f0)은 시트에 구워 둔다.** 그래야 개발이 레이어를 쓰지 않아도
시트 한 장으로 사람이 완성된다. 레이어는 **기본 시트와의 픽셀 차이만** 담는다.

```
기본 시트(src/<role>[_b].png)  +  hair/<role>_<body>/braid.png  ==  땋은머리 시트
```

이 등식이 **한 픽셀도 틀리지 않는지 생성기가 144장 전부 검사한다**(§3-1). 패치 방식이라 외곽선 변화까지
자동으로 들어간다 — 손으로 맞출 여지가 없다.

여섯 머리는 **전부 같은 정수리 띠로 시작한다.** 그래서 기본(short)으로 구운 시트 위에 어느 머리를 얹어도
기본 머리가 완전히 덮인다. 이것도 자동 검사한다(「기본머리 미덮임: 없음」).

| 머리 | 무엇 | 얼굴 | 무엇 |
|---|---|---|---|
| `short` 짧은머리 | 정수리 띠만(기본) | `f0` | 둥근 눈 · 곧은 눈썹 · 넓은 미소(기본) |
| `tied` 묶은머리 | 오른쪽 투구 테 아래 매듭 + 짧은 꽁지 | `f1` | 좁은 눈 · 올라간 눈썹 · 작은 입 · 주근깨 3점 |
| `long` 긴머리 | 양쪽 어깨 앞으로 내린 두 갈래 | `f2` | 넓게 벌어진 눈 · 안쪽이 내려온 눈썹 |
| `braid` 땋은머리 | 왼쪽 가슴 위 세 마디 땋음 | | |
| `curly` 곱슬 | 정수리 띠가 울퉁불퉁 + 이마 양끝 곱슬 두 점 | | |
| `scarf` 민머리+두건 | 정수리 띠 자리를 천이 대신하고 왼쪽으로 비껴 내림 | | |

**규칙 하나를 스스로 더 세웠다 — 머리 갈래는 「투구 테 아래」에서만 나온다.**
투구 위는 역할이 사는 자리다(C1: 머리에 쓴 것이 역할을 말한다). 머리가 그 위로 올라가면
체형·머리가 바뀔 때마다 역할 판독이 흔들린다. 그래서 매듭·갈래·땋음을 전부 테 아래에 뒀다.
`check/silhouette70_16.png` 에서 체형이 바뀌어도 실루엣의 윗부분이 그대로인 것이 그 결과다.

**또 하나 — 늘어뜨린 갈래는 어두운 쪽을 속심으로 쓴다.** 처음엔 밝은 머리색(`hair`)을 속심으로 썼는데
겉옷이 역할마다 달라서(올리브·크림·숯·황토·자주·적갈) **올리브·황토 역할에서 머리가 묻혔다.** 눈으로 보고
`hairD`(외곽선에 가까운 색)를 속심으로 뒤집었다. 두건만 반대로 밝은 천이 속심이다.

### 1-3. 체형·머리·얼굴은 역할을 보지 않는다 (§6-1 제1 원칙)

```python
def pick_look(role, body, salt=0):      # 게임에서는 role 자리에 uid + 주민 id 가 들어간다
    h = 2166136261
    for ch in (role + '|' + body + '|' + str(salt)):
        h = ((h ^ ord(ch)) * 16777619) & 0xFFFFFFFF
    return HAIRS[h % 6][0], FACES[(h >> 11) % 3][0]
```

역할 문자열은 **시드의 재료로만** 쓰이고 분기에 쓰이지 않는다. 같은 입력이면 같은 사람이 나온다(D6 결정성,
RESIDENT_STATS §3의 스탯 생성 규칙과 같은 꼴). 이 식을 `meta.json.variation_recipe` 에 적어 개발이 같은 걸 돌리게 했다.

결과로 나온 열여섯(생성기 로그 그대로): 의무병 A = 긴머리, 의무병 B = 묶은머리, 기술자 A = 땋은머리,
기술자 B = 긴머리, 농부 B = 곱슬, 교섭가 B = 땋은머리, 정찰병 B = 두건…
**어느 역할에도 특정 머리가 몰리지 않았고, 색은 한 벌 그대로다(분홍 없음).**

## 2. S8이 남긴 숙제 — 의무병과 교섭가의 실루엣

S8 보고서 §4-1에서 내가 "여덟이 갈린다"고 쓰면서도 가장 아슬아슬하다고 적었던 쌍이다.
둘 다 「둥근 머리 + 한쪽으로 뻗은 작은 돌기」였다.

**교섭가의 챙 한쪽을 접어 올렸다.**

```
의무병  머릿수건 + 뒤 꼬리가 **오른쪽**으로            (그대로)
교섭가  챙이 오른쪽으로 더 길고, **왼쪽 챙이 위로 접혀 6px 지느러미**   (신규)
```

뻗는 방향이 좌/우로 반대가 되고, 교섭가 쪽에만 **세로로 선 돌기**가 생긴다.
`check/silhouette70.png` 를 다시 열어 확인했다 — 셋째(의무병)는 매끈한 둥근 윤곽에 오른쪽 혹,
일곱째(교섭가)는 왼쪽 위로 뾰족한 지느러미. **3초 안에 갈린다.**
키에 미치는 영향은 모자 포함 48 → 49px뿐이고 **맨머리 44px(=1.600m)는 그대로**다.

## 3. 자동 검사 — 사람 눈이 아니라 기계가 본다

S8에서는 「각인 12종끼리 겹치지 않는가」 하나만 기계가 봤다. 지시대로 **머리·얼굴까지 넓혔고**, 검사 항목이 다섯이 됐다.
매 실행마다 전부 돈다.

```
[검사] 머리·얼굴 패치 144장, 기본시트+패치==변형시트 불일치 0건
[검사] a      각인×각인 0 · 각인×얼굴 0 · 각인×머리 0 · 기본머리 미덮임 없음 []
[검사] b      각인×각인 0 · 각인×얼굴 0 · 각인×머리 0 · 기본머리 미덮임 없음 []
[검사] kid    각인×각인 0 · 각인×얼굴 0 · 각인×머리 0 · 기본머리 미덮임 없음 []
[검사] kid_b  각인×각인 0 · 각인×얼굴 0 · 각인×머리 0 · 기본머리 미덮임 없음 []
[검사] 레이어 충돌 합계: 0건
[검사] a/b/kid/kid_b  water_memory 는 머리 6종 모두에 얹히는가: True True True True
```

### 3-1. 다섯 검사가 각각 무엇을 막는가
| # | 검사 | 막는 사고 |
|---|---|---|
| ① | 각인 12종 × 각인 12종 | 각인 두 개를 동시에 달면 한쪽이 지워진다 |
| ② | 각인 12종 × **얼굴 3종** | 각인이 눈·눈썹·입·홍조를 덮어 표정이 죽는다 |
| ③ | 각인 12종 × **머리 6종** | 머리를 바꿨더니 각인이 사라진다 |
| ④ | **기본머리 덮임** | 머리를 바꿔도 기본 머리가 밑에서 비친다 |
| ⑤ | **기본시트 + 패치 == 변형시트** (144장 전수) | 개발이 레이어를 얹었을 때 내가 본 것과 다른 그림이 나온다 |

### 3-2. 검사가 설계를 거꾸로 뒤집은 예외 하나
「**물의 기억**」(젖은 앞머리 + 반짝임)은 **머리 위에 얹히도록 설계된** 각인이다. ③을 그대로 적용하면 영원히 실패한다.
그래서 이것만 ③에서 빼고, 대신 **거꾸로 검사한다** — "머리 6종 **전부**와 실제로 겹치는가". 네 체형 모두 True다.
겹치면 안 되는 것을 검사하는 것만큼, **겹쳐야 하는 것이 겹치는지** 검사하는 것도 필요했다.
`meta.json.imprints[].on_hair` 에 플래그로 남겼다.

### 3-3. 검사가 실제로 잡아낸 결함 셋 (전부 고쳤다)
1. **「지킨 자」(오른 광대) × 얼굴 3종의 볼 홍조** — 같은 줄에 있었다. 각인을 1px 아래·안쪽(턱 쪽)으로 내렸다.
2. **「깊이의 자국」·「두드림을 들은 자」(좌우 관자놀이) × 아이의 얼굴 ③** — 아이는 얼굴이 작아(반지름 5.2px)
   넓게 벌린 눈이 관자놀이까지 왔다. ①각인의 꼬리를 바깥으로 돌리고 ②얼굴 ③의 눈 간격을
   **고정값에서 얼굴 반지름 비례로** 바꿨다. 어른에게는 변화가 없다.
3. **「깊이의 자국」 × 「햇빛의 기억」(머리 왼쪽 베일)** — ②를 고치다가 새로 생겼다. 꼬리를 직선으로 폈다.

②가 중요하다. **아이를 어른의 축소판으로 다루면 안 된다**는 것을 기계가 알려 줬다. 어른만 보고 끝냈으면 못 봤다.

## 4. 검증 — 눈으로 보고 고친 횟수 (07 W2)

**`Read` 로 직접 열어 보고 6회 고쳤다.**

| 회차 | 본 것 | 진단 | 고친 것 |
|---|---|---|---|
| 1 | `bodyAB.png` 1차 | 체형 A와 B가 **구분이 안 됨** | 폭을 픽셀로 재 보니 **팔이 몸통을 덮어 바깥선이 안 바뀜** → 팔꿈치 아래 1px 당기기로 설계 변경 |
| 2 | `bodyAB.png` 2차 | ×6 확대가 패널 밖으로 잘림, 실루엣 비교가 뭉개짐 | ×4 + **겹쳐 보기**(A만/B만 픽셀을 색으로) 추가 |
| 3 | `hair6_face3.png` 1차 | 의무병으로 찍어서 **크림 가운에 머리가 묻힘**, 전신이라 너무 작음 | 기술자(숯회색)로 바꾸고 머리+어깨만 ×5 확대 |
| 4 | `hair6_face3.png` 2차 | 얼굴 ③이 **눈썹이 굵고 낮아 화난 얼굴**로 보임 | 눈썹을 눈에서 떼고 눈 높이를 되돌리고 입을 넓은 미소로 |
| 5 | `poses.png`(체형 B·땋은머리) | **땋은머리가 안 보임** | 머리색이 소매와 같은 갈색이었다 → 어두운 쪽을 속심으로 뒤집고, 갈래를 팔 안쪽(겉옷 위)으로 옮김 |
| 6 | `silhouette70.png` | 교섭가 vs 의무병 재확인 | 통과(§2) |

### 4-1. 70px에서 16명 — 역할이 버티는가
`check/row70_16_light.png` · `row70_16_dark.png` · `silhouette70_16.png`

**통과. 그리고 통과의 뜻을 정확히 적는다.**
- **역할은 70px에서도 흔들리지 않는다.** 갈라 주는 것은 여전히 「머리에 쓴 것」이고, 체형은 바깥선을 좌우 1~2px만 움직인다.
  검은 실루엣 16개를 놓고 봐도 같은 역할의 A/B가 **같은 머리 모양**을 하고 있다 — 이게 지시의 요구였다
  ("체형이 역할 구분을 흐리면 안 된다").
- **사람의 차이(체형·머리·얼굴)는 70px에서 희미하고, 실제 게임 크기 ×3 = 132px에서 읽힌다.**
  이건 결함이 아니라 §6-1 "아주 조금만 난다"를 지킨 결과다. 실제 크기 증거는 §4-2.

### 4-2. 실제 게임 크기(×3) — `charpixel.html` §체형 5꼭지 「16종 걷기」
브라우저에서 16장 카드를 직접 봤다. **×3에서는 A와 B가 분명히 다른 사람이다** —
요리사 A(짧은머리) vs B(땋은머리·어깨 좁음), 의무병 A(긴머리·크림 가운 위 어두운 두 갈래) vs B(묶은머리),
기술자 A(땋은머리) vs B(긴머리). 각 카드는 그 자리에서 걷는다(CSS `steps(3)`, 방 빛을 받은 시트).

## 6. 직군 교본 §5 자가 검수 5문항

## 7. 미완 · 리스크

1. **70px에서 같은 역할의 A/B는 거의 같아 보인다.** 이것은 §6-1("아주 조금만 난다")을 지킨 결과이지
   버그가 아니다. 다만 **UI가 주민을 70px 이하로 줄여서 쓰는 화면이 생기면**(예: 방 배치 미니맵)
   그 화면에서는 사람을 이름·스탯 점으로 구분해야 한다. 개발과 PM이 알고 있어야 한다.
2. **머리 갈래는 자세가 바뀌어도 모양이 같다.** 머리는 자세별로 다시 그리지 않고 한 벌을 모든 행에 쓴다
   (자세별로 찍으면 파일이 7배가 된다). 실제로 문제가 되는 곳은 `carry`(물건 들기) 하나였다 —
   땋은머리 끝 2px이 상자 윗단을 덮었다. **땋음을 한 마디 줄여** 상자 위에서 멈추게 했고,
   여섯 머리 × 두 체형 전부가 상자 윗단(원화 y 41)보다 위에서 끝나는 것을 코드로 확인했다(최대 y 40).
   다만 `sit`·`hurt` 처럼 몸이 낮아지는 자세에서는 갈래가 어깨에 **얹힌 듯** 보인다 — 치명적이진 않지만
   정식 자세별 머리가 필요해지면 그때 `sit`·`hurt` 두 행만 따로 찍는다.
3. **스탯 UI(점 네 줄 + 특이점 한 줄)는 안 만들었다.** 개발 영역이다. 다만 그 카드에 **초상 썸네일**이 들어간다면
   체형·머리·얼굴 조합이 시트와 같아야 한다 — `meta.json.variation_recipe` 를 쓰면 저절로 맞는다.
4. **역할 진화 표식 8종 여전히 미제작**(S8 §7-4, 시나리오 요청 43). 남은 부위는 등(공기통 사이)·오른 어깨·
   왼 손목·장화 넷이다. 이제 머리·얼굴 레이어도 자리를 썼으므로 **남은 부위가 더 줄었다** — 시나리오에서
   부위 지정 한 줄을 받으면 바로 넣고, 자동 검사에 ⑥번 항목으로 추가하겠다.
5. **감정 교체 얼굴 미제작**(S8 §7-5). 지금 얼굴 3종은 **사람의 차이**이지 **감정의 차이**가 아니다.
   둘은 다른 축이고, 감정 4종을 더하면 얼굴 레이어가 3 × 5 = 15종이 된다. 패치 구조가 이미 있으니
   추가 비용은 코드 한 함수다.
6. **부족 의상 미제작**(S8 §7-6). 1막 범위 밖.
7. **시나리오 S9-B의 신규 생물 아홉 실루엣 미착수.** 같은 스프린트에 요청이 들어왔고 이번엔 체형을 맡았다.

   다음 스프린트 1순위로 둔다.
8. **옛 폴더 정리 미착수**(S8 §7-7). `journey.html` 이 아직 `front/b/*_hero.png` 를 쓴다.
