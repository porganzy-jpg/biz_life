## 3. 어떻게 했나 — 뼈 스케일 + **키 재정규화**

```
build(role)                      ← S4와 동일. 여기서 보정 전 실측 키 h0 을 잰다
  → folk_extras(cute=True)       ← 화풍 형상(목 실링·무게추·헬멧). 자락만 구로 교체
  → cute_eyes()                  ← §5-3-2
  → folk_materials()             ← 팔레트·2단 음영. 손대지 않음
  → cute_static()                ← 뼈 **스케일** (액션이 키프레임하지 않으므로 클립을 갈아도 유지)
  → cute_frame()                 ← 발 IK 타깃 올림 (액션이 매 프레임 덮어쓰므로 다시 건다)
  → 재정규화: 스케일 f = h0 / (보정 후 키) 를 곱하고 발을 z=0 으로
```

**재정규화가 이 작업의 핵심 안전장치다.** 비율만 바꾸고 총 키를 원래대로 되돌리기 때문에:

| 규약 | S4 | S5-C | 결과 |
|---|---|---|---|
| 실측 키(정찰병·의무병·아이·기술자) | 1.6812 / 1.6216 / 1.2074 / 1.6627 | **완전히 동일**(소수점 4자리) | 회귀 0 |
| 미터당 110px · 발 기준선 240px | 유지 | 유지 | 클라이언트 코드 변경 0 |
| 시트 레이아웃(셀 256 · 가로 5 · 세로 3) | 유지 | 유지 | 경로의 `b`→`c` 한 글자면 교체 |

문어만 예외다(아마추어가 없어 절차 생성): 외투막을 키운 만큼 키가 0.52 → **0.57 m**로 늘었다. 의도한 것이고 `h_c`에 기록했다.

## 6. 04 §5 자가 검수 5문항

1. **검은 실루엣으로도 8역할이 갈리는가?**
   보정판은 대표 5종(+선택 4종, §8-1)에만 적용했고 **그 다섯은 70px 3배경에서 전부 갈린다.** 오히려 S4보다 낫다 — 얼굴 덩어리가 커져 명도 대비가 강해졌다. 다만 **실루엣만 놓고 보면 S4보다 서로 닮았다**: 아래가 전부 같은 둥근 종 모양이 됐기 때문이다. 판별은 이제 실루엣 1 : 색 1.5 : 머리 장비 2 의 비중이다. 이것은 「덩어리진 실루엣」(REF §1-6)을 강하게 따른 결과이지 사고가 아니다.
2. **큰 눈·창백함·부족 적응이 보이는가?**
   **큰 눈이 돌아왔다.** S4 §8-2에 적어 둔 「성경 C2(큰 눈) vs REF §1-7(작은 눈 점)」 충돌이 이번 지시로 **성경 쪽으로 정리됐다** — 다만 코·입은 계속 없으므로 REF §1-7의 "얼굴은 최소"도 절반은 지킨다. 창백함은 얼굴 면적이 커져 더 강해졌다. 부족 적응(C3) 7종은 여전히 미적용(S2부터의 잔여 과제).
3. **각인 3개가 겹쳐도 읽히는가?**
   정찰병 `c/scout_imp3.png`로 확인 — 176px에서 읽힌다. **70px에서는 S4와 같이 허리띠만 남는다.** 개선도 악화도 아니다(미완, §8).
4. **짐승이 사람보다 가깝고 따뜻해 보이는가?**
   **더 그렇다.** 문어도 같은 규칙(머리 키우기·눈 키우기·하이라이트)을 받아 외투막이 커지고 황토 눈이 커졌다. 사람 넷은 여전히 서로 닿지 않고, 문어만 둥글게 웅크린다. 색은 한 값도 안 바꿨다(C5의 "짐승 눈이 더 밝다"가 그대로 유지).
5. **발 원점·키·+Z·클립이 맞는가?**
   맞는다. 실측 키 4종이 **소수점 4자리까지 S4와 동일**, 발 기준선 240px(렌더 실측 240~243px, 걷는 중 ±3px은 애니메이션), 클립 3종, 정면 0°. 문어만 0.52→0.57로 의도적으로 커졌다.

## 7. 교본 인용

- **00 P1(보편적 원형 — 둥지 들여다보기)** · **P2(한 장의 스크린샷)** — 70px 판별을 1순위로 둔 이유. 귀여움은 2순위다. 이 순서를 지키려고 머리 배율을 1.50에서 1.26으로 내렸다.

## 8. 미완·리스크

1. **요리사가 여덟 중 가장 약하다.** 높은 요리모자가 **머리 메시 안에** 있어서 머리 배율이 그대로 곱해지면 모자가 접시 더미처럼 퍼지고, 키를 되돌리는 과정에서 몸이 눌려 통처럼 보인다. 머리 배율만 예외로 낮춰(`CUTE_HEAD = {"cook": 1.12}`) 완화했지만 나머지 일곱만큼 좋지는 않다. **모자를 소품으로 분리해야 제대로 풀린다**(메시 작업 = 다음 스프린트). 요리사는 대표 5종이 아니므로 합격 기준에는 영향이 없다.
2. **적용 범위.** `c` 는 **8역할 + 문어 전부** 있다. hero 512는 대표 4종 + 문어만. **한 화면에 b와 c를 섞으면 등신이 달라 보인다** — 통일 여부는 PM 판단(`TASKS.md` 요청함에 등재).
3. **실루엣 유사도 상승.** 다섯의 아래쪽이 모두 같은 둥근 종이 됐다. 지금은 색과 머리 장비로 갈리지만, 역할이 더 늘면 **밑단 폭을 역할마다 다르게** 하는 손잡이가 필요하다(`CUTE["skirt"]`를 역할별 값으로 바꾸면 된다).
4. **각인 70px 미판독** — S4에서 넘어온 그대로. 머리가 커지면서 얼굴 각인(반점·흉터)은 오히려 유리해졌을 것이나 확인하지 않았다.
5. **PickUp 구간을 22% → 18%로 줄였다**(보정판만). 머리가 1.26배라 같은 각도에서 정수리가 더 크게 보이기 때문이다. 보정 전 b는 22% 그대로 둔다. **남은 약점: 아이의 PickUp 마지막 프레임은 후드가 얼굴을 덮어 노란 원반으로 보인다** — b에서도 같은 프레임이 같은 문제를 갖는 **기존 한계**(S4 §5)이고 이번에 악화시키지는 않았다(과장 0 대조군을 따로 렌더해 확인). 「일하는 모션」을 좌우·상하로 새로 설계해야 근본 해결된다.
6. **정면 한 방위뿐** — S4와 동일.
7. **`pick_chin`(턱 들기) 실패 기록.** `pb.matrix` 로 Head에 월드 회전을 걸면 화면에 변화가 없었다. 부모 갱신 순서 문제로 보이며, 뼈 단위 회전 과장이 더 필요해지면 **로컬 쿼터니언으로 다시 짜야 한다.** 주석에 남겼다.
8. **용량**: `static/art/chars/front/c` **4.1MB** 추가(원본 `art_raw/chars_cute` 6.3MB). 화풍·비율 확정 후 a안을 빼고 프레임을 5→3으로 줄이면 전체 2MB 이하로 내려간다(S4 §10-9와 같은 처방).
9. **문어 키 0.52 → 0.57.** 개발이 문어를 `h` 로 배치하고 있다면 5cm 커진다.
