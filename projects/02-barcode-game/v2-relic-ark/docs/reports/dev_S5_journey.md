### 페이지 구성
1. **머리** — `section_hero.png` 를 어둡게 깐 표지 + 이 페이지가 무엇인지 한 문장.
2. **§00 한 화면 요약** — 다섯 동사(보다 → 나가다 → 돌아오다 → 커지다 → 찾아오다) 카드 5장 + **감정 곡선 SVG**.
   곡선 위에 J1~J14 를 시각(0:00·2:30·…·1개월)과 함께 찍었고, 공들인 다섯 장은 굵은 점으로 구분했다.
   J10~J14 구간은 「같은 바퀴를 더 크게 — 하루·주·달」 띠로 묶어, 다섯 동사가 스케일만 바꿔 반복된다는 것을 한 눈에 보이게 했다.
3. **J1~J14 블록 14개** — 왼쪽에 폰 세로 비율(390×844) 시안 한 장, 오른쪽에 여정 표의 네 열 그대로
   (무엇을 보는가 / 무엇을 하는가 / 무엇을 느끼는가 / 어떤 시스템이 작동하는가) + 그 단계를 왜 이렇게 두는지 한 문단.
4. **§15 보강 일곱** — E1~E7 카드 + 지표 카드 + **E×J 작동 지점 표**(7행 × 14열).

### 공들인 다섯 장 — 무엇을 어떻게 그렸나
- **J1 첫 숨**: 화면의 3/4이 검정. 아래에서 돔이 절반만 떠오른 중간 상태로, 방 세 칸의 불빛만 서로 다른 투명도로 켜 둔다. **UI 0 · 자막 0.**
- **J5 첫 스캔(3컷)**: ① 카메라 뷰(조준 브래킷·스캔선·셔터, 진짜 EAN-13 막대 그림) → ② 카드 뒤집힘(rotateY) + **E7 전체 화면 공개** → ③ **창고 선반 3단에 그 물건이 놓인다(E1)**. 방금 놓인 상자만 밝기와 글로우를 올려 "저게 내가 찍은 것"이 즉시 읽히게 했다.
- **J7 문어**: 창 안쪽에서 문어가 들어오고 빨판이 그려진 팔이 아이 손목까지 닿는다. 아래에서 **이름 입력칸**(커서 깜빡이는 필드 + 「정했다」)이 올라온다. 캐릭터는 기존 `kid_hero.png` · `octopus_hero.png` 사용.
- **J10 하루 마감**: 「오늘 바뀐 것」 4줄(각 줄 색점 = 종류) + **눈금 일지**. `90초` 취소선 → `85초`, 그리고 눈금 막대 차트에서 회색 눈금(90초 구간)보다 주황 눈금(85초 구간) 간격이 실제로 좁다. 아래에 「내일 오는 것」 한 줄.
- **J14 해구 문턱**: 방주가 화면 위로 밀려 올라가고 깊이 눈금이 맨 아래 「해구 문턱」에 닿아 있다. 다음 자리에는 ×, 그 밑에 빗금 경계와 **"여기서부터는 지어지지 않는다"**, 그 아래는 정보가 없는 검정 + 「먼 울음 · 41초」.

## 2. 성경·교본을 어떻게 지켰나

**팔레트(REF_ART_FLAT_FOLK §5)** — CSS 변수 이름부터 갈라 두었다.
`--cream/--ochre/--lamp/--oxblood/--charcoal/--olive` 는 **실내·사람에만**, `--water-far/--water/--deep/--abyss`(청록→남색→검정)는 **물에만**.
방 색은 `base.js` 의 방 색표(`pantry #c08a33`, `well #d8c9a3`, `infirmary #8c9161`, `library #c6a23a`, `rock #a2603a`)를 그대로 가져와 **거점 화면과 같은 계열**을 유지했다.
**화면에서 가장 밝은 것은 언제나 방 안의 등불**이라는 규칙 때문에 J11의 방 바탕을 크림(#d8c9a3)에서 황토(#b4712f)로 내렸다(크림 벽이 등불보다 넓고 밝아 규칙을 깼다).

**단면 원리(REF_CROSS_SECTION §1)** — 정면 직교, 방=얕은 상자(뒷벽 `.bk` + 바닥 `.fl`), **3px 숯검정 테두리**, 방마다 다른 색, 방마다 사람 2~6명(빈 방 없음), 수직 척추가 유일한 동선 축, **UI는 가장자리에만**(가운데는 언제나 거점), 아래로 갈수록 나중 콘텐츠.

**적용한 교본 원칙**
- **P2(30초 안에 이해)** — §00 한 화면 요약이 페이지의 첫 화면에서 게임 전체를 한 번에 설명한다.
- **P3(감정의 가속도)** — 감정 곡선을 실제 그래프로 그려, 이 게임이 상태가 아니라 **변화**를 설계한다는 것을 그림으로 주장한다. J4(각박) 직후 J5(발견), J8·J9(상실·공포) 직후 J10(마침표)의 낙차가 곡선에 그대로 보인다.
- **P1(원형 체험)** — E1을 3컷으로 크게 다룬 이유. 뒤지기(스캔) → 비축(선반) → 둥지(증축)가 한 줄로 이어지는 것이 이 게임의 원형이다.
- **D2(모든 숫자는 화면의 무엇으로 보인다)** — 이 페이지 자체가 D2의 시각화다. 공기·깊이는 숫자가 아니라 줄어드는 띠, 자원은 선반 위 물건, 울음 간격은 눈금 막대, 성장은 방 칸 수.
- **D5(첫 3분 루프)** — J1~J6(첫 6분)에 탭이 몇 번 드는지 각 블록의 "무엇을 하는가"에 명시했다(문 열기 1, 줍기 1, 촬영 1, 배치 1).
- **D8(모바일 예산)** — 폰 프레임 안의 손가락 대상(셔터·「정했다」·선택지·줌 버튼)을 390 기준 40~66px로 잡아 44px 규칙을 지켰다.
- **S1(보여주고 말하지 않는다)** — 폰 프레임 안에는 설명문을 넣지 않았다. 안에 들어간 글자는 전부 **그 화면에 실제로 뜰 UI 문자열**(방 이름·토스트·쪽지·선택지·라벨)이다. 해설은 프레임 **밖** 오른쪽 네 줄로 분리했다.
- **W2(작게 만들고 눈으로 확인)·W6(매주 보여줄 것)** — 14블록을 전부 브라우저에서 한 장씩 확인하고 13곳을 고쳤다(§3). 데브로그용 스크린샷 6장이 나왔다.
- **07 §6(AI 공개 관리표)** — **이 페이지는 새 AI 생성물을 만들지 않는다.** 폰 화면은 전부 손으로 쓴 HTML·CSS·SVG이고, 사용한 이미지는 이미 관리표에 올라 있는 기존 에셋 2종(배경 1·캐릭터 스프라이트 4)뿐이다. 공개표 갱신 불필요.

**원칙과 다르게 한 곳 (이유)**
1. **D7(데이터가 규칙을 든다)을 따르지 않고 마크업에 값을 직접 박았다.** 이 산출물은 동작하는 시스템이 아니라 **기획안용 그림**이라 JSON 스키마 계약이 필요 없다. 데이터화하면 시안 한 장을 고치는 비용만 커진다. 실제 구현 때는 각 화면이 `base.js`/`data/*.json` 으로 옮겨 간다.
2. **J5만 폰 3장(3컷)** — 나머지는 한 장 규칙을 깼다. E1이 이 게임의 정체성이고(PLAYER_JOURNEY §6 우선순위 1), "카드가 나온다"와 "물건이 선반에 놓인다"는 한 장으로 겹쳐 그리면 둘 다 죽는다.
3. **폰 세로에서 J5 3컷을 축소하지 않고 한 장씩 세로로 쌓았다.** 3분할하면 220→150px가 되어 UI가 안 읽힌다. D8의 "읽혀야 한다"를 우선했다.

### 3-2. 서버 기동

$ RELIC_DEV=1 python server.py --port=8012

## 5. 자가 검수 (02_DEV §5)

1. **새 숫자가 화면의 무엇으로 보이는가?** — 이 페이지는 숫자를 만들지 않고, 기존 숫자가 무엇으로 보여야 하는지를 **정의하는** 문서다. 공기=띠, 깊이=눈금과 방 칸 수, 자원=선반 위 물건, 울음 간격=눈금 막대 차트.
2. **첫 3분 루프의 탭 수가 늘었나?** — 늘지 않았다. 게임 화면이 아니라 `/journey` 별도 페이지이고 게임 흐름에 링크를 넣지 않았다(반대로 페이지 하단에서 `/base`로 나간다).
3. **같은 입력이면 같은 결과인가(시드)?** — 정적 페이지라 난수 0, 애니메이션 0. 언제 열어도 같은 그림이고 스크린샷 회귀 비교가 가능하다.
4. **폰 가로 720px에서 손가락으로 조작 가능한가?** — 페이지 자체는 읽기 전용이고 390px에서 가로 넘침 0. 시안 안의 터치 대상은 40~66px로 그려 44px 규칙을 지켰다.
5. **회귀 로그가 있는가?** — §3-4에 스캔·건설·사건·각인·도감·스팟·기존 화면 9건의 응답을 붙였다.

## 5-1. 자가 검수 (07 §7)
1. 사람이 읽고 고칠 수 있는가 — HTML 1파일(약 90KB)·CSS 1파일(약 23KB), 블록마다 `<!-- J7 -->` 주석. 각 시안이 독립이라 한 장만 고쳐도 다른 장이 안 깨진다.
2. 플레이어가 보고 듣는 AI 생성물인가 — **새로 만든 것 없음.** 기존 관리표 항목만 재사용.
3. 보여줄 스크린샷·클립 — 6장 확보(전체 1 + 구간 5).
4. 첫 3분 루프가 무거워졌나 — 아니오.
5. 어느 지표를 움직이는가 — 직접 움직이지 않는다(기획 문서). 간접적으로 E1·E3·E6의 구현 우선순위를 눈으로 합의시켜 H1·H3에 닿는다.

## 6. 미완 · 리스크

1. **`/journey`가 8002에서 아직 404다.** 8002의 서버 프로세스가 옛 코드다. **누군가 8002를 재기동해야 한다**(내가 죽이지 않은 이유는 §3-2). 그 전까지는 `/static/journey.html` 로 열면 된다.
2. **시안은 정지 화면이다.** J1의 "떠오른다", J5의 "뒤집힌다", J7의 "감는다"는 중간 상태 한 컷으로만 표현했다. 움직임이 필요하면 CSS 애니메이션을 얹을 수 있지만, 기획안 인쇄·캡처용이라 일부러 정지로 뒀다.
3. **소품 스프라이트가 아직 색 상자다.** E1의 진짜 값어치는 "라면 상자처럼 생긴 것"이 선반에 놓이는 것이다. 지금은 색과 크기로만 구분한다 — 소품 30종이 나오면 J5 ③을 교체해야 한다.
4. **J12 열수구 정원은 코드로 그린 근사치**다. 배경 담당의 실제 스팟 렌더가 나오면 그 장은 이미지로 바꾸는 편이 낫다.
5. **캐릭터 3등신화(PLAYER_JOURNEY §5-3)가 진행 중**이라, J7·J11·J3·J4·J12에 쓴 `front/b/*.png` 가 교체되면 크기·발 위치를 다시 맞춰야 한다(각 `.fig` 의 top/width 5곳).
6. 전체 스크린샷 2장이 합계 약 4MB다. 저장소가 무거워지는 것이 싫으면 PM이 구간 5장만 남기고 전체본을 지워도 된다.
