## 2. 한 바퀴가 어떻게 도는가

```
   소리          →  실루엣             →  (준비: 얼마든지)      →  접촉        →  결과       →  흔적
   알림 + 오디오      바깥 물에 그림자가      사람을 옮긴다            관문 + 점수     막음/금/상실   금·물 찬 방
   어느 방인지 모름   그 방 쪽으로 다가온다   불을 끈다 / 전원을 내린다
                     창 앞에서 **멈춰 선다**  밖의 사람을 들인다
                                            도구를 만들고 붙인다
```

- **시계가 없다.** `/api/raid/advance` 는 플레이어가 누를 때만 단계를 올린다. 실루엣이 다 와도 접촉하지 않고 창 앞에서 기다린다(§6-2 「놀래키지 않는다」, §9 준비 단계 권장안 채택).
- **정보를 숨기지 않는다.** 실루엣 단계부터 `ready.gate`(관문 한 줄)와 `ready.would`(지금 맞서면 어떻게 되는지)를 그대로 내려 준다. 02_DEV §3 Slay the Spire — 계획이 가능해야 선택이 선택이 된다.
- **접촉은 하루 한 번뿐이다.** 이미 지나간 습격은 다시 뽑히지 않는다.

## 3. 방어 판정 공식 (정본: `engine/combat.py` `evaluate`)

### 3-1. 관문이 먼저다
종마다 **단 하나의 조건**이 있고, 그것을 못 넘기면 점수가 아무리 높아도 막지 못한다.
점수로 뭉개면 모든 습격이 "사람 많이 넣기"로 수렴하고, 그것이 이 장르를 지루하게 만드는 주범이다(§4).

| 생물 | 관문 | 통과 조건 |
|---|---|---|
| 작은 떼 | `people` | 그 방 사람 수 + 도구가 드는 손 ≥ **2 + 세기** |
| 긴목 | `lights_off` | 그 방의 **불이 꺼져 있다**(차광 덧문도 같은 효과) |
| 문지기 | `quiet` | **전원이 내려가 있고** 전원이 **한 방에** 모였다(소리 가리개 방이면 전원 무관) |
| 손톱 무리 | `all_inside` | **밖에 있는 사람이 0명** |
| 동거 문어 | `none` | 관문도 판정도 없다. 식구다 |

### 3-2. 점수
```
score = 방 1.0
      + Σ 사람      (0.5 + 0.1 × 담)        ← 부상이면 × 0.5
      + Σ 역할 태그 일치 1.5                 ← roles.json counter_tags ∩ 생물 role_tags
      + Σ 각인 일치     1.5                 ← 두드림을 들은 자 · 금을 본 자 · 아낀 숨
      + Σ 설치 도구 세기                     ← 이음매 보강대 2.0 / 긴 장대 그물 2.0 / 전용 도구 1.0
      + Σ 소모품 세기                        ← 접촉 순간에 쓴 것
      + 관문 통과 3.0

need  = 생물 기본값(3.0~4.0) + 세기(0~2, 시드 uid|day|raid|sev)
```

### 3-3. 등급
| 조건 | 결과 |
|---|---|
| 관문 통과 & score ≥ need | **막았다** — 자원 소량 + 각인 기회 |
| 관문 통과 & need−2 ≤ score < need | **유리에 금** — `room.cracked`, 사기 −1 |
| 관문 실패 & score ≥ need−2 | **유리에 금** |
| 그 밖 | **방을 잃는다** — 격벽이 닫히고 영구 침수, 1명 부상, 사기 −3 |

### 3-4. 결정성(D6)
**난수가 한 톨도 없다.** 같은 `ctx` 로 1,000번 평가해 서로 다른 결과 **가짓수 1**.
난수가 쓰이는 곳은 그날의 **생물·대상 방·세기** 뿐이고 전부 `uid|day|raid|목적` 시드다.
그래서 화면이 접촉 **전에** 보여 주는 예상(`ready.would`)이 실제 결과와 **언제나 같다**(검증 로그 §5-1).

### 3-5. 이탈 1 — 도구가 「사람 몫」을 한다
사양서에는 작은 떼가 **사람 수**로만 막힌다고 되어 있다. 그대로 두면 정원 2인 방(정수실·서고)은
세기 2의 떼를 **영영** 막을 수 없는 막다른 골목이 생긴다(정원 상한 < 필요 인원). 그래서
봉합 패치·긴 장대 그물·이음매 보강대에 `hands: 1` 을 주어 관문 계산에서 한 사람 몫을 하게 했다.
공식이 아니라 **막다른 골목을 없애려는 보정**이고, 관문 문구에 "(지금 2명 + 도구 1)"로 그대로 보인다.

## 4. 주민 스탯 넷 (PM 추가 지시)

| 스탯 | 어디에 실제로 물렸나 | 코드 |
|---|---|---|
| **담** | 방어 판정의 **사람 무게**(0.5 + 0.1×담, 부상 ×0.5). 담 5 = 옛 1.0 과 같다 | `combat.person_weight` |
| **눈** | 돔 안 최고 눈 ≥ 8 이면 **소리 단계에서 이미 대상 방을 안다**(예고 한 단계 앞당김) | `server.raid_public` `EYE_EARLY` |
| **손** | 공방에 **서 있는 사람**의 손 ≥ 8 이면 재료 하나를 아끼고, ≤ 3 이면 하나가 더 든다 | `server.craft_cost` |
| **숨** | 부상 회복 순서 — 숨이 긴 사람이 먼저 일어난다 | `server.tick_production` |

- 생성: 역할 기본값(§3-1 표 그대로) + 무작위 −2~+2 + **특이점 ±2**, 범위 1~10, 시드 `uid|resident_id|stats`.
- **특이점은 절반이 마이너스다**(`rng.random() < 0.5`). 실측 표본에서 「손이 서툴다」 「밤눈이 어둡다」 「큰 것 앞에서는 못 선다」가 고르게 나온다.
- 화면: 숫자를 크게 쓰지 않는다. **점 네 줄**(●×값 + ·×나머지)과 그 아래 **특이점 한 줄**. 그 방에 유리한 스탯과 **노려지는 방의 「담」**이 등불색으로 밝아진다.
- 스탯은 **변하지 않는다.** 사람이 바뀌는 일은 각인이 한다(§3-3 설계 가드 준수).
- 구버전 방주: `ensure_stats(uid, r)` 가 같은 시드 규칙으로 채운다. 기존 저장은 깨지지 않는다(§5-3 로그).

## 7. 배치 UX를 이렇게 고른 이유

| 선택 | 왜 |
|---|---|
| **드래그(데스크톱) + 탭-탭(폰)을 같은 코드로** | `pointerdown` 에서 사람을 잡고, 8px 넘게 움직이면 드래그, 안 움직이면 선택. 두 입력이 같은 `place()` 로 들어간다. 분기 두 벌을 만들지 않았다 |
| **들고 있을 때는 '놓기'가 먼저** | 폰 검수에서 실제로 걸린 결함: 사람이 있는 방을 탭하면 그 방 사람을 새로 집어 영원히 못 옮겼다. 지금은 carry 가 있으면 방 탭 = 놓기 |
| **패널에 「갈 곳 목록」** | 폰에서 패널(바텀 시트)이 화면 아래 절반을 덮어 목표 방을 탭할 수 없다. 목록이 있으면 손가락 하나로 끝난다. 정원이 찬 방은 비활성(44px 터치 영역 유지) |
| **사람을 탭하면 그 사람의 카드가 열린다** | 스탯 네 줄과 특이점을 보려면 카드가 필요한데, 따로 여는 동작을 만들면 탭이 는다(D5). 집는 동작에 얹었다 |
| **홀을 화면에 그렸다** | 배치 안 된 사람이 "목록 어딘가"에 있으면 옮길 생각이 안 난다. 돔 상부에 서 있으면 **보이니까 옮긴다**(D2) |
| **HUD 를 `pointer-events:none` 으로** | 자원 줄이 캔버스를 가로채 폰에서 사람을 못 집었다. 버튼만 이벤트를 받는다 |
| **습격 막대 높이가 바뀌면 카메라가 그만큼 민다** | 폰에서 막대가 자라며 홀을 덮었다. 줌은 건드리지 않고 카메라만 민다 |

## 8. 캐릭터 p2 적용 (DECISIONS 2026-10-01)

`front/p2/` 가 이미 도착해 있어 **색 사각형으로 진행하지 않고 실제로 붙였다.**
- 폴백 사슬 **`p2 → c → b → a → 색 사각형`**. 변형마다 시트 규약이 다르므로 `SHEETS` 표 하나로 분기한다(`base.js`).
- 2.5D 성립 조건: ① **정수 배율 + 최근접 보간** — ×1 원화 `src/<role>.png`(셀 64·기준선 60)를 `round(37.4·cam.z / 27.5)` 배로, `imageSmoothingEnabled=false`. ② **방 등불색** — `masks/<role>.png` 로 흰 곳만 곱연산(불 꺼진 방은 차가운 쪽). ③ **발밑 접지 그림자** 타원.
- **이탈 2**: 규약이 지정한 ×3(단면 렌더용)·×4 고정 배율은 자유 줌이 있는 캔버스에서 쓸 수 없다. 대신 **원화 기준 정수 배율**(1·2·3×)을 쓴다 — 원리(정수·최근접)는 지키고 숫자만 다르다. 캐릭터 담당에게 회신으로 남겼다.
- 아직 안 쓴 것: `walk`·`work`·`sit`·`carry`·`hurt`·`back_walk` 행, `imprints/` 레이어. 지금은 `idle` 2프레임만.

## 12. 자가 검수 (02_DEV §5)

1. **새 숫자가 화면의 무엇으로 보이는가?**
   담 → 판정 내역의 "바람 · 담 4 0.9" 한 줄과 주민 카드의 점. 점수/필요치 → "지금 맞서면 막았다" 한 문장.
   관문 → "그 방의 불을 끈다 — 지금 켜져 있다". 침수 → 물결과 가라앉은 가구 그림자. **숫자만 있는 것은 없다.**
2. **첫 3분 루프의 탭 수가 늘었나?**
   **늘지 않았다.** 스캔→카드→방주→사건 경로는 그대로다. 습격은 2일째부터, 그것도 1/3 확률로만 뜬다.
3. **같은 입력이면 같은 결과인가?**
   판정에 난수 없음(1,000회 1가지), 습격·세기·스탯 전부 시드. 화면이 접촉 전에 보여 준 예상이 실제와 항상 일치.
4. **폰 가로 720px에서 손가락으로 조작 가능한가?**
   390×844 에서 실제로 돌렸다. 탭-탭 배치 성공, 전원 스위치 44px, 패널 「갈 곳 목록」 44px.
   검수 중 발견한 가림 결함 셋(HUD·습격 막대·바텀 시트)을 전부 고쳤다.
5. **회귀 7항목 로그가 있는가?** §5-7 에 전문. 마이그레이션(§5-8), 페이지 코드(§5-9), 배포 모드 404(§5-9)까지.

## 13. 마지막 질문 — 이 산출물이 게임을 더 재미있게 했는가

**그렇다.** 그 전까지 `/base` 는 보기만 하는 화면이었고, PLAYER_JOURNEY §1 의 G1(분 단위 할 일 없음)이 그대로 열려 있었다.
이제 같은 화면에서 **손가락이 할 일**이 생겼고, 그 일이 "공격 버튼 누르기"가 아니라 **불을 끄고, 모이고, 들이고, 옮기는 것**이다.
가장 좋은 신호는 검수 중에 나왔다 — 「그 방 정원이 2명이라 떼를 못 막는다」는 상황에서 공방을 짓고 그물을 만들어 붙이는 길이 **설계하지 않았는데도 자연스럽게 열렸다.** 규칙이 적고 곱이 많다는 증거다(D1).

경계할 것 하나: 습격이 **32.6%**라는 숫자가 "조용한 날이 더 많다"는 §6-1과 맞는지는 실사용 측정 전까지 가설이다. 재미있다고 빈도를 올리고 싶어지는 순간이 이 게임이 아늑함을 잃는 순간이다.

## 14. 작업 중 도착한 것에 대한 대응 (스프린트 말미)

병렬로 돌던 두 에이전트의 산출물이 작업 끝 무렵에 도착해서, **읽는 쪽만 바꿔** 받아들였다.

### 14-1. 시나리오 `data/creatures.json` — 받았다
요청했던 `creatures_deep.json` 대신 **`creatures.json` 한 파일이 명단의 정본**이라는 회신이 왔다.
`server.py` `_CRE_FILES = ("creatures.json", "creatures_deep.json")` 로 바꿔 **새 이름을 먼저 읽는다**(옛 이름은 폴백).
다섯 생물의 `sound`·`silhouette`·`contact`·`how`·`lines` 가 그대로 화면에 올라왔다.

```
swarm    | 작은 떼   | 물이 잘게 끓는 소리가 번진다. 아직 어느 쪽인지 모른다.
longneck | 긴목      | 두드리는 소리. 똑, 똑. 박자가 고르다.
warden   | 문지기    | 들리던 소리가 전부 사라진다. 물이 조용해지면 온 것이다.
claws    | 손톱 무리 | 소리가 없다. 바닥 잡음이 천천히 빠져나간다.
octopus  | 동거 문어 | 에어락 쪽에서 작은 물소리. 같은 소리가 하루에 한 번 난다.

긴목 held     → "어둠 속에서 한참을 기다리다 갔다. 유리에 김이 서렸다 사라졌다."
긴목 scarred  → "유리에 긴 자국이 남았다. 닦아도 지워지지 않는다."
작은 떼 breached → "이음매가 먼저 열렸다. 방 하나가 물로 찼다."
마크다운·치환 잔재 검사: []   (플레이어가 보는 문장 전수)
```
개발 초안보다 확실히 낫다. **내 초안 문장은 이제 한 줄도 화면에 나오지 않는다**(파일이 이긴다).
새로 들어온 **거울눈·곧은치**는 전투 규칙(관문·`need`)이 아직 없어 **조용히 건너뛴다** — 이름만 있는 생물이 습격으로 뜨면 플레이어가 막을 길이 없기 때문이다. 관문 한 줄만 정해지면 `CREATURES` 에 한 항목 추가로 붙는다(요청함에 남겼다).

### 14-2. 기획·밸런스 `data/balance/defense.json` — 읽었고, 다음 스프린트
새로 생긴 relic-design 에이전트가 **「관문을 +3.0 점수로 주면 관문만 넘기면 무조건 막는다」**를 지적했다. 타당하다.
이번 스프린트는 구조를 세우는 것이 목표라 상수를 코드에 두었지만, 바꿀 자리는 **함수 하나(`combat.evaluate`)와 표 둘**뿐이고 **판정에 난수가 없어서 값만 갈아 끼우면 회귀가 즉시 보인다.** 다음 스프린트에 `defense.json`·`threats.json` 을 읽어 상수를 대체하겠다 — 정해 달라고 요청한 두 가지는 요청함에 적었다(관문 실패 시 상한, 세기의 정본).

### 14-3. 그 밖
- 캐릭터가 **체형 B(`*_b.png`)** 시트를 추가하는 중이다(`RESIDENT_STATS` §6). 지금 `SHEETS.p2` 는 `<role>.png` 한 벌만 읽는다 — 체형 선택이 확정되면 역할 뒤에 `_b` 를 붙이는 한 줄이면 된다.
