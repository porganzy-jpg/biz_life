# 개발 보고 — S10-E 심해 거점 화면에 빠진 조작 넷 (2026-10-03)

담당: 개발(화면). 고친 파일은 `static/base.js`·`static/base.css`·`static/base.html` 셋뿐이다. `server.py`·`engine/`은 건드리지 않았다(동시 작업 중인 서버 담당과 충돌 없음).
서버 담당이 넣은 해구 문턱 **180 m** 줄(`base.js` 26~32행)은 그대로 두었다.

### 서버 행동 id에 대해
PM 브리프의 `lure_elsewhere`·`stand_still` 은 서버에 버튼 행동으로 없다. 서버 정본은 `light_elsewhere`(거울눈)이고, `stand_still`(덮개)은 **하지 않는 것**이라 버튼이 없다(`/api/ark/act` 주석). 화면은 서버가 주는 `raid.action` 하나만 그리고, 덮개는 반전 줄로 다룬다. 행동 id를 화면에 하드코딩하지 않았다(효과음 대응표만 있다).

## 2. 가로 전환 대비(PM 예고 반영)
- 로직과 배치를 나눴다. 선반은 **방 사각형(`rectOf`) 기준 상대 좌표**로만 그리고, 카메라 이동은 `flyToSlot(slot)` 한 곳이다. 방 배치가 가로로 바뀌어도 `rectOf`만 바뀌면 그대로 맞는다.
- 패널 내용 생성(`shelfSection`·`upgradeSection`·`lightButton`·`renderGate`)과 API 호출(`doAct`·`handleCode`·`openAccount`)을 함수로 분리. 찍기 화면은 가운데 오버레이, 버튼들은 가장자리에 붙는 독립 요소다.
- 세로 전용 좌표는 새로 넣지 않았다. 폰에서 찍기 버튼을 옮긴 것도 CSS 가장자리 고정(`right/bottom`)뿐이다.

## 4. 교본 적용
- **P1** 원형 「뒤지기·비축」: 찍은 것이 선반에 쌓이고, 빈 칸 점선이 「더 채우고 싶다」를 만든다.
- **P3** 감정의 가속도: 카드 뒷면 → 0.4초 뒤 뒤집기 → 단추가 늦게 뜬다 → 카메라가 창고로 날아가며 칸이 빛난다. 「현실이 들어왔다」를 한 박자씩 늦춰 쌓았다.
- **D2** 숫자는 화면의 무엇으로: 대가를 숫자만 쓰지 않고 「치른 것」 줄로 남기고, 자원 줄이 그 자리에서 줄어든다. 선반 칸 수는 판의 길이로 보인다.
- **D4** 실패는 서사, 막힘은 버그: 할 수 없는 행동은 까닭(`blocked`/`lacking`)을 그대로 보이고 회색으로 둔다. 틀린 열쇠는 404/400/429를 나눠 말한다.
- **D5** 첫 3분 루프: 찍기는 거점 화면 단추 하나 → 숫자 입력 1회 → 「선반에 둔다」 1회. 옛 `/` 화면으로 갈 필요가 없어졌다(탭 수 감소).
- **D6** 결정성: 화면은 계산하지 않고 서버 `raid.action`·`shelf`를 그린다.
- **D8** 44px 터치: 찍기 52px, 행동 버튼 44px, 열쇠 입력·버튼 44px.
- 02_DEV §3 Slay the Spire: 반전 줄은 접촉 **전에**(소리 단계부터) 보인다.
- 07 W2: 스크린샷을 직접 보고 세 번 고쳤다(폰에서 찍기 버튼이 스위치를 가림 → 이동, 토스트가 버튼을 덮음 → 위로, 소품 배율이 물건마다 달라 들쭉날쭉 → 선반 하나에 배율 하나).

**원칙에서 벗어난 곳(이유)**
- PM 브리프는 소품에 `image-rendering: pixelated`를 요구했지만 배경 담당(TASKS S6-B 회신)은 「픽셀아트가 아니라 평면 민속화라 image-rendering을 건드리지 말 것, 고해상도는 x4를 쓸 것」이라고 했다. 그래서 **표시 크기는 원화 34×30의 정수배**(배율은 선반 전체에 하나)로 지키고, 배율이 4 미만이면 x4 원화를 매끄럽게 줄여 쓰고 4 이상이면 1배 원화를 최근접 보간으로 키운다. 결과적으로 뭉개짐 없이 또렷하다. 정본 판단은 PM이 해 달라.
- 폰에서 습격 막대가 화면의 3분의 1을 조금 넘는다(거울눈 + 불 꺼짐 + 행동 칸에서 378/844 = 45%, 다시 켜면 336 = 40%). 행동이 있으면 서술 줄·막는 법·관문 까닭을 접어 416 → 336까지 줄였다. 남은 것은 대가·반전·버튼이라 더 접으면 「대가를 보여 준다」는 완료 기준을 깬다. 가로 전환 때 막대를 옆 가장자리로 옮기면 풀린다.

## 5. 자가 검수 (02_DEV §5)
1. **새 숫자가 화면의 무엇으로 보이나?** 선반 칸 = 판 위 점선 칸, 대가 = 「치른 것」 줄과 줄어든 자원, 덮개 이동 횟수 = 붉은 반전 줄.
2. **첫 3분 루프의 탭 수가 늘었나?** 줄었다. 찍기가 거점 화면에 들어와 화면을 오가는 일이 없어졌다(찍기 1 + 입력/촬영 + 「선반에 둔다」 1).
3. **같은 입력이면 같은 결과인가?** 화면은 계산하지 않는다. 선반 칸·행동 가능 여부·대가는 전부 서버 값.
4. **폰에서 손가락으로 되나?** 390×844 실측: 찍기·열쇠·행동·「다시 켠다」·탭-탭 전부 탭으로 통과. 폰에서 찍기가 스위치 줄을 가리던 결함을 찾아 고쳤다.
5. **회귀 로그가 있나?** 드래그·탭-탭·습격 진행·불·전원 토글은 위 시나리오에 들어 있다. 사건(`/` 화면)·도감·시뮬·마이그레이션은 서버 쪽이고 이번에 건드린 파일과 무관해 돌리지 않았다.

## 6. 미완·리스크
- 카메라 실촬영(BarcodeDetector)은 Playwright에 카메라가 없어 **숫자 입력 경로로만** 검증했다. 촬영 코드는 `app.js`에서 그대로 옮겼다. 실기기 HTTPS(`--https`, 8444) 확인이 필요하다.
- 예시 바코드 단추는 `127.0.0.1`·`localhost`·`?samples`에서만 보인다(진짜 물건을 찍는 것이 이 게임의 훅이라).
- 서버 `return_it`은 손패 첫 장을 내려보내는데 선반에서도 그 물건이 빠진다(`shelf_remove_card`). 「도감의 그 칸은 비어 있는 채로」와 선반이 함께 비는 것은 맞는 연출이지만, 「가장 깊은 데서 온 것」이 아니라 손패 첫 장이라는 점은 서버 쪽 판단이다.
- 선반이 Lv2(12칸)가 되면 한 줄 6칸 × 2줄인데, 폭 2 소품이 줄 끝 칸(5·11)에 놓이면 판 밖으로 반 칸 삐져나간다(서버가 줄을 모르고 칸만 세기 때문). 칸 배정에 줄 경계를 넣을지 서버와 정해야 한다.
- 데스크톱에서 습격 막대가 길어지면 그 아래에 열리는 방 패널이 낮아진다(기존 `placePanel` 동작). 가로 전환 때 같이 정리한다.

## 7. 요청
- [개발(화면)→개발(서버)] 선반 Lv2 이상에서 폭 2 소품이 줄 경계(`slot % 6 == 5`)를 넘지 않게 `shelf_place`에서 막아 주거나, `shelf_room`에 `per_row`를 내려 주면 화면이 그 값을 쓴다.
- [개발(화면)→PM] 소품 렌더 규약(정수배 크기 + x4 축소) 승인 여부. `pixelated`를 고집하면 한 줄만 바꾸면 된다.
- [개발(화면)→PM] 실기기 HTTPS에서 카메라 촬영 확인 한 번.
