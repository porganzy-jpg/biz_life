## 1. 무엇을 만들었나

Quaternius Ultimate Animated Character Pack(CC0, 공용 골격 `CharacterArmature`, 액션 17종)을 베이스로
8역할을 **하나의 파이프라인**으로 정식화했다. 역할마다 (a) 베이스 .blend 선택, (b) 원시 도형 소품을
**아마추어 뼈에 본 페어런팅**(애니메이션을 그대로 따라감), (c) 성경의 적응 묘사(창백한 피부·크고 어두운 눈),
(d) `data/roles.json`의 body/accent 색을 옷 재질에 입히는 순서로 빌드한다.

한 스크립트로 GLB와 스프라이트를 모두 만든다:

```
blender -b --python tools/blender_chars_v2.py -- all           # 8역할 GLB + 스프라이트
blender -b --python tools/blender_chars_v2.py -- glb medic     # 일부만
blender -b --python tools/blender_chars_v2.py -- sprites
```

### 1-2. 성경 반영 (`docs/LORE_v2 §3`, `WORLD_BIBLE_v2 §2`)
- **창백한 피부** `#efd9c8` — 원본 Skin 재질이 검정(0.013)으로 저장되어 있어 전 역할 강제 교체. 얼굴은 한 톤 더 밝은 `#f6e6d8`.
- **크고 어두운 눈동자** — 머리 앞에 흰자(`#f4eee4`) + 동공(`#17120f`) 구체 2쌍, `Head` 뼈에 본 페어런팅해 모든 액션에서 얼굴을 따라간다. 베이스마다 앞머리 길이가 달라 `eye_y`로 역할별 보정(−0.48 ~ −0.60).
- **부족 표식** — 의무병에 하얀 부족의 마스크(턱에 걸친), 기술자에 불꽃 부족의 시안 배터리팩("빛은 빚이다"), 정찰병에 탑 부족의 쌍안경, 농부에 온실 부족의 넓은 챙·베일형 모자를 넣었다.

### 1-3. 본 페어런팅 방식(핵심 기법)
`attach(obj, arm, bone, world)` — `parent_type='BONE'`으로 붙인 뒤 **지금 포즈에서의 목표 월드 트랜스폼**을 주면
`matrix_basis = (arm.matrix_world @ pose_bone.matrix @ T(0, bone.length, 0))⁻¹ @ world` 로 로컬을 역산한다.
덕분에 소품 좌표를 리그 원본 좌표계(머리 뼈 z=2.117, 얼굴 앞 y≈−0.53 등)에서 직관적으로 찍을 수 있고,
Idle/Walk/PickUp 어느 액션에서도 소품이 손·머리를 따라간다.

**정규화 규약** — 모든 역할을 같은 배율(`1.6 / 3.078`, 아이는 `1.2 / 3.078`)로 줄인다.
3.078은 모자·머리카락이 없는 리그 원본 키다. 즉 **맨머리 기준 키가 정확히 1.6m(아이 1.2m)** 이고,
요리사 모자·농부 밀짚모자·정찰병 헬멧은 그 위로 더 올라간다(사람 키는 같고 모자만 높다 = 의도한 결과).
발 원점은 **몸 메시 최저점**으로 잡아 소품(렌치 끝 등)이 조금 아래로 내려가도 발이 z=0을 유지한다.

검증(내보낸 GLB를 다시 임포트 → Idle 액션 할당 → 이밸류에이트한 정점 실측):
```
cook.glb     body z 0.000..1.973 | clips 7
engineer.glb body z 0.000..1.663 | clips 7
farmer.glb   body z 0.000..1.803 | clips 7
kid.glb      body z 0.000..1.207 | clips 7
medic.glb    body z 0.000..1.622 | clips 7
scholar.glb  body z 0.000..1.601 | clips 7
scout.glb    body z 0.000..1.681 | clips 7
trader.glb   body z 0.000..1.663 | clips 7
```
소품은 스킨 메시가 아니라 **조인트 노드의 자식 노드**로 나간다(역할당 10~17개). Three.js `GLTFLoader`는 그대로 따라간다.
Y-up 내보내기이므로 Blender −Y(원본 정면)가 glTF **+Z** = Three.js 기준 정면이다.

### 2-2. 스프라이트 — `static/art/chars/<role>_dl_b.png`, `<role>_ul_b.png`
역할당 4장 — `<role>_{dl,ul}_{a,b}.png`. 256px 투명 PNG, 아이소 카메라(방위 45°·고도 32°·직교 2.2), Freestyle 외곽선 `#1a1714`.
프레임 규약은 기존 치비와 동일: **b = 모음(Idle 첫 프레임), a = 다리 벌림(Walk 25% 지점)** — `static/life.js`가 걷는 동안 a/b를 번갈아 쓴다.
**기존 파일명을 그대로 덮어썼으므로 현재 클라이언트(`static/app.js`)는 수정 없이 새 그림을 쓴다.**
방위는 기존 치비와 동일: `dl` = 정면 왼쪽(원본 −Y에서 **−90°**), `ul` = 뒷모습(**180°**).
> 지시서에는 ul을 +90°로 적어 두었으나, +90°는 오른쪽 뒷모습(ur)이 되어 기존 치비의 ul(정면 +Y)과 어긋난다.
> 클라이언트가 좌우 반전으로 오른쪽 방향을 만들고 있어 **기존 규약(180°)을 따랐다.**

`static/art/chars/chars_meta.json`(발 픽셀 위치)도 같이 갱신된다 — v2 카메라 기준 `foot [128.0, 206.9] · res 256 · ortho 2.2 · h`(역할 키).
참고용 사본은 `art_raw/chars_v2/`에도 저장된다.

## 3. 자가 평가 — 3초 안에 8역할이 구분되는가

Playwright로 페이지를 열어 스크린샷을 직접 보고 3회에 걸쳐 고쳤다.

| 회차 | 문제 | 조치 |
|---|---|---|
| 1 | AgX 뷰 트랜스폼이 채도를 죽여 8명이 전부 회색으로 보임 | 렌더 뷰 트랜스폼 **Standard**, 노출 0, 월드 밝기 0.8→0.45, 조명 완화 |
| 2 | 정찰병 배낭이 몸과 같은 색이라 뭉개짐 / 기술자가 어두운 덩어리 / 요리사가 온통 흰색 | 배낭을 어두운 강조색 + 멜빵만 몸색, 기술자에 밝은 금속 렌치·등 배터리팩 추가, 요리사 속옷을 주황으로 |
| 3 | 의무병이 갈색 덩어리(머리카락이 면적의 56%) / 십자가 작음 / 기술자 하의가 배경과 붙음 | 머리카락을 따뜻한 갈색 `#6b4a33`, **앞·뒤 양쪽 붉은 십자**로 확대, 기술자 하의 `#5a554b`로 밝힘 |

최종 판정: **통과.** 정면·뒷모습 모두 한눈에 갈린다.
- 정찰병 = 초록 + **큰 등짐** / 요리사 = **높은 흰 모자** + 냄비 / 의무병 = **붉은 십자**(앞뒤) + 녹색 가방
- 기술자 = **시안 고글·배터리** + 밝은 렌치 / 농부 = **가장 넓은 밀짚모자** + 물뿌리개
- 학자 = 보라 + **가슴의 노란 책** / 교섭가 = **검은 중절모 + 붉은 목도리** / 아이 = **혼자 작다** + 노란 후드

남은 약점(치명적이지 않음):
- 기술자의 렌치는 256px에서 작다. 손 위치가 허벅지 옆이라 다리와 겹친다.
- 정찰병·기술자는 둘 다 어두운 계열이라 실루엣만으로는 배낭 유무에 의존한다.
- 머리카락 면적이 큰 베이스(의무병 56%, 학자 54%)는 색 하나가 인상을 지배한다.

## 4. 미완·리스크

1. **걷기 사이클이 2프레임뿐.** a(Walk 25%)·b(Idle)만 있어 이동이 다소 뻣뻣하다. 4프레임으로 늘리려면 `FRAMES` 상수에 두 줄 추가하면 되지만, 클라이언트(`static/life.js`)가 a/b 2프레임만 쓰고 있어 함께 바꿔야 한다.
2. **방향 2종만.** dl·ul만 있고 오른쪽 방향은 클라이언트 CSS 좌우 반전에 의존한다(기존 규약 유지). 소품이 왼쪽/오른쪽 손에 따로 붙어 있어 반전 시 냄비·렌치가 반대 손으로 보인다 — 3D 전환 시 자연히 해소된다.
3. **구 GLB 3종 잔존.** `BlueSoldier_Male.glb` / `Chef_Male.glb` / `Doctor_Female_Young.glb`는 `static/poc3d.html`이 직접 로드하고 있어 **지우지 않았다.** 개발이 역할 GLB로 바꾼 뒤 삭제하면 된다.
4. **얼굴 디테일 없음.** 입·눈썹이 없다. 큰 눈만으로 감정이 안 나오므로, 대화·명단에는 별도 초상(E행, 아직 비어 있음)이 필요하다.
5. **용량.** 역할당 519~675 KB, 8종 합계 약 4.6 MB. 8명이 동시에 등장하면 모바일에서 부담. 클립을 Idle/Walk/PickUp 3종으로 줄이면 절반 이하로 떨어진다(`KEEP_ACTIONS` 한 줄 수정). 더 줄이려면 Draco/메시 병합이 필요한데 Blender 내보내기 옵션만으로 가능하다.
6. **소품이 별도 노드**라 드로우콜이 역할당 11~18개다. 방주에 주민 10명이면 150콜 수준. 필요하면 소품을 몸 메시에 조인(스킨 웨이트 전이)하는 후처리가 필요하다 — 지금은 가독성을 우선했다.

## 5. 남에게 요청할 것

**개발 에이전트에게 (`docs/TASKS.md` 요청함에도 등록)**
1. `static/poc3d.html`(및 본 화면 승격 시 `static/app.js`)에서 캐릭터 GLB를 **역할별 파일**로 로드해 주세요:
   `/static/models/chars/${role}.glb` (role ∈ scout·cook·medic·engineer·farmer·scholar·trader·kid).
   클립 이름은 소문자 매칭 그대로 `idle / walk / run / pickup / sitdown / standup / death` 입니다.
2. **높이 재정규화는 하지 말아 주세요.** GLB가 이미 발 원점·맨머리 1.6m(아이 1.2m)로 정규화되어 있습니다.
   현재 `poc3d.html`은 바운딩박스로 1.6m에 다시 맞추는데, 그러면 **요리사 모자·농부 밀짚모자까지 1.6m 안에 우겨넣어 사람이 작아집니다.**
   `root.scale`을 건드리지 말고 그대로 배치하면 8역할의 키 비교가 맞습니다.
3. 주민 이동 방향은 모델 정면이 **+Z**입니다. `object.lookAt(target)`으로 바로 맞습니다.
4. 역할별 "일하는 모션"은 `pickup`(요리사 냄비·농부 물뿌리개·기술자 렌치가 손에 붙어 함께 움직입니다)과
   `sitdown`/`standup`(휴식·식사 연출)을 쓰시면 됩니다.

- 구 GLB 3종 삭제 시점은 개발이 역할 GLB로 전환한 뒤로 잡아 주세요.
