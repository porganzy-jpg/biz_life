## 5. 버그 (재현)
1. **창고 상자로 간 스캔은 「어디로」로 줄 수 없다**: 선반이 꽉 찬 상태에서 찍기 → 응답 `where.suggest` 의 매듭 제안 → `POST /api/give {scan_id, target:{resident_id}}` → 400 「그 물건을 찾을 수 없습니다」(A 4일째 저녁, 진라면 → 새벽). 1~3일째에는 같은 상황이 통과한 적도 있어 조건이 섞여 있다 [추정: 바꾸기 제안(swap_offer)이 같이 온 스캔].
2. **꾸밈 반응의 꼬리표 이름이 틀림**: 「꾸밈: 식량창고(책 냄새 0/2)」를 고르면 「「따뜻한 부엌」 쪽으로…」(A 1일째). 「손때 묻은 작업대」 → 「따뜻한 부엌」(5일째), 「반짝이는 것들」 → 「책 냄새」(6일째). 방에 처음 붙기 시작한 꼬리표 이름을 쓰는 것으로 보인다.
3. **비트 5일째 「누구에게 보여 드릴지 골라 주세요」에 고르는 기능이 없다**: `octopus_tick` 은 선물을 정할 뿐, 고르는 API·`ask` 가 없다(server.py 2521행 근처). 비트 3일째 「주민 한 분이 처음으로 부탁을 하나 하셨습니다」도 그날 열린 ask 가 없을 때 나온다.
4. **반응 문장이 비거나 겹친다**: warm·꾸밈은 `announce` == `line`(같은 문장 두 번). 선반은 `line: null`. 매듭 사건 `announce: null`(A 5일째 요리사 3매듭). 버튼형 물음의 답 뒤 `after_ask_ko: null`(A 6일째).
5. **원칙 위반 대사**: 교섭가 liked_lines 「읽을 수 있는 게 하나 늘었어요. 고마워요.」 — CORE_LOOP_A §8.
6. **찾은 스팟 재방문은 「밤 넘기기」만**: 「위를 보는 숲」을 4일째 반나절에 찾았는데, 다음부터는 `lengths: ["long"]` 이라 에어락이 없으면 다시 못 간다.
7. 도구 쪽(내 실수, 고침): `arc_events` 와 `next.ask` 가 같은 물음을 두 번 보내 내가 step 없이 한 번 더 답해 422가 났다. 7일째 화면 출력은 필터 오타로 잃었고, 세션 기록 파일에서 되살렸다.

## 6. 문제 다섯 (중요도 순)
1. **같은 날 감쇠가 둘째 세션을 죽인다.** 사람이 3~6명이고 같은 날 두 번째부터 ×0.5(같은 물건 사흘이면 ×0.15)라서, 저녁 「어디로」의 절반 이상이 「제안이 다 약함 → 선반」이다(A 2·3·7일째 저녁).
2. **꾸밈 → 방문자 루프가 1주일 안에 한 번도 닫히지 않는다.** 칸 2, 꼬리표마다 물건 2개 필요, 제안이 매번 다른 꼬리표를 권하고, 반응은 꼬리표 이름을 틀린다. A·B 모두 꼬리표 완성 0, 방문자 0.
3. **약속과 화면이 어긋난다.** 비트 3일째(부탁)·5일째(골라 주세요), 「○○ 님이 뭔가 하실 말씀이 있는 눈치입니다」가 2~3일 연속인데 아무 일도 없음, 힌트 「부품·줄·충전선」과 실제 매칭(케이블)이 다름. 다시 올 이유가 신뢰를 잃는다.
4. **반응 문장의 반복과 빈칸.** warm 4종이 7일 내내 돌아가고, 같은 문장이 두 번 찍히고, 답해도 대답이 없다(after_ask null). 이야기가 핵심인 루프에서 문장 품질이 곧 재미다.
5. **주 후반 새것 고갈.** 6·7일째 저녁은 계약의 「새것」·「모르는 결과」가 X. 가정 물건이 다 한 번씩 찍혔고 방문자가 없어서, 남는 것은 아는 물건을 놓는 일뿐이다.
