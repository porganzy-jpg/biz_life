# 개발 S32 화면 — 「다음 할 일」 한 줄 · 첫 찍기 길잡이 (2026-10-17)

사용자가 막힌 곳(「창고에 사람을 둔 다음 뭘 하지?」)과 「찍기 카드도 길잡이로」 요청에 대한 화면 작업이다. 서버 API_S19 §21 과 시나리오 ui_moments(next_step·tutorial)를 쓴다. 확인은 8041 별도 포트에서만 했다(사용자가 8002 에서 플레이 중이라 건드리지 않음, 확인 뒤 8041 껐음). **커밋하지 않음.**

### 「다음 할 일」 한 줄 (next_step)
- 위 줄 바로 아래 왼쪽에 `next_step.line_ko` 한 줄. 폰 가로에서는 오른쪽 버튼 자리를 비우고 한 줄로 두며, 넘치면 말줄임(…).
- 누르면 대상을 부드럽게 빛내고(고리) 화살표를 단다. 4.5초 동안 보인다.
  - scan → 찍기 단추.
  - hall → 자리를 정할 사람. 홀·문간 어디에 서 있든 그 사람을 빛낸다. 처음에는 빈 홀을 빛내서 고쳤다.
  - room → slot 또는 room_id 의 방. 카메라를 먼저 그쪽으로 옮긴다.
  - shelf → 선반, expedition → 내보내기, table → 한 상, menu → ≡. 메뉴 단추가 없으면 ≡ 를 빛낸다.
- 새로 그리기: 모든 응답의 state 에 next_step 이 있어서, 찍기·건네기·자리·짓기 뒤 apply 때마다 다시 그린다. 없는 응답 뒤에는 0.9초 뒤 /api/ark 를 한 번 다시 받는다.
- hint_mode:
  - "always"(켠 날 1~3): 늘 보인다.
  - "idle"(4일째부터, idle_sec 30): 손을 30초 안 대면 스며 나오고, 누르거나 만지면 다시 숨는다.
- 길잡이가 떠 있는 동안은 숨는다(말풍선 하나만).

### 첫 찍기 길잡이 (tutorial)
- 단계 이름은 서버·시나리오와 같다: scan_button → scan_window → card_flip → subtype_pick → where → after_first_give. 문장은 `ui_moments.tutorial.<단계>.lines[]`(시나리오)를 차례로 보이고, 없으면 기본값을 쓴다.
- 말풍선 하나와 대상 빛·화살표. 말풍선은 대상과 겹치지 않는 쪽(위 → 아래 → 옆, 그래도 겹치면 반대 구석)에 두고, 누를 단추는 화살표로 가리킨다(시험에서 겹침 0).
- 단계 끝(화면 상태로 판단) → `POST /api/tutorial {step}` → 다음 단계:
  - scan_button: 찍기 창이 열림.
  - scan_window: 숫자 칸 줄(입력·읽기)을 가리킨다. 카드가 보이면 끝. 처음에는 창 전체를 빛내서 고쳤다.
  - card_flip: [알겠습니다]를 누르거나 6초가 지나면 끝.
  - subtype_pick: 고르기가 끝나면.
  - where: 건네면.
  - after_first_give: [알겠습니다]를 누르면.
- [건너뛰기] = `step:"skip"`. 서버가 남은 걸음을 모두 끝낸다(done:true 확인).
- 찍기 창을 닫아 버리면 빛을 찍기 단추로 되돌린다. 단계는 서버가 정한다.
- **PM 지적 반영(말풍선과 방송이 동시에 뜸)**: 길잡이 단계가 떠 있는 동안 관리실 방송(say)과 미룬 방송을 모두 줄에 세워 두고, 길잡이가 끝나면 0.6초 뒤부터 차례로 흘린다. 첫 걸음을 「사람 두기」에 양보하는 쪽 대신 이쪽(줄 세우기)을 골랐다. 첫 화면의 이야기가 「찍기」에서 시작해야 해서다(D5).

## 3. 교본
- D5(첫 3분 루프): 길잡이가 찍기 → 카드 → 이름 → 어디로 → 건네기를 그대로 따라가고, 새 탭은 늘지 않는다(말풍선은 눌러도 되고 안 눌러도 된다). 화면에 말할 곳은 늘 하나다.
- D3·D4: 막힌 사람에게 다음 한 걸음을 한 줄로 보여 준다. 4일째부터는 손이 멈췄을 때만 나와서 방해하지 않는다.
- D7: 문장은 ui_moments, 걸음·대상은 서버 next_step·tutorial 에서 읽는다.
