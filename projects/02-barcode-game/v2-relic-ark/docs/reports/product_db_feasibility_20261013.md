# 질랜디아: 바코드로 제품명·종류 조회 타당성 조사

조사일: 2026-10-13. 저장소는 고치지 않았다. 인증키는 쓰지도 적지도 않았다.
API는 두 번만 실제로 불렀다. 식품안전나라는 사이트가 공개한 `sample` 경로로 I2570을 1회, Open Food Facts는 바코드 8801007112480 하나로 1회다. 그 밖에 OFF 검색 서비스에서 건수만 세는 질의를 몇 번 했다.

## 0. 결론 먼저

**추천 조합은 아래 넷이다.**
1. 식약처 「유통바코드」(식품안전나라 I2570)를 한 번 통째로 받아 서버에 내장한다.
2. 책은 지금처럼 접두 978/979로 판정한다. 필요하면 국립중앙도서관 ISBN API의 KDC 분류로 하위 종류까지 제안한다.
3. 나머지는 지금의 「이게 뭐예요?」 플레이어 선택으로 처리한다.
4. 조회 결과는 정답 확정이 아니라 **제안(preselect)** 으로만 쓴다.

- 근거 1: I2570은 무료다. 대·중·소 품목분류가 붙어 있어 하위 종류로 바꾸기 쉽다.
- 근거 2: 2018년 이후 갱신이 멈췄다. 그래서 한 번 받아 두면 끝이고, 호출 한도나 개인정보 문제도 사라진다.
- 단점: 2019년 이후 나온 신제품과 비식품은 비어 있다. 그래서 플레이어 선택이 계속 필요하다.
- 구현 비용 추정: 약 2~3인일. 키 발급 대기는 별도다.

## 1. 후보별 확인 결과

### 1-1. 공공데이터포털: 식품의약품안전처_유통바코드
- URL: https://www.data.go.kr/data/15064775/openapi.do
- 데이터셋 번호: 요청에 적힌 15063677은 「식품의약품안전처_검사부적합(국내)」 데이터셋이다. 이 데이터에도 바코드번호와 제품명이 있지만 부적합 제품만 담겨 있어 쓸모가 없다(https://www.data.go.kr/data/15063677/openapi.do). 유통바코드의 실제 번호는 **15064775** 다.
- 유형: API 유형이 "LINK"로, 실제 호출은 식품안전나라(I2570)로 연결된다. 형식은 JSON+XML이다.
- 제공 항목: 바코드번호, 품목보고번호, 회사명, 제품명, 최종수정일시, 품목분류 대·중·소분류.
- 이용허락범위: **"이용허락범위 제한 없음"**. 비용은 무료다.
- 갱신주기: 포털에는 "실시간"으로 적혀 있다. 그러나 설명에는 **2018년 이후 최신화 중단**이라고 되어 있어 서로 맞지 않는다.
- 건수: **미확인**. 포털에 적혀 있지 않고, sample 키로는 total_count가 5로 잘려 나온다.
- 활용신청 7,887건, 등록 2020-09-15, 최종 수정 2025-08-27.
- 원 데이터: 대한상공회의소 유통물류진흥원이 **유료로 공급**하던 것이다. 진흥원의 요청으로 2018년 이후 갱신이 끊겼다.

### 1-2. 식품안전나라 OpenAPI
URL 형식은 `http://openapi.foodsafetykorea.go.kr/api/{keyId}/{serviceId}/{xml|json}/{startIdx}/{endIdx}[/변수=값]` 이다.

**I2570 「유통바코드」 (주력 후보)**
- 안내 페이지: https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=I2570
- 요청 변수: `BRCD_NO`(바코드), `PRDT_NM`(제품명), `PRDLST_REPORT_NO`, `CHNG_DT`.
- 응답 필드: `BRCD_NO`, `PRDLST_REPORT_NO`, `CMPNY_NM`(회사명), `PRDT_NM`(제품명), `LAST_UPDT_DTM`, `PRDLST_NM`(소분류), `HRNK_PRDLST_NM`(중분류), `HTRK_PRDLST_NM`(대분류).
- 2015-01 개설, 2020-07 최종 수정. 비고: 유통물류진흥원 데이터라 2018년 이후 갱신이 중단됐다.
- sample 호출 실제 응답:
  ```json
  {"BRCD_NO":"8809360172547","PRDT_NM":"황금빛하늘내린황태포5미370g","CMPNY_NM":"용대황태연합단대륭영농조합법인",
   "HTRK_PRDLST_NM":"가공식품","HRNK_PRDLST_NM":"건포류","PRDLST_NM":"건어포","LAST_UPDT_DTM":"2015-01-22 11:12:12.0"}
  ```
  분류 계층이 실제로 채워져 온다. 제품명에는 용량("370g")이 붙어 있다.

**C005 「바코드연계제품정보」 (보조 후보)**
- 안내 페이지: https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=C005
- 응답 필드: `BAR_CD`, `PRDLST_NM`(제품명), `PRDLST_DCNM`(식품유형), `BSSH_NM`(제조사), `POG_DAYCNT`, `END_DT`(생산중단일) 등.
- 이 서비스도 2018년 이후 갱신이 중단됐다(같은 이유).
- I2570에는 없지만 C005에는 있는 정보가 식품유형(`PRDLST_DCNM`)이다. 예: 커피, 과·채주스, 우유류.

**두 서비스 공통 호출 제한** (안내 페이지 기준)
- 한 번 요청에 최대 1,000건.
- CHNG_DT 없이 부르면 시간당 100회.
- 06~19시에는 키·서비스당 300회.
- 파일 다운로드는 키당 하루 10회.

**키와 라이선스**
- 식품안전나라 회원 가입 후 인증키를 신청한다. sample 키는 5건으로 제한된다.
- 라이선스는 data.go.kr 표기로 "이용허락범위 제한 없음"이다. 상업 이용은 허용으로 판단한다.
- 식품안전나라 사이트 자체의 저작권 정책 원문은 **미확인**이다.

### 1-3. 코리안넷 / GS1 Korea (대한상공회의소 유통물류진흥원)
- URL: https://www.koreannet.or.kr/front/koreannet/dbApply.do (「바코드 DB활용」)
- 방식: **제휴 계약 후 바코드 조회 API**를 준다. 데이터 형태는 협의로 정한다.
- 제공 항목: 바코드, 상품분류, 상품명, 단축상품명, 브랜드, 규격·용량, 중량, 가로·세로·높이, 이미지, 제조사. 경우에 따라 일부만 준다.
- 심사 기준: 사업 건전성, 활용 목적, 사업·서비스 모델.
- 계약: **최소 12개월 단위**다. 초기 연계비와 월 이용료가 협의 항목이다. 금액은 **미확인**이고, 공개 가격표가 없다.
- 회원 자격 요건은 명시되어 있지 않다. 게임이나 앱 용도의 별도 조항은 **미확인**이다.
- 활용 사례: 네이버 쇼핑렌즈, 공정위 소비자24.
- 문의처: 데이터정보팀 02-6050-1483.
- 평가: 커버리지는 비식품까지 포함해 가장 넓을 것이다. 그러나 개인이 만드는 코지 게임에는 비용과 심사, 12개월 약정이 과하다. 정식 출시와 수익화 뒤에 다시 검토한다.

### 1-4. Open Food Facts
- API 문서: https://openfoodfacts.github.io/openfoodfacts-server/api/
- **880 접두 상품 수: 6,457건.** search.openfoodfacts.org에서 `code:880*` 로 센 정확한 건수다(2026-10-13).
- `countries_tags=en:south-korea` 로 세면 약 1,5xx건이다.
- 샘플 1건(8801007112480, 비비고 두부)은 찾았다. 그러나 이름이 영어("CJ Tasty Soy Tofu For Soup (soft)")였고, 판매국은 프랑스였다.
  - 한국 제품은 수출용 영어 이름으로 등록된 경우가 많은 것으로 보인다.
  - 이 샘플은 `categories_tags` 가 꽤 자세했다(…, xx:tofu).
- 호출 제한: 상품 조회 **분당 15회/IP**, 검색 **분당 10회/IP**. 넘기면 IP가 차단될 수 있다.
  - User-Agent는 `앱이름/버전 (연락처)` 형식이 필수다.
  - 수백 건이 넘으면 API 대신 덤프(CSV/JSONL)를 쓰라고 권한다.
- 라이선스
  - DB: ODbL 1.0. 개별 내용: DbCL 1.0. 이미지: CC BY-SA 3.0.
  - 게임은 "Produced Work"이므로 출처 표시만 하면 된다.
  - 880만 추려 **파생 DB를 공개적으로 쓰거나 배포하면** 그 파생 DB에 ODbL(share-alike)이 적용되고, 요청이 오면 제공할 의무가 생긴다.
  - 이미지는 쓰지 않는 것을 권한다.
- 평가: 한국 가정 스캔 커버리지는 낮다(추정 식품의 5~15%). 보조 수단으로만 쓴다.

### 1-5. 그 밖의 후보
**책: 국립중앙도서관 ISBN 서지정보 API**
- 안내: https://www.nl.go.kr/NL/contents/N31101030500.do
- 요청 URL: `https://www.nl.go.kr/seoji/SearchApi.do?cert_key=…&result_style=json&page_no=1&page_size=1&isbn=…`
- 응답 필드: `TITLE`, `PUBLISHER`, `AUTHOR`, `SUBJECT`(주제), `KDC`(한국십진분류), `EA_ADD_CODE`(ISBN 부가기호) 등 40개.
- 키: 도서관 회원 가입 → 인증키 신청 → 담당자 승인(https://www.nl.go.kr/NL/contents/N31101010000.do).
- 호출 한도와 상업 이용 조건은 **미확인**이다. 문의처: 디지털정보기획과 02-590-0548.
- 참고: 978/979 접두만으로도 "책"은 오프라인에서 100% 판정된다. 게임은 이미 이렇게 하고 있다. API는 하위 종류(요리책, 도감, 지도, 이야기책)를 제안할 때만 의미가 있다.
- 키 없이도 쓸 수 있는 부분: ISBN 부가기호 5자리 중 3번째 자리가 내용분류다(0 총류 … 8 문학, 9 역사). 이것으로 간이 제안이 가능하다. 다만 부가기호는 바코드 본체가 아니라 옆의 작은 애드온 바코드에 있어서, 스캐너가 읽지 못할 수 있다.

**의약품: 식약처 의약품 제품 허가정보 API**
- URL: https://www.data.go.kr/data/15095677/openapi.do
- 이용허락범위 제한 없음, 개발계정 10,000회.
- 응답에 **바코드나 표준코드 필드가 있는지 미확인**이다(포털 페이지에 명세가 없다).
- 의약품 표준코드(880으로 시작하는 13자리)를 품목으로 바꿔 주는 무료 공개 파일·API를 이번 조사에서 확인하지 못했다(**미확인**). 후보는 심평원 의약품관리종합정보센터(KPIS)의 KD코드다.

**생활용품, 화장품, 문구, 전자(건전지)**
- 무료 공개 바코드 DB를 찾지 못했다.
- Open Beauty Facts와 Open Products Facts에도 한국 제품은 거의 없다(추정).
- 사실상 코리안넷만 커버한다.

추정 근거
- 무료 조합(I2570 + 978/979 접두 + 선택적 ISBN API)으로 **스캔의 약 40~50%** 에 "제안"을 붙일 수 있다.
- 나머지 절반은 지금처럼 플레이어가 고른다.
- 게임에 이미 있는 "알려진 가문 18곳(GS1 업체코드 7자리)" 매핑과 전역 투표(`subtype_votes`)가 빈 곳을 일부 메운다.
- 위 수치는 모두 추정이며 실측하지 않았다.

### 2-2. 하위 종류 매핑 (I2570 분류 → 게임 `_subtypes`)
- I2570의 중·소분류는 식품공전 품목명이다. 예: 커피, 과·채주스, 우유류, 면류.
- 게임의 하위 종류는 `data/relic_templates.json` 의 `_subtypes` 다. food에는 noodle, snack, sweet, canned, grain, sauce가 있고, drink에는 water, soda, coffee, tea, milk, juice, alcohol이 있다.
- 매핑표는 키워드 규칙으로 60~100줄 정도면 된다.

| I2570 중·소분류 키워드(예) | 게임 갈래 / 하위 종류 |
|---|---|
| 면류, 국수, 라면, 당면 | food / noodle |
| 과자, 스낵, 빵류, 떡류 | food / snack |
| 사탕, 초콜릿, 캔디, 잼, 당류 | food / sweet |
| 통조림, 절임, 김치, 젓갈 | food / canned |
| 곡류, 즉석밥, 시리얼 | food / grain |
| 장류, 소스, 조미료, 식용유지, 식초 | food / sauce |
| 먹는샘물, 혼합음료(물) | drink / water |
| 탄산음료 | drink / soda |
| 커피, 액상커피 | drink / coffee |
| 다류, 침출차, 고형차 | drink / tea |
| 우유류, 가공유, 발효유, 두유 | drink / milk |
| 과·채주스, 과·채음료 | drink / juice |
| 주류(있다면) | drink / alcohol (가문 전용 규칙은 지켜야 함) |
| 건강기능식품 | medical / tonic |
| 그 밖(건포류, 수산가공품 등) | food / 갈래만 제안하고 하위 종류는 플레이어가 선택 |

- 매핑 실패율을 줄이려면 C005의 `PRDLST_DCNM`(식품유형)을 함께 쓴다. 다만 C005도 2018년 동결이라 커버리지는 비슷하다(추정).
- 책(KDC): 590 가정·요리 → manual, 400 자연과학 → field_guide, 980 지리·지도 → map, 800 문학 → story, 0xx 총류 → index, 사전·장부류 → ledger.
- **전자(battery)와 의류(socks)는 무료 DB로 매핑할 길이 없다.** 이 둘은 플레이어 선택이나 가문 매핑에 맡긴다.

### 2-3. 비용과 위험
| 항목 | I2570 / C005 | OFF | ISBN API | 코리안넷 |
|---|---|---|---|---|
| 비용 | 무료 | 무료 | 무료 | 유료(초기비 + 월이용료, 금액 미확인), 12개월 약정 |
| 라이선스 | 이용허락범위 제한 없음 | ODbL(출처 표시, 파생 DB share-alike) | 미확인 | 계약 조건 |
| 호출 한도 | 시간당 100회 / 주간 300회 → **내장하면 무관** | 분당 15회/IP → 서버 경유와 캐시 필수 | 미확인 | 계약 |
| 신선도 | 2018년 동결(신제품 누락). 대신 한 번 받으면 끝 | 계속 갱신(한국은 드묾) | 계속 갱신 | 계속 갱신 |
| 개인정보 | 내장하면 외부로 나가는 것 없음 | 서버 경유 시 바코드만 나감(사용자 IP 노출 없음) | 서버 경유 시 ISBN만 | 서버 경유 |
| 오프라인 캐시 | 전체 내장 가능(크기 미확인, 수십 MB 이하로 추정) | 880 덤프 6.4천 건 내장 가능(ODbL 의무 동반) | 조회 결과 캐시 | 계약 확인 필요 |

- 클라이언트(브라우저)가 외부 API를 직접 부르지 않게 한다. 반드시 게임 서버가 대신 조회하고 바코드별로 캐시한다. 이렇게 하면 사용자 IP와 키가 노출되지 않는다.
- 제품명은 실제 상표명이다. 게임 유물 이름(템플릿 생성)을 대체하지 말고, "아마 ○○ 같아요" 같은 제안 문구에만 쓴다. 상표가 게임 화면에 크게 노출되는 것을 피하기 위해서다.
- DB 오답 위험: 2018년 이전 데이터에는 바코드가 재사용됐거나 단종된 제품이 있다. 그래서 확정하지 않고 제안만 한다. 플레이어가 바꿔 고르면 전역 투표가 덮어쓰게 한다.

### 2-4. 추천과 구현 비용
**추천: I2570 전량 내장(+ 선택적으로 C005 식품유형) + 978/979 접두(+ 선택적 ISBN API KDC) + 플레이어 선택 폴백**

게임과 맞물리는 방식
- 이미 `/api/scan` 의 `where.subtype_pick.suggest` 슬롯이 있다(지금은 전역 투표 기반). 여기에 `source: "db"` 제안을 먼저 채운다.
- 「이게 뭐예요?」 의식은 그대로 둔다. 플레이어가 확인 한 번만 누르면 된다.
- "검사"로 쓰는 안도 가능하다. 플레이어 선택이 DB와 다를 때 귀띔만 하고 벌점은 주지 않는다. 코지 게임 톤을 지키기 위해서다.

## 3. 미확인으로 남은 것
- I2570과 C005의 전체 건수와 파일 크기. sample 키로는 5건만 보인다.
- 식품안전나라 자체 저작권 정책 원문(data.go.kr 표기는 "제한 없음").
- 코리안넷 DB활용 가격, 회원 요건, 게임 용도 조항.
