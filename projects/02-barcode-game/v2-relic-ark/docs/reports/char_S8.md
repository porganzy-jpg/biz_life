## 0. 먼저 — 「방향 간 키 ±12% 오차」를 어떻게 없앴나 (합격 기준 ④)

S7 보고서 §5-6에서 내가 스스로 적은 결함이다. 이번에 **규약 자체를 다시 세워** 해결했다.

| 쓰임 | 배율 | 셀 | 발 기준선 | 미터당 | 맨머리 1.6m | 아이 1.2m |
|---|---|---|---|---|---|---|
| **원화(소스)** | ×1 | 64 | 60 | **27.5px** | **44px** | **33px** |
| **front 시트(출하 기본)** | ×4 | **256** | **240** | **110px** | 176px | 132px |
| **단면 렌더 방 안** | ×3 | 192 | 180 | 82.5px | **132px** | 99px |

핵심은 **원화 1m = 27.5px**이라는 수 하나다. 이 수를 고르면
- ×4 가 **기존 front 규약(셀 256 · 발 기준선 240 · 미터당 110px)과 한 자리도 어긋나지 않고**,
- ×3 이 단면 렌더 방의 실측(아래 §4-4에서 126~133px)과 맞고,
- 두 배율이 **모두 정수**다 → 2.5D 조건 ①(정수 배율 최근접)이 깨지지 않는다.

**실측 키는 「맨머리 꼭대기 ~ 발바닥」으로 정의한다**(C9: 맨머리 1.6m, 아이 1.2m). 모자·챙·후드 꼭지는 그 위로 자유롭게 올라간다 — 사람의 키를 모자로 재지 않기 때문이다. 생성기가 매 실행마다 역할별로 둘 다 찍어서 출력한다.

```
[ok] scout     맨머리 44px = 1.600m  (모자 포함 49px)
[ok] cook      맨머리 44px = 1.600m  (모자 포함 51px)
[ok] medic     맨머리 44px = 1.600m  (모자 포함 45px)
[ok] engineer  맨머리 44px = 1.600m  (모자 포함 47px)
[ok] farmer    맨머리 44px = 1.600m  (모자 포함 46px)
[ok] scholar   맨머리 44px = 1.600m  (모자 포함 47px)
[ok] trader    맨머리 44px = 1.600m  (모자 포함 48px)
[ok] kid       맨머리 33px = 1.200m  (모자 포함 36px)
```

**오차 0%.** 여덟 전부 정확히 같다.

### 1-1. 8역할 — 역할 구분의 세 축
①머리에 쓴 것 ②겉옷 색 ③손에 든 것. **①이 실루엣을, ②가 70px 색 판독을, ③이 근접 확인을 맡는다.**

| 역할 | ① 머리 | ② 겉옷 | ③ 손 | 색 |
|---|---|---|---|---|
| 정찰병 | **뾰족 꼭지가 달린 후드** + 뒤 꼬리 | 올리브 조끼 | 짧은 망원경 | `#606E48` |
| 요리사 | **키 큰 천 모자** (가장 높다) | 번트오렌지 앞치마 | 국자 | `#CE7A38` |
| 의무병 | **머릿수건 + 뒤 꼬리** + 이마 십자 | 크림 가운 + 적갈 완장 | 약 가방 | `#E4D8BC` |
| 기술자 | **이마 위로 올린 넓은 용접 고글** | 숯회색 작업복 | 렌치 | `#585248` |
| 농부 | **가장 넓은 밀짚 챙** | 황토 작업복 | 물뿌리개 | `#988042` |
| 학자 | **각진 납작 모자** + 깨진 안경 | 자줏빛 긴 외투 | 책 | `#80667C` |
| 교섭가 | **둥근 챙모자** + 목도리 | 적갈 코트 | 손저울 | `#A05842` |
| 아이 | **작은 우비 후드** | 노란 우비 (1.2m) | 작은 등불 | `#E2B74C` |

> 정찰병의 후드는 `data/roles.json` 의 `hood:true` 를 그대로 따른 것이다. 1차안에서는 기술자와 같은 「이마 밴드」였는데, **검은 실루엣 70px에서 둘이 구분되지 않아** 후드로 바꿨다(§4-1).

### 1-2. 자세 7종 — 시트 행 번호
`idle`(0, 2프레임 느린 호흡) · `walk`(1, 3) · `work`(2, 3) · **`sit`(3, 2)** · `carry`(4, 2) · `hurt`(5, 2) · `back_walk`(6, 3).
`meta.json` 의 `rows`·`frames`·`anim_seconds` 가 정본.

- **`sit` 은 이제 정식 자세다.** 배경이 Idle 을 방석 뒤로 내려 앉은 것처럼 속이던 것(S6-B 요청)을 끝냈다. 앉기·주저앉음은 **다리를 몸통보다 나중에 그려 앞으로 나오게** 한다 — 1차안에서는 몸통 타원이 접은 다리를 전부 덮어서 그냥 선 자세로 보였다.
- `hurt` 는 한 무릎을 꿇고 한 손으로 바닥을 짚는다. 눈썹이 뒤집히고 눈이 낮아지고 입이 내려간다.
- `back_walk` 는 **공기통 두 개를 몸통보다 나중에** 그린다(뒤에서 보면 등이 앞이다). 이것 하나로 앞뒤가 즉시 갈린다.

### 1-3. 각인 12종 — 부위를 나눠 겹치지 않게 (C4)
48px에서 각인은 2~5px이므로 **형태가 아니라 색으로 구분**한다(지시 그대로).

| 각인 | 부위 | 색 | | 각인 | 부위 | 색 |
|---|---|---|---|---|---|---|
| 포자의 표식 | 왼 목덜미 | 녹색 | | 갚은 자 | 오른 손목 | 놋쇠 |
| 빈 위장 | 허리띠 매듭 | 올리브·놋쇠 | | 물의 기억 | 이마 앞머리 | 젖은 머리+반짝임 |
| 지킨 자 | 오른 광대 | 적갈 | | 아낀 숨 | 오른 옷깃 호스 고리 | 구릿빛 |
| 햇빛의 기억 | 머리 왼쪽 늘어진 베일 | 바랜 크림 | | 금을 본 자 | 왼 장갑 끝 | 유리빛(차가운 색) |
| 빈 자리 | 왼 위팔 | 숯검정 | | 깊이의 자국 | 왼 관자놀이 | 자줏빛 |
| 발자국 | 가슴 중앙 목걸이 | 흰 이빨 | | 두드림을 들은 자 | 오른 관자놀이 울림쇠 | 놋쇠+흰 점 |

12종을 **쓰임새가 아니라 자리로** 갈랐기 때문에, 3개가 아니라 12개를 다 붙여도 겹치지 않는다. 생성기가 매 실행마다 자동 검사한다(§4-3).

### 1-4. 문어
`idle` 3프레임 + **손목 감기**(J7 장면). 외투막 + 여덟 팔 + 사이펀, 팔에 빨판 점. **눈이 사람보다 크고 밝다**(C5 — 신뢰의 역전을 색으로). 손목 감기는 잠수복 소매 하나와 그 둘레를 세 바퀴 감은 팔로 그렸다. **말풍선·의성어 없음**(DECISIONS 2026-09-27).

## 4. 검증 방법과 결과

### 4-0. 자기 눈으로 보고 고친 횟수 (07 W2)
**`Read` 로 직접 열어 보고 9회 고쳤다.** 무엇이 틀렸고 왜 고쳤는지:

| 회차 | 본 것 | 진단 | 고친 것 |
|---|---|---|---|
| 1 | 자세 7종 1차 | `sit`·`hurt` 가 **선 자세와 구분이 안 됨** — 몸통 타원이 접은 다리를 전부 덮었다 | 다리를 몸통보다 **나중에** 그리는 경로 추가, 앉은 자세의 몸통 반지름을 줄임 |
| 2 | 역할 8종 얼굴 확대 | **의무병·아이의 머리에 쓴 것이 얼굴을 통째로 덮었다**(천이 얼굴보다 나중에 그려짐) | `headwear()` 를 `under`/`over` 두 층으로 분리 — 두개골을 감싸는 천은 얼굴 **앞**에 그리고, 챙·밴드·꼬리만 **뒤**에 |
| 3 | 놋쇠 돔 | 얼굴 구멍이 너무 커서 돔이 1px 띠로만 남음 | 얼굴 구멍을 1.5px 내리고 반지름을 줄여 이마 위 놋쇠를 3.7px 확보 + 볼트 2개 |
| 4 | 랜턴 | 허리 랜턴이 **왼쪽 벙어리장갑과 한 덩어리**로 뭉쳐 보이지 않음 | 허리띠 바로 아래 앞쪽으로 내림 |
| 5 | 검은 실루엣 70px | **정찰병과 기술자가 같은 실루엣**(둘 다 이마 밴드) | 정찰병을 `roles.json` 의 `hood:true` 대로 **뾰족 꼭지 후드**로, 기술자 고글을 머리 폭보다 넓게 |

| 8 | 걷기 시트 | 어두운 배경에서 **장화가 사라졌다**(장화가 외곽선과 같은 색) | 장화 전용 색 2단(`bootM`/`bootL`) 신설 + 놋쇠 밑창 |
| 9 | 문어 | **거미/게처럼 보였다** — 눈이 두 개의 흰 네모 + 검은 막대(고글처럼), 팔이 가로로 뻗음 | 둥근 눈동자 + 반짝임으로, 팔을 아래로 늘어뜨리고 끝을 말아 올림, 외투막을 위로 솟게 |

### 4-1. 합격 기준 ① — 70px에서 여덟이 갈리는가
`check/row70_light.png`(밝은 벽) · `check/row70_dark.png`(어두운 방) · `check/silhouette70.png`(검은 실루엣).
**통과.** 실루엣만으로도 여덟이 갈린다: 뾰족 후드 / 키 큰 모자 / 뒤 꼬리 / 넓은 고글 / 가장 넓은 챙 / 각진 납작 / 둥근 챙 / 작은 몸.
색으로는 올리브-주황-크림-숯-황토-자주-적갈-노랑 여덟 색상이 서로 다른 색상환 자리를 쓴다.

### 4-2. 합격 기준 ② — 어두운 방에서 안 묻히는가
**통과.** `row70_dark.png` 에서 여덟 전부 얼굴과 겉옷이 분리되어 보인다. 근거는 `harmonize()` 의 대비 재확장(S7 3회차에서 캐릭터가 벽과 같은 갈색이 되어 사라졌던 사고의 교훈)과, 8회차에서 새로 넣은 장화 2단 색이다.

### 4-3. 합격 기준 ③ — 각인 3개가 겹치지 않는가
**통과. 사람 눈이 아니라 생성기가 검사한다.** 12종 레이어의 모든 불투명 픽셀을 좌표로 모아 중복을 센다.

```
[검사] scout 각인 12종 픽셀 충돌: 0건 []
[검사] kid   각인 12종 픽셀 충돌: 0건 []
```

3개가 아니라 **12개 전부가 서로 겹치지 않는다**. 컷은 `check/imprint3.png`(네 조합, 노란 상자가 각인 자리 + ×5 확대)와 `check/imprints12.png`(12종 전부 ×8 확대).
아이는 체격이 달라 앵커가 다르므로 **각인 레이어를 따로 한 벌**(`imprints/kid/`) 냈다 — 1차안은 어른 한 벌만 내서 아이에게 각인이 어긋나게 붙었을 것이다(검사에서 발견).

### 4-4. 합격 기준 ④ — 실측 키 규약 정확히 일치
**통과.** §0의 표와 생성기 출력. 추가로 **시트를 다시 열어 발 기준선을 픽셀로 확인**했다:

```
scout..kid  sheet 768x1792  셀0 bbox y ..~243  발(외곽선 포함) 244 = 기준선 240 + 외곽선 1px×4
baseline ok True   (8/8)
```

배경 렌더의 실측도 직접 쟀다: `section_room_zoom.png` 의 옛 화풍 주민은 **모자 포함 158px, 맨머리 약 126px**(바닥선 y=578 기준) → **79~83px/m**. 우리 ×3 = 82.5px/m 이 이 범위 안이다. `check/room_composite.png` 에 **1.6m(132px)·1.2m(99px) 노란 눈금**을 그려 넣어 눈으로도 대조할 수 있게 했다.

### 4-5. 합격 기준 ⑤ — 여전히 친근한가

## 5. 적용한 교본 원칙

- **P1(보편적 원형 — 둥지 만들기·키우기)** · **COMBAT_AND_DEFENSE §3-4** — 배치 방어는 **방마다 사람이 보여야** 성립한다. 그래서 자세 목록을 Idle/Walk 가 아니라 **방 안에서 무엇을 하고 있는지**로 짰다: `work`(일하는 중) · `sit`(쉬는 중) · `carry`(옮기는 중) · `hurt`(막다 다침) · `back_walk`(돌아섬). 플레이어가 사람을 끌어다 놓을 때 **그 방에서 무엇을 하는지가 그림으로 보인다**.
- **P2(30초에 이해)** — 목 실링·공기통·허리 랜턴·무게추 장화 넷을 여덟 역할 전부의 공통 실루엣으로 고정했다. 한 장만 봐도 "심해에 사는 사람들"이 읽힌다. 역할은 그 위에 얹는다.
- **P3(감정의 가속도)** — 차가운 색을 **기술자의 고글 유리와 「금을 본 자」 각인**에만 허용했다. 따뜻한 방 안에서 그 둘만 바다를 한 조각 달고 있다.
- **C1(3초 실루엣)** — 5회차 수정의 이유. 정찰병·기술자가 검은 실루엣에서 같아 보여 머리를 다시 설계했다.
- **C3(부족은 몸의 상실로 읽힌다)** — 이번 범위(방주 안 주민)에는 부족 의상이 없다. 대신 **각인이 같은 문법**으로 작동한다: 「깊이의 자국」은 눌린 귀, 「아낀 숨」은 목에 감아 둔 호스, 「금을 본 자」는 장갑 끝의 유리 조각. **능력이 아니라 몸에 남은 자국**을 그렸다.
- **C4(각인은 부위를 정해 겹치지 않게)** — 이 원칙을 사람 눈이 아니라 **자동 검사로** 지켰다(§4-3).
- **C5(짐승은 사람보다 따뜻하게)** — 문어의 눈을 사람보다 크고 밝게, 몸을 구릿빛 자홍으로.
- **C7(애니메이션은 일하는 모습이 먼저)** — `work`·`sit`·`carry` 를 `idle`·`walk` 와 같은 급으로 넣었다.
- **C9(발 원점·맨머리 1.6m·아이 1.2m)** — 3D 규약을 2D 도트로 **정확히 번역**한 것이 §0의 표다.
- **C10(얼굴 없는 얼굴을 피한다)** + **DECISIONS 2026-09-27** — 전 역할 눈·눈썹·입·볼 홍조. `back_walk` 만 얼굴이 없고, 그 대신 공기통 두 개로 방향을 말한다.
- **REF_ART_FLAT_FOLK §1-5(장식 무늬가 디테일을 대신한다)** — 목 실링의 물결, 밀짚 챙의 엮은 무늬, 요리사 모자단의 반복, 옷의 적갈 기운 자국, 문어 팔의 빨판 점.
- **07 §6(AI 공개 관리표)** — **이번 산출물은 공개 대상이 아니다.** 생성 AI를 한 번도 호출하지 않았다(Pollinations·Colab 미사용). 전부 절차적 드로잉이고 코드 AI는 2026 Steam 규칙상 공개 대상이 아니다. **관리표에 새 줄을 추가할 필요 없음.**
- **07 W6(매 스프린트 보여줄 것 1개)** — `check/room_composite.png`(실제 렌더 방에 세 사람이 서 있는 컷)와 비교 페이지의 8역할 걷기 무대가 데브로그 클립 재료다.

### 원칙과 다르게 한 곳
1. **07 W2(최대 3회)를 다시 이탈했다 — 9회.** 이유: 1~5회차는 "읽히는가", 6~7회차는 "각인이 겹치지 않는가", 8~9회차는 "어두운 방에서 사라지지 않는가·징그럽지 않은가"로 **보는 기준이 매번 달랐다.** 합격 기준이 다섯 개인 과제라 기준마다 한 번씩은 봐야 했다. 회수 상한보다 합격 기준을 우선했다.
2. **지시의 "P2는 ×3 = 144px"을 그대로 쓰지 않았다.** 144px은 S7의 48px 원화 × 3이고, 그 수가 바로 ±12% 오차의 원인이었다(미터당 110px 규약으로는 1.31m 짜리 어른이 된다). 같은 지시의 다음 줄이 "원본 높이를 조정해 실측 키 규약에 정확히 맞춘다"였으므로, **두 요구가 충돌할 때 「실측 키 정확히 일치」(합격 기준 ④)를 택했다.** 결과는 맨머리 44 원화px이고 ×3 = **132px**, ×4 = 176px이다. 판단 근거: 공통 교본 §3-1(성경·결정 로그에 답이 있는가 — `front_meta.json` 의 미터당 110px이 이미 정본).
3. **`work` 동작이 아직 역할별로 다르지 않다.** 전 역할이 "상체를 기울이고 오른손의 도구를 들었다 내린다"를 공유한다(도구만 다르다). 역할별 고유 작업 모션은 §6-3.

## 6. 직군 교본 §5 자가 검수 5문항

1. **검은 실루엣으로도 8역할이 갈리는가** — **갈린다.** `check/silhouette70.png` 로 확인했고, 갈리지 않던 두 역할(정찰병·기술자)을 그 컷을 보고 다시 설계했다. 갈라 주는 것은 머리에 쓴 것 하나다.
2. **큰 눈·창백함·부족 적응이 보이는가** — 큰 눈(3×3 + 반짝임)은 전원. **창백한 피부는 의도적으로 계속 완화한다** — 흰 피부가 흰 가면으로 읽혀 "징그럽다"의 직접 원인이었다(DECISIONS 2026-09-27). 어둠 적응은 **큰 눈 + 허리 랜턴 + 무게추 장화 + 목 실링**으로 말하고 피부는 따뜻한 쪽으로 간다. 부족 의상은 이번 범위 밖(방주 안 주민).
3. **각인 3개가 겹쳐도 읽히는가** — **읽힌다. 자동 검사 0건**(어른·아이 둘 다). 12종 전부가 서로 다른 픽셀을 쓴다.
4. **짐승이 사람보다 가깝고 따뜻해 보이는가** — 문어의 눈이 사람보다 크고 밝고, 몸이 사람의 어느 색보다 따뜻하다(구릿빛 자홍). **손목 감기 포즈는 사람 쪽에서 내준 손목에 짐승이 먼저 닿는 그림**이다 — 사람끼리는 하지 않는 거리다.
5. **발 원점·1.6m·+Z·클립 7종** — 2D 도트 대응 규약으로 번역해 전부 맞췄다: **발 = 발 기준선 60(×4 = 240)**, **맨머리 1.6m = 44 원화px(아이 1.2m = 33px)**, **정면 + 뒷모습(back_walk)**, **클립 7종**(idle·walk·work·sit·carry·hurt·back_walk). 시트를 다시 열어 발 기준선을 8/8 픽셀 확인했다.

## 7. 미완 · 리스크

1. **사람 없는 방 플레이트가 아직 없다.** 크롭을 `(1148,330)-(1364,600)` 으로 좁혀 주민을 피했지만, 넓은 합성 컷(`check/room_composite.png`)에는 좌우 끝에 옛 화풍 주민이 남는다. **일부러 남겼다** — 키가 맞는지 비교하는 데 쓸모가 있었다. 배경 담당에게 재요청(§8).
2. **단면 렌더의 캐릭터 배율이 정수가 아닐 수 있다.** 내가 잰 옛 주민 키는 79~83px/m이고 우리 ×3은 82.5px/m라 거의 맞지만, 배경 쪽에서 소수 배율로 붙이고 있으면 2.5D 조건 ①이 깨진다. 배경에 ×3 고정을 요청했다(§8).
3. **`work` 가 역할별로 다르지 않다.** 지금은 공용 모션 + 역할 도구. 방 기능(발전실·의무실·공방·창고·온실·정수)과 1:1로 붙는 작업 모션은 **방 배치 전투의 UI가 확정된 뒤**에 만드는 것이 맞다(지금 만들면 어느 방에 누가 서는지 모른 채 찍게 된다).
4. **역할 진화 표식 8종 미제작**(시나리오 요청 43). 각인 12종이 자리를 다 썼고, 남은 부위는 **등(공기통 사이)·오른 어깨·왼 손목·장화** 넷이다. 시나리오에서 어느 부위가 이름과 맞는지 한 줄만 받으면 다음 스프린트에 넣는다.
5. **감정 교체 얼굴 미제작.** 지금은 기본 웃는 얼굴과 `hurt` 의 찡그린 얼굴 둘뿐이다. S7에서 "눈·입만 바꿔 감정 6종"이라고 적었으니, 사건 결과·바람 달성·사기 낮음에 쓸 얼굴 4종이 더 필요하다.
6. **부족 의상 미제작.** 1막은 방주 안이라 당장은 필요 없지만, 첫 접촉 컷(E7)이 생기면 길손·불꽃·하얀 셋은 있어야 한다.
7. **옛 폴더 정리.** `static/art/chars/pixel/`(샘플 여섯)과 `front/a·b·c·d`(폐기 계열)는 **지우지 않았다** — `journey.html` 이 아직 `front/b/*_hero.png` 를 쓰고 있어서(읽기만 하는 파일이라 내가 못 고친다). 개발이 교체한 뒤에 지우는 것이 안전하다.
8. **문어의 크기 기준이 없다.** 지금은 몸 ~22 원화px(≈0.8m)로 찍었는데 성경에 문어 크기 수치가 없다. 다르면 알려 주면 바꾼다.
