# 전체 검수 — 오퍼스 5.5 (2026-10-03)

> 사용자 지시: "오퍼스 5.5로 전체 검수도 하고 부족한 부분을 채우는 계획과 실행도 진행해줘."

## 0. 이번 검수가 이전과 다른 점
지금까지 PM은 **부품을 따로따로** 검증했다. 방어 공식은 함수를 직접 불러서, 캐릭터는 그림을 열어서, 사운드는 스펙트럼을 재서. 각각은 통과했다.
**그런데 플레이어처럼 처음부터 끝까지 한 줄로 이어 본 적이 없었다.** 이번엔 그것을 했다 — 새 방주를 열고, 스캔하고, 짓고, 배치하고, 습격을 받고, 관문 행동을 하고, 복구 코드로 다른 기기에서 이어하기까지, **API를 플레이어 순서대로** 호출했다.

**결론부터: 부품은 거의 다 있는데, 서로 연결되지 않은 곳이 넷 있다. 그 넷이 전부 "플레이어가 실제로 할 수 있는가"의 문제다.**

| 시나리오 | 세션 종료 | 심해 각인 4종 등재, 2막 카드 **14장**(목표 10 초과) |

## 4. 찾은 구멍 넷 — 전부 "플레이어가 할 수 있는가"

### G-A. 심해 거점 화면에서 바코드를 못 찍는다 ★가장 심각
`static/base.js`가 `/api/scan`을 한 번도 부르지 않는다. 스캔은 옛 2D 화면(`/`)에만 있다. **이 게임의 핵심 훅이 본 화면에 없다.** 개발 가이드 Phase 1 #2("거점 화면에 스캔 이식")가 아직 미이행이었다.

### G-B. 신규 생물 일곱을 막을 방법이 화면에 없다
서버 `/api/ark/act`는 동작하는데 화면이 안 부른다. 생물 14종 중 **일곱은 습격이 와도 플레이어가 이길 수 없다.** 시나리오가 공들인 "먼저 배운 정답이 오답이 되는" 반전 둘(거울눈·덮개)도 화면에서 체험할 수 없다.

### G-C. 복구 코드가 서버에만 있다
발급·불러오기 모두 서버에서 동작하는데 화면이 안 부른다. **플레이어가 자기 코드를 볼 방법이 없다.** 기기를 바꾸면 여전히 전부 사라진다.

### G-D. 첫날 아무 방도 못 짓고, 방은 기획서 12종인데 코드는 5종
- 시작 자원(식량4·물4·부품1·잔해2)으로 정수실·공방 전부 자원 부족. 첫 10분 대본 5:20 「첫 증축」이 성립하지 않는다.
- `rooms_catalog`가 5종(식량창고·정수실·의무실·서고·공방)뿐이다. **거주실은 "없는 방"으로 거절**된다. `ROOMS_AND_ITEMS.md`의 12종과 레벨업 조건이 코드에 안 들어갔다.

### 그리고 E1 선반 — 미구현
이 게임의 정체성(PLAYER_JOURNEY E1). 소품 그림 34종과 이름은 다 있는데 연결이 없다.

## 5. 왜 이런 구멍이 생겼나 — PM의 검수 방식 문제
**공통 원인: 각 에이전트는 자기 파일을 완성했고, PM은 각 파일을 검증했다. 그런데 파일과 파일 사이 — 서버가 만든 기능을 화면이 부르는지 — 는 아무도 소유하지 않았다.** 파일 소유권 방식의 사각지대다.
- 서버 담당은 API를 만들고 "동작한다"를 증명했다. 맞다.
- 화면 담당은 자기가 부르는 API가 동작함을 증명했다. 맞다.
- **"서버에 있는데 화면이 안 부르는 API"는 둘 중 누구의 완료 기준에도 없었다.**

→ **검수 규칙 (사) 추가: 스프린트마다 "서버 API 목록 − 화면이 부르는 API 목록"을 뽑는다.** 차집합이 비어 있지 않으면 기능이 플레이어에게 닿지 않은 것이다. 한 줄 명령으로 된다:
```
comm -23 <(서버 라우트) <(화면이 부르는 경로)
```
그리고 **스프린트마다 플레이어 한 바퀴를 API로 돌린다.** 부품 검증만으로는 이번 같은 구멍을 영원히 못 잡는다.

## 8. 정정 (시나리오 보고 후)
**"심해 각인이 전투에 닿지 않는다(각인 항 언제나 0)"는 틀린 주장이었다.** 밸런스 보고서가 그렇게 썼고 PM이 검증 없이 옮겨 적었다(§1 표의 "심해 각인 4종 등재"를 큰 해결처럼 쓴 것도 같은 오류). 시나리오가 실측으로 바로잡았고 PM이 재현했다 — `crack_seen`을 가진 주민이 작은 떼를 막을 때 **+1.5**가 붙는다. 런타임 병합으로 원래 닿고 있었다. 이번 등재로 바뀐 것은 동작이 아니라 **정본의 위치**(코드 사본 → 데이터 파일)다.
**실제로 0인 것은 따로 있었다**: 신규 생물용 각인 셋(`made_way`·`fed_it`·`sent_up`). 생물은 등록됐는데 각 생물의 각인 목록에 새 이름이 없다. PM 측정 셋 다 +0.0. 서버 담당에 전달.
**교훈**: 다른 에이전트의 보고를 옮겨 적을 때도 재현한다. M2(검수는 다시 해 보는 것)는 에이전트 산출물에만이 아니라 **에이전트의 주장**에도 적용된다.


## 9. 독립 코드 리뷰 — PM과 다른 눈으로
결론 없이 코드만 넘겼다. **방어 판정의 결정성·산술·충돌은 문제없다**는 판정과 함께, PM이 세 번 검수하며 못 본 결함 넷이 나왔다.

| # | 결함 | 심각도 | PM 판단 |
|---|---|---|---|
| 1 | **문지기: 정답을 해도 진다.** 아무 방에나 모여 숨죽이면 관문은 통과하는데 점수는 공격받는 방만 센다. 그 방이 비면 진다. 게다가 공격 대상은 소리 단계에서 숨겨져 있다 | **높음 — 플레이어가 규칙을 지켜도 지는 구조** | **관문 통과 시 결과는 `passed`(못 찾고 지나감).** 문지기의 막는 법은 "맞선다"가 아니라 "들키지 않는다"다 |
| 2 | 복구 코드 무차별 대입 — 시도 제한이 없다. 돌려받는 uid가 유일한 열쇠라 한 번 맞히면 완전 탈취 | 높음(외부 노출 시) | IP별·전역 실패 제한. **코드는 6자리 유지**(손으로 적기 쉬워야 한다) |
| 3 | 아무 uid로 코드 요청 시 빈 방주 생성 | 낮음 | 있는 방주에만 발급 |
| 4 | 작은 떼: 정원 2 방에서 세기 4면 불가능 | 중간(드묾) | 필요 인원을 방이 채울 수 있는 최대로 상한 |

전부 서버 담당에 전달했다.

**왜 PM이 1번을 못 봤나**: 문지기를 검증할 때 `gathered_one_room=True`를 ctx에 직접 넣었다. **어느 방에 모였는지**와 **어느 방이 공격받는지**를 따로 움직여 본 적이 없다. 검수 규칙 (바)("변수 하나씩 고정하고 나머지를 움직인다")를 지켰다면 잡았을 결함이다. 규칙을 세워 놓고 다음 검증에서 또 빠뜨렸다.

**독립 리뷰를 붙인 판단은 옳았다.** 같은 눈으로 네 번째를 봤으면 같은 곳을 못 봤다.

### 남은 것
- 화면 담당이 작업 중이다. `/base`의 `openAccount is not defined`는 그쪽 진행 중 코드.

- 「숨의 손」 각인이 아직 없어 의무실 Lv3이 임시로 「아낀 숨」을 본다.
- 시도 제한이 메모리에 있어 서버 재시작 시 풀린다(지인 테스트 단계에선 수용).

| G-B 신규 생물 일곱을 막을 방법 없음 | **닫힘** — 습격 막대에 행동 버튼·대가·할 수 없는 까닭. **거울눈·덮개 반전이 화면에서 읽힌다**(「끄면 최악수」, 「옮기면 최악수」) |
| G-C 복구 코드가 서버에만 | **닫힘** — 「열쇠」. 404·400·429를 나눠 안내. **폰 브라우저에서 코드로 같은 방주를 이어받아 선반 3점이 그대로 보였다** |
| G-D 첫날 증축 불가·방 5종 | **닫힘**(서버) |
| E1 선반 | **닫힘** — PM이 스크린샷 직접 확인: 「방금 찍은 것 · 열두 칸 상자」 금색 테두리 + 알림 |

### PM 결정
- **소품 렌더 규약 승인**: 표시 크기를 원화의 정수배로 지키고, 배율 4 미만이면 ×4 원본을 줄여 쓰고 4 이상이면 1배 원화를 최근접 보간으로 키운다. 결과가 뭉개짐 없이 또렷하다. PM 브리프의 `pixelated` 일괄 지시와 배경 규약이 충돌했는데 둘을 다 지키는 해법을 찾았다.
- 덤으로 **레벨업 버튼**과 **신규 생물 일곱의 실루엣이 문어 모양으로 그려져 '식구'로 읽히던 것**을 고쳤다. 후자는 PM이 못 본 것이다 — 위협이 식구처럼 보이면 플레이어가 대응하지 않는다.

### 남은 것
- **실기기 카메라 확인 한 번** — Playwright에 카메라가 없어 숫자 입력 경로로만 검증. 폰 HTTPS(8444)에서 사용자가 직접.
- 폰에서 습격 막대가 화면의 40~45% — **가로 전환 때 옆 가장자리로 옮기면 풀린다.**
- 선반 Lv2(12칸)에서 폭 2 소품이 줄 끝에 놓이면 반 칸 삐져나감 — 서버 칸 배정 문제, 요청함에 등재됨.
