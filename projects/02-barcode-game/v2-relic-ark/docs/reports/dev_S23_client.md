## ② 아이폰 카메라 — 고침(실기기 확인은 사용자 몫)
- **판별기**: 브라우저에 `BarcodeDetector`가 없으면(iOS Safari·Firefox·윈도 Chrome) zxing-wasm 폴리필 `cdn.jsdelivr.net/npm/barcode-detector@2.3.1/pure/+esm`을 쓴다.
  - **찍기 창을 열 때만** 받는다. 첫 화면 로드에서 내려받는 바이트는 0이다. 카메라 권한을 묻는 동안 함께 받는다.
  - 읽는 형식: EAN-13·UPC-A·EAN-8.
- **카메라**:
  - 후면(`facingMode: environment`)을 쓰고, 지원하는 기기면 연속 초점을 켠다.
  - iOS용으로 `playsinline`·`muted`를 건다.
  - 권한을 거부하면 「카메라를 쓰지 않기로 하셨습니다. 아래에 숫자를 적어 주셔도 됩니다」.
- **읽은 번호 거르기**: 카메라가 읽은 번호도 GS1 검증 숫자가 맞는 것만 받는다(잘못 읽은 프레임을 거른다).
- **손 입력**:
  - GS1 검증 숫자를 먼저 본다. 틀리면 「관리실에서 알려 드립니다. 숫자를 다시 한 번 확인해 주세요. 끝자리가 줄무늬 아래 숫자와 맞지 않습니다.」
  - `/api/scan`에 `source: "manual" | "camera"`를 보낸다.
- **검증**:
  - **Chromium**(가짜 카메라에 EAN-13 영상): 폴리필 경로로 4.3초 안에 읽고 `/api/scan`까지 갔다. 찍기 창을 열기 전 jsdelivr 요청 0, 콘솔 0.
  - **WebKit**(Playwright 26, 윈도판): `getUserMedia` 자체가 없어 카메라 경로는 확인하지 못했다. 대신 같은 폴리필을 WebKit 엔진에서 불러 EAN-13 그림을 0.2초에 읽었다(8801043015097).
  - GS1 검사: 8801043015097 맞음, …098 틀림, UPC-A·EAN-8 맞음.
  - **실제 아이폰 확인은 사용자 몫이다.** 카메라는 HTTPS에서만 열린다(`python server.py --https`, 8444).
- 스크린샷: `s23_cam_chromium`, `s23_manual_bad_{chromium,webkit}`

## 걷기 빠르기(PM 수정분) 확인
- `WALK_PACE 1.6`·`SIDE_LOOP_ADULT 0.8/1.6`·side 클립 ms ÷ pace가 그대로다.
- 계산상 옆걸음 한 바퀴는 16 원본px / 0.5초 = 32 px/s = 1.16 m/s다. 클립도 같은 배율로 빨라져 발과 바닥의 비가 1.6배 전과 같다. 그래서 미끄럼은 계산상 0이다.
- **눈으로 프레임 비교는 하지 않았다(헤드리스 스틸만).**
- 승강기 배차(`secPerFloor 0.9`, 문 0.5초)는 바뀌지 않았다. 걷기만 빨라져, 걷는 구간 대비 승강기 대기 비중이 조금 커진다.
- **실기기에서 1280·844로 한 번 보는 것을 권한다.**
