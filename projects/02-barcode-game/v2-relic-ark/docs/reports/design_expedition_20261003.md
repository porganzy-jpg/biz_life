## 1. 무엇을 정했나 — 결정 여덟

| # | 결정 | 핵심 숫자 |
|---|---|---|
| 1 | **문간** = 맨 위층 트인 쪽의 고정 자리(유리 지붕 정원의 옛 문). 배치 안 된 사람은 홀 대신 여기 모여 **각자 가장 높은 스탯의 일**을 한다(수선·망보기·펌프·마중) | 덤은 활동마다 한 사람 몫만: 마모 −1/일, 눈 8 예고, 공기 +1/일, 마중 사기 +1 |
| 2 | 새 주민은 **문간으로 온다**: 두드림 + 원정 구조. **손님은 스스로 떠나지 않는다** | 3일차 첫 두드림 고정, 이후 8%/일. 구조: 모르는 쪽 10%(반나절)·18%(밤), 첫 '모르는 쪽'은 반드시. 잠자리 3/6/9/12, 손님 자리 2 |
| 3 | 원정은 **실제 시간**, 길이 셋 | 잠깐 30분 / 반나절 4시간 / 밤 넘기기 10시간(에어락 Lv1) |
| 4 | 공기는 **하루 공급량**(재고 아님), 원정이 공기통만큼 쓴다 | 공급 8(온실 Lv2 +2·Lv3 +4, 에어락 Lv2 ×1.25), 공기통 2/4/6 |
| 5 | 스탯 넷이 원정에서 각자 다른 일 | 숨: 행동 ×(1+0.1(숨−5)) · 눈: 상자/유물 +1%p, 발견 0.40+0.06(눈−5) · 손: 칸 2+⌈손/2⌉ · 담: 큰 것 판정 |
| 6 | 원정의 큰 몫은 **봉인 상자**, **같은 갈래 바코드로 연다(감쇠된 바코드도)** | 줍기당 8%, 상자 = 주 재료 4(+유물 25%), 7일 뒤 억지로 절반 |
| 7 | 위험 넷이 스탯 넷에 하나씩. **죽음·미귀환·장비 소멸 0** | 위험 8/15/25%, 처음 두 원정 0, 판정 0.55+0.07(스탯−5) |
| 8 | 접촉 전이면 **그 생물이 바깥에 있다** → 원정 위험 가산. 밖에 나간 사람은 집을 못 지킨다 | 손톱 +0.25, 긴목·문지기 +0.10, 문어의 날 −0.05 |

## 2. 각 값의 근거 (요약 — 전부는 json `_basis`)

- **문간 덤을 사람 수와 무관하게**: 한 사람을 생산 방에 넣으면 ×1.0. 문간 넷을 다 합쳐도 그보다 작아야 "놀게 두기"가 정답이 되지 않는다(B3).
- **손님이 떠나지 않는다**: 기한이 있으면 타이머다(00_COMMON 금지 목록, M10). 대신 손님 자리 둘이 차면 새 사람이 오지 않는다 — 돌려보내는 장면을 시스템이 만들지 않는다(B4).
- **잠자리 3/6/9/12**: Lv1이 1주차 목표(5)+손님 하나를 받고, Lv2가 2주차 목표(7) 위로 여유 2. 잠자리가 아니라 **도착 속도가 곡선을 정하게** 하려는 것(잠자리가 정하면 "거주실을 올려야 사람이 온다"는 압박).
- **공기 8**: 긴 원정 6 + 짧은 2, 또는 반나절 둘. 하루 한 번 켜는 사람도 6을 쓴다 → 격차 0.75배(B4). 상한 하루치 = 오프라인 생산 상한과 같은 논리.
- **숨을 곱으로**: 처음엔 floor((숨−5)/2) 더하기였는데 짧은 원정(공기 2)에서 숨 7이 +50%가 되어 "짧게 여러 번"이 정답이 됐다(1차 X2). 곱으로 바꿔 길이마다 같은 비율.
- **상자 4·8%**: 상자 하나 = 좋은 스캔 하나(기본 산출 3~4 × 기대 배수 1.21). 직접 재료(줍기당 0.36)는 일부러 작다 — 원정 가치의 상당 부분이 **스캔으로만 열리는 상자**로 흐르게 했다.
- **상자 갈래 절반 = 최근 7일 찍은 갈래(균등)**: 열쇠 없는 상자만 쌓이는 막다른 길 방지. 횟수 비례가 아니라 균등인 이유는 식품·음료 상자만 나오면 다양성(H2)을 못 밀기 때문.
- **스팟을 깊이로 연다**(0/60/120/180m): 단서 문턱(갈래별 2~4회, 서버·시나리오 소유)이 낮아 2차 시뮬레이션에서 14일차에 4.6곳을 알았다. 문턱은 건드리지 않고 깊이로 문을 열었다 — 내려가기가 지도를 넓힌다.
- **스팟 방문 덤 3일 쿨다운**: 매번 주면 '위를 보는 숲'(식량2·직물2)의 공기당 가치가 1.41로 다른 곳(0.77~0.99)의 1.5배 → 정답 목적지가 생겼다(B3 위반). 쿨다운 뒤 0.96.
- **위험 판정 0.55+0.07**: 스탯 5에 55%, 8에 76%, 3에 41%. 20~95%로 묶어 스탯이 운명이 되지 않게.
- **에어락 Lv2 ×1.25**(문서는 1.5): 1.5면 2주차에 공기 16.5 → 원정 수입이 스캔 비중을 54%까지 내렸다(1차). **M3 이탈**.
- **공기통 +1/+3**(장비, 원래 +2/+5): 공기통이 2/4/6이 되었으니 +5는 긴 원정을 거의 두 배로 만든다. 대가(숨 −1)는 유지.
- **두드림 8%·구조 10/18%**: 1차(15%·15/25%)에서 30일 주민 11.5 → 목표 10 초과. 깎은 뒤 10.8.

### X7. 습격과의 거래
**빠진 사람의 값**(보통 배치 "맞는 사람 2 + 나머지", 관문 했을 때, 막음 비율 변화): 등급 1 −10%p · 2 −20%p · 3 −36%p · 4 −84%p · 5 −71%p. 정원을 채운 방(총력)은 한 사람이 빠져도 0%p. → **깊어질수록 '누구를 내보내나'가 무거워지고, 방을 채우는 것이 원정의 보험이 된다.**

## 4. PM의 재미 질문 셋에 대한 답

- **(a) 세션마다 의미 있는 결정**: 누구를(눈 혼자 / 손 짝 / 숨 짧은 사람 빼기) · 어디로(재료·열쇠 / 첫 발견 / 사람) · 얼마나(다음에 언제 켤까) · 언제 받나(물 먼저 / 길 먼저) · 누구를 들이나 · 무엇을 찍나(선반의 상자 무늬). X1·X2가 "어느 답도 크게 이기지 않는다"를 보인다.
- **(b) 새 바코드 의존 줄이기**: 봉인 상자 — **열쇠는 새것일 필요가 없다.** 감쇠는 그대로 두고 헌 물건에 두 번째 쓸모를 얹었다. X6.
- **(c) 처벌 아닌 애착의 무게**: 기다리는 사람(신뢰 최고)이 문간에서 문을 본다 · 구한 사람과 구해진 사람 신뢰 20 · 함께 나가면 +3, 위험을 함께 넘기면 +10 · 각인은 밖에서 생긴다(「아낀 숨」은 **실패**가 조건) · 다친 사람이 눕는 것이 보인다 · 숨이 자란다 · 일지 한 줄.

## 5. 적용한 교본 원칙

- **B1** 값마다 json `_basis`. 근거가 시뮬레이션뿐인 것은 그렇다고 썼다.
- **B2** 30·60일 × 3유형 × 씨앗 20, 1차→2차→3차 튜닝을 보고서에 남겼다(§2의 "1차에서…").
- **B3** 공기당 가치 ±12%(X2), 조 구성 0.67~0.91(X1), 물 먼저/길 먼저 어느 쪽도 늘 이기지 않음, 덤 쿨다운으로 정답 목적지 제거, 갈림길은 기댓값 중립.
- **B4** 손님 기한 없음, 상자 7일 바닥, 처음 두 원정 위험 0, 미귀환 0, 결석 무벌칙, 따라 나가기 안 해도 기댓값 같음.
- **B5** 상자 열쇠 = 스캔, 스팟 갈래 여덟, 상자 갈래 균등. 스캔이 모든 유형에서 가장 큰 단일 수입원.
- **B6** 숨 성장 최대 +2(= 행동 +20%)로 각인 이하. 원정 각인은 처음 겪는 종류만.
- **B7** §7 목록. json `_what_measurement_would_settle_this`.
- **M10 / 00_COMMON 금지 목록** 기다리게만 하는 타이머 없음 — 기다림은 "돌아온 사람"으로 보상. 알림·실시간 개입 없음.
- **P3** 안(등불·리더 목소리)/밖(어둠·숨소리) 대비를 원정이 하루에 여러 번 만든다.

## 6. 발견 사항 — 원정과 별개로 고쳐야 할 것

1. **경제 곡선이 이미 빠르다.** `sim_economy.py`(2026-10-01, 내 작업)는 씨앗 7 하나로 "네 지점 모두 맞음"을 냈다. 씨앗 20개 평균으로 다시 돌리면 보통 플레이어 방이 **7일 8.2 / 14일 10.6**(목표 6 / 9)이다. 원정을 끈 내 모델에서도 8.7 / 10.8. → 목표 곡선 판정은 **씨앗 한 개로 하면 안 된다.** 다음 밸런스 작업에서 sim_economy를 다중 씨앗으로 바꾸고 건설비를 다시 맞춰야 한다. 원정의 스팟 깊이 문도 이 곡선을 따라가므로 함께 늦춰진다.
2. **지금 1막에는 사람이 늘어나는 길이 없다.** 합류는 `events.json drifter` 한 장(acts [3])뿐. 이 사양의 문간이 고칠 때까지 1막 주민은 영영 3명이다.
3. **습격을 끝까지 안 누르면 아무 일도 없다.** 날이 넘어가면 판정 없이 지나간다(economy.json skipped_day의 의도는 '접속 안 한 날'이었다). 접속한 날 일부러 안 누르는 것도 공짜다. 이 사양의 '생물이 바깥에 머문다'가 원정 쪽에서 작은 이유를 만들지만, 습격 자체의 규칙은 PM 판단이 필요하다(§8 질문 3).
4. `ensure_raid`가 날마다 `outside`를 비운다 — 밤 넘기기가 날을 넘기면 원정대가 사라진다. 원정 구현 때 반드시 폐지.

## 7. 미확정 임시값 (B7)

| 값 | 지금 | 확정 방법 |
|---|---|---|
| 길이 30분/4h/10h | 하루 2~3회 접속 가정 | 실제 접속 시각 분포 |
| 공기 8 | 시뮬레이션 | 출발 횟수/일(2 미만이면 6으로) |
| 상자 4·8%·7일·갈래 50/50 | 시뮬레이션 | 재스캔으로 연 비율(≥30%), 억지로 연 비율(≤30%) |
| 두드림 8%·구조 10/18% | 목표 곡선 | 실제 주민 곡선, 손님 거절률 |
| 위험 8/15/25%·판정식 | 부상 ≤1/주 | 실플레이 부상 빈도, "덜 보내게 되는가" |
| 생물 가산 | 설계 판단 | 물 먼저/길 먼저 비율(한쪽 90%↑면 수정) — 길 먼저의 이득(준비)은 아직 값이 없다 |
| 갈림길 ±0.10/±0.03 | 기댓값 중립 계산 | 갈림길 선택 비율 |
| 스팟 깊이 문 | '주에 하나' | 발견 간격 — 경제 곡선이 고쳐진 뒤 |

**다시 봐야 하는 가정**: 스캔 카테고리 분포(economy.json, 가장 약한 숫자)가 바뀌면 상자 열쇠 비율(X6)이 가장 먼저 흔들린다. 하루 접속 횟수 가정이 틀리면 X3·X5 전체.

## 8. 사용자에게 묻고 싶은 것

1. **따라 나가기(앞머리 1~2분 직접 조작)가 기댓값을 바꾸지 않는 설계**에 동의하는가. 직접 조작에 보상을 더 주면 재미는 커지지만 "접속해서 따라 나가야 손해가 없다"가 된다.
2. **손님이 스스로 떠나지 않는 것**이 맞는가. 아니면 "며칠 뒤 다른 돔으로 가며 작은 선물을 두고 간다" 같은 부드러운 이별을 원하는가.
3. **습격을 끝까지 안 누르면 그냥 지나가는 것**을 유지할 것인가(§6-3). 유지하면 원정의 '생물이 바깥에 있다'가 습격을 누를 거의 유일한 이유가 된다.
4. 띄엄띄엄 플레이어 60일차에 스캔 비중이 39%로 떨어지는 것(스캔은 여전히 가장 크다)을 받아들일 것인가.
5. 스팟 '발견'을 스캔에서 원정으로 옮기는 것(스캔은 단서까지).
