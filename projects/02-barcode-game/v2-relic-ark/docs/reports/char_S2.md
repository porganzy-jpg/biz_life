Quaternius `Cow.blend`는 인간형 골격(두 발)이라 네 발 보행에 맞지 않아 쓰지 않았다.

- **정면 +Z**(Blender −Y → `export_yup=True`). 캐릭터 GLB와 같은 규약이라 `object.lookAt()`이 그대로 맞는다.
- **눈**(C5, 신뢰의 역전을 색으로): 사람은 큰 흰자 + 어두운 동공(`#17120f`)인데, 짐승은 **밝은 홍채 + 작은 동공 + 흰 반짝임**.

- **개 Idle = 기대는 포즈**(C5, `TRUST_AND_COMPANIONS §3` "몸으로. 인간이 무언가를 껴안는 유일한 장면"):
  Root를 몸통 축(−X 쪽)으로 **16° 기울이고** 0.048 m 밀어 넣은 뒤, 목·머리를 들어 사람을 올려다보게 했다.

- Walk는 대각선 보행(앞왼+뒤오른), 까마귀는 총총 뛰는 걸음(Root 상하 + 머리 앞뒤 찌르기).
- 뼈가 "2~4본" 지시보다 많은 9~10본인 이유: 네 다리를 따로 흔들지 않으면 걷기가 미끄러지듯 보인다.
  대신 **스킨 없이 뼈 부모(bone parent)** 만 써서 가중치·본 수의 비용을 없앴다.

## 3. 각인 외형 파츠 8종 — 8역할 GLB 안에

데이터의 실제 id(`empty_stomach`, `warden`)를 따랐다(지시서 본문의 "id와 정확히 일치" 조항 우선).

| `imp_` 노드 | 각인 | 부위(C4, 겹침 없음) | 형태 | 붙은 뼈 |
|---|---|---|---|---|
| `imp_spore_mark` | 포자의 표식 | **얼굴 왼뺨·턱 + 목덜미** | 녹색 반점 5 | Head |
| `imp_warden` | 지킨 자 | **얼굴 오른뺨 + 등** | 흉터 2 + 방망이(자루·머리·손잡이 끈) | Head |
| `imp_sun_memory` | 햇빛의 기억 | **머리 뒤(베일) + 팔뚝** | 이마 띠 + 늘어진 천 2 + 그을린 팔뚝 2 | Head |
| `imp_water_memory` | 물의 기억 | **정수리 + 눈** | 젖은 머리(광택) + 앞머리 3 + 밝아진 눈 2 | Head |
| `imp_footprint` | 발자국 | **목 + 가슴** | 끈 + 이빨 3 + 찢긴 어깨 | Neck |
| `imp_empty_stomach` | 빈 위장 | **허리** | 가죽 띠 + 놋쇠 버클 + 매달린 표찰 | Hips |
| `imp_empty_seat` | 빈 자리 | **왼 위팔(어깨쪽)** | 검은 팔띠 + 매듭 | UpperArm.L |
| `imp_debt_paid` | 갚은 자 | **오른 손목** | 놋쇠 팔찌 2겹 | Fist.R |

부위 분리는 최대 3개 동시 착용을 전제로 정했다(04 §C4). 기존 소품과의 충돌도 피했다:
의무병의 붉은 완장(UpperArm.L, 아래쪽) ↔ 검은 팔띠(위쪽), 기술자의 공구벨트(`hi.z+0.34`) ↔ 허리띠 유물(`hi.z+0.22`).
얼굴 반점·흉터는 **머리를 구로 근사해 표면에 정확히 올렸다**(`on_head()`) — 첫 시도에서는 머리 안에 파묻혀 보이지 않았다.

### 3-1. ★ 노드명 규약 (개발이 런타임에 켜는 방법)

```
imp_<id>            ← 빈(Empty) 노드 하나. 이것만 끄고 켜면 각인 전체가 사라지고 나타난다.
  imp_<id>_0 … _n   ← 그 각인의 파츠 메시들(자식). 개별로 만질 일 없음.
```

- `<id>`는 **`data/imprints.json`의 `imprints[].id`** 그대로다: `spore_mark · empty_stomach · warden · sun_memory · empty_seat · footprint · debt_paid · water_memory`.
- `imp_` 노드는 항상 **뼈(Head/Neck/Torso/Hips/UpperArm.L/Fist.R)의 자식**이므로 모든 클립에서 몸을 따라간다.
- **기본 hidden은 GLB에 반영되지 않는다.** Blender에서는 `hide_viewport/hide_render = True`로 만들지만,
  glTF 2.0에 표준 가시성 필드가 없고 Blender 5.2 내보내기도 `KHR_node_visibility`를 쓰지 않는다(빈 큐브로 직접 확인).
  따라서 **로드 직후 개발이 이름으로 전부 끈 다음, 주민의 `imprints` 배열에 있는 것만 켜야 한다.**

```js
// Three.js — 로드 직후 1회
const imps = {};
root.traverse(o => { if (/^imp_[a-z_]+$/.test(o.name)) { imps[o.name.slice(4)] = o; o.visible = false; } });
// 주민 상태가 바뀔 때
function applyImprints(root, ids /* residents_list[].imprints */) {
  for (const [id, node] of Object.entries(root.userData.imps)) node.visible = ids.includes(id);
}
```
정규식에 `_\d+$`가 걸리지 않게 해야 자식 메시까지 개별 제어하는 실수를 막는다(자식은 부모가 꺼지면 같이 꺼진다).

### 3-2. 역할 진화 표식 — `evo_<role>` 노드명 **예약**(모델링은 스프린트 3)

PM 중계로 받은 `data/roles_evolved.json` 이름에서 떠오르는 표식 1줄 아이디어.

| 진화 이름 | 표식 아이디어(부위 1개·색 1개) |
|---|---|
| 노래잡이 | 목에 감은 낡은 끈과 **작은 종** — 걸을 때만 소리 난다(목: 이빨 목걸이와 높이 분리) |
| 버림 없는 손 | 허리에 매단 **깨진 그릇 조각 꾸러미** — 아무것도 버리지 않은 사람 |
| 숨의 손 | 손목까지 올린 **천 감은 양손**, 손끝만 드러남 — 닿아야 하는 사람 |
| 조상 깨우는 이 | 등에 진 **불 꺼진 전구 하나**, 어깨의 구리선 — 잠든 것을 깨우는 사람 |
| 문턱지기 | 어깨에 걸친 **문짝 경첩 한 쌍** — 문턱에 서는 사람의 계급장 |
| 낭독하는 이 | 가슴 앞에 펼친 **낱장 묶음**과 입가의 잉크 자국 |
| 빈손 흥정꾼 | **장갑을 벗은 맨손**과 허리의 빈 주머니 — 담보 없이 거래하는 사람 |
| 짐을 진 아이 | 키보다 큰 **등짐**, 어깨끈이 파고든 자국 |

> 확인 필요: 이 8개 이름은 「정찰병·수집가·의무병·기술자·경비·기록자·상인·아이」로 왔는데
> `data/roles.json`의 8역할은 「정찰병·요리사·의무병·기술자·농부·학자·교섭가·아이」다.
> 수집가/경비/기록자/상인 ↔ 요리사/농부/학자/교섭가의 대응을 PM이 확정해 주셔야 `evo_<role>`의 `<role>`을 못 박을 수 있다.

## 4. 8역할 GLB 재검증 (각인 파츠 포함 재내보내기 후)

내보내기 규약을 하나 고쳤다: **액션을 NLA 트랙으로 밀어 넣지 않는다.**
트랙을 만들면 뎁스그래프가 그것을 평가해 GLB의 **기본 포즈**가 마지막 트랙 첫 프레임(Walk)으로 굳는다
(짐승 개 모델에서 발이 6 mm 바닥을 파고드는 형태로 처음 발견했다).
`export_animation_mode='ACTIONS'`는 파일 안의 모든 액션을 알아서 각각 내보내므로 트랙이 필요 없고,
액션만 떼면 **기본 포즈 = Idle 0프레임 = 정규화를 계산한 그 자세**가 된다.

클립 이름은 그대로 `Idle/Walk/Run/PickUp/SitDown/StandUp/Death`.

### 검증 방법 (`blender_animals.py -- verify`)
1. **(a) 씬 실측** — 짐승·공룡을 다시 빌드해 뎁스그래프 이밸류에이트로 Idle 첫 프레임의 z 최저/최고를 잰다.
2. **(b) GLB 직접 읽기** — GLB의 JSON 청크를 직접 파싱해 노드·애니메이션·용량을 확인한다.
3. **(c)** 8역할 GLB의 `imp_` 노드 목록.

> ⚠ **재임포트 검증은 쓰지 않았다.** Blender의 glTF *임포터*는 뼈 길이·롤을 스스로 다시 추정하기 때문에
> 포즈의 **이동(translation) 채널**이 다른 기저로 해석된다. 실제로 씬 실측이 정확히 `0.0000..0.5500`인 개가
> 재임포트하면 `-0.0059..0.5591`로 보였다. Three.js는 뼈를 재구성하지 않고 glTF 노드 TRS를 그대로 쓰므로
> **씬 실측 값이 클라이언트가 보는 값**이다. S1 보고서의 재임포트 수치도 같은 이유로 ±1% 오차가 있었을 수 있다.

J행에서 녹색 반점 · 흉터 · 밝아진 눈 · 허리띠 · 놋쇠 팔찌 · 검은 팔띠가 한눈에 읽힌다.

남은 약점(치명적 아님)
- **이빨 목걸이가 요리사에서 흐리다** — 상아색 이빨 + 흰 조리복이라 대비가 없다. 어두운 옷(정찰병·기술자)에서는 잘 읽힌다.
- **등 뒤 방망이·베일이 정면 컷에서 작다** — 부위상 뒤에 있어 그렇다. 3D 화면에서는 회전하면 보인다.
- 개 렌더가 의도한 색(`#2C241B`)보다 밝게 나온다. `hexcol()`이 sRGB 값을 선형으로 그대로 넣는 기존 파이프라인 규약 때문인데, **캐릭터와 톤을 맞추려 일부러 고치지 않았다**(고치면 짐승만 어두워진다).
- 까마귀·개가 여전히 각진 상자형이다. 저폴리 톤 안에서는 허용 범위지만, 근접 컷이 필요하면 다듬어야 한다.

## 6. 교본 인용

- **C1 3초 실루엣** — 짐승 셋을 귀·부리 하나로 갈랐다(늘어진 귀 / 삼각 귀 / 부리+부채 꼬리). 각인도 "부위 하나에 크게".
- **C4 각인은 부위를 정해 겹치지 않게** — 위 §3 표가 그 구현이다. `imp_<id>` 노드 + 기본 hidden까지 교본 문장 그대로.
- **C5 짐승은 사람보다 따뜻하게** — 개 Idle의 기대는 포즈, 짐승만 밝은 눈.
- **C6 공룡은 위협이자 풍경** — 무채+초록 통일, 사람과 같은 카메라(45°/32°)·같은 선 두께(Freestyle 1.3, `#1a1714`).
- **C8 공용 골격, 파츠 조합** — 각인을 뼈 부모로 붙여 애니메이션 하나로 전원이 움직인다.
- **C9 발 원점, 정면 +Z, 실측 크기** — §1·§2·§4 표.
- **P1(보편적 원형)** — 짐승 키우기와 공룡은 여덟 원형 중 "키우기"와 "종말 공상"에 직접 닿는다.
- **P3(감정의 가속도)** — 각인은 위기 **다음 날 아침 갑자기** 외형이 바뀌는 계단이다. 그래서 파츠를 런타임 토글로 만들었다.
- **07 W2(작게 만들고 눈으로 확인)** — 렌더를 직접 보고 3회 고쳤다(위 표).
- **07 W5(3D 먼저, AI 그림은 나중)** — 이번 산출물에 생성 AI는 **한 점도 쓰지 않았다**. 전부 Blender 절차 + CC0.
- **교본과 다르게 한 곳**: 04 §2 C7 "일하는 모션 1종 필수" — 짐승·공룡은 Idle/Walk만 넣었다(지시서 범위). 공룡의 Attack, 개의 "경고(짖음)"는 스프린트 3 후보.

## 7. 04 §5 자가 검수 5문항

1. **검은 실루엣으로도 8역할이 갈리는가?** — 갈린다. S1의 시그니처(등짐·높은 모자·붉은 십자·시안 고글·넓은 밀짚모자·가슴의 책·챙 넓은 모자·작은 키)를 그대로 두고 각인은 **기본 hidden**이라 실루엣을 건드리지 않는다. 8역할 GLB의 몸 높이가 S1과 소수점 4자리까지 같은 것으로 확인.
2. **큰 눈·창백함·부족 적응이 보이는가?** — 보인다(S1 유지). 이번에 더한 것은 그 대비다: 사람은 어두운 눈, 짐승은 밝은 눈.
3. **각인 3개가 겹쳐도 읽히는가?** — 읽힌다. 「3개 겹침」카드(지킨 자+발자국+빈 위장)에서 얼굴 흉터·가슴 이빨·허리띠가 각각 다른 높이에 있어 서로를 가리지 않는다. 부위를 8곳으로 쪼갠 결과다.
4. **짐승이 사람보다 가깝고 따뜻해 보이는가?** — 개 Idle이 사람 다리에 몸을 기울여 닿는다(`dog_lean.png`). 사람 소품에는 "닿는" 포즈가 하나도 없다. 눈 밝기도 짐승만 다르다.
5. **발 원점·키·+Z·클립이 맞는가?** — 맞는다. 짐승 3·공룡 3의 발 z가 전부 `±0.0000`, 키가 목표와 소수점 4자리까지 일치. 8역할은 발 z 0.0000, 클립 7종 유지. 정면은 전부 glTF +Z.

## 8. 미완·리스크

1. **기본 hidden이 GLB에 없다.** glTF 2.0의 한계다. 개발이 로드 직후 `imp_*`를 끄지 않으면 **모든 주민이 각인 8개를 전부 달고 나온다.** §3-1의 3줄이 반드시 들어가야 한다. (대안: 나중에 파츠만 분리 GLB로 빼는 방법도 있으나 드로우콜·로드가 늘어 지금은 한 파일에 담았다.)
2. **용량.** 8역할 합계 4.6 MB → **5.9 MB**. 주민 10명이 동시에 보이면 모바일에 부담이다. 줄이는 순서: 클립 7종→3종(약 −45%) → Draco 압축 → 소품 메시 병합.
3. **드로우콜.** 역할당 노드가 34~41 → **74~81개**로 늘었다. 각인이 꺼져 있으면 렌더 비용은 거의 없지만 씬 그래프는 커진다.
4. **짐승 Walk의 발 미끄러짐.** 제자리 애니라 이동 속도를 클라이언트가 보폭에 맞춰야 한다. 권장 속도: 개 1.2 m/s, 고양이 0.9, 까마귀 0.5(걸을 때).
5. **공룡 Attack/Death 없음.** 밤 육식 연출에는 Attack이 필요하다(스프린트 3).
6. **까마귀의 "어깨에 앉기"(C5) 미구현.** 사람 어깨 뼈에 붙이는 소켓 노드가 필요하다 — §9로 요청.
7. **역할 진화 표식 미구현.** `evo_<role>` 이름만 예약(§3-2). 역할 id 대응 확정 필요.
8. **sRGB→선형 미변환.** 기존 파이프라인 규약을 유지했다. 톤을 정식으로 손보려면 배경 에이전트와 함께 한 번에 바꿔야 한다.
