## 2. 막(acts) — 1막 풀 수치와 시뮬레이션

작업 중에 시나리오 S4-C 가 도착해 **사건 60장 전부가 파일에 `acts` 를 갖게 됐다.** 코드의 임시 분류표는 지금 한 장도 타지 않는다(지우지 않은 이유는 §6 이탈 2번).

```
전체 60장 / 파일에 acts 를 적은 카드 60장
  1막 풀 26장   접두어 {famine 1, drought 1, confusion 1, relic_cache 1, deep 22}
  2막 풀  4장
  3막 풀 38장   {육상 10 + tribe 21 + dino 4 + outside 3}
  1막 목표 24장 대비: +2      ← DECISIONS 2026-09-23 의 최소선 충족
```

추첨 시뮬레이션(막별 300방주 × 14일 = 4,200회, `storyteller.pick_event` 실물, 시드 `sim{n}|{day}`):
```
1막: 4200회 / 서로 다른 카드 26종 / 막 위반 0건 / 육상(dino·tribe) 카드 0회
     상위: deep_seam_mold 252 · confusion 249 · deep_jelly_bloom_seen 246 · drought 227 …
     한 번도 안 나온 카드: 없음
3막: 4200회 / 38종 / 막 위반 0건 / 심해(deep) 카드 0회
     상위: tribe_archive_reading_invite 202 · tribe_shelf_audit 185 · drought 170 …
     한 번도 안 나온 카드: 없음
```
**dev_S3 R7(1막에 육상 공룡·부족 카드가 섞이던 결함)은 닫혔다.** 반대 방향(3막에 심해 카드)도 0이다.

파일에 `acts` 가 없는 카드가 새로 들어오면: `deep_*`→[1], `dino_*`·`tribe_*`→[3], `events.json` 10장은 id 표(질병·굶주림·물·불신 = 전 막 공용), 그래도 모르면 **전 막 공용 + 표준출력 경고**. 안 나오는 카드는 없는 카드이므로 숨기는 쪽을 택하지 않았다(D4).

## 6. 적용한 교본 원칙

| 원칙 | 어디에 |
|---|---|
| **D7**(데이터가 규칙을 든다) | `acts` 를 코드 상수가 아니라 **스키마 필드**로 냈다. 시나리오가 값을 적자마자 코드의 임시 표가 통째로 무력해졌고 — 그게 정상 동작이다. 대사 `acts`·`airlock_in` 도 같은 방식(스키마 먼저, 값은 시나리오) |
| **D1**(규칙은 적게, 조합은 많게) | 막 구분은 새 시스템이 아니라 기존 추첨에 필터 한 줄이다. 거점 화면도 새 서버 개념 0 — 기존 `slot` 규약을 **다르게 그렸을 뿐**이라 index 와 한 방주를 공유한다 |
| **D2**(모든 숫자는 화면의 무엇으로) | 깊이를 숫자로 찍지 않고 **띠 + 구역 이름**으로 냈고, 아래로 지으면 띠가 자란다. 방의 기능은 색으로 읽힌다. `far_call_sec` 은 아직 화면이 없어 §7 R4 에 적었다 |

1. **D2 이탈 — 공기 게이지 값이 고정(0.82)이다.** 원정(공기 소모)이 없어 움직일 근거가 없다. 지시대로 UI 자리와 상태 필드만 만들었고 응답에 `fixed:true` 와 사유를 함께 실어 **다음 담당이 고정값을 진짜 값으로 오해하지 않게** 했다. 반대로 **깊이는 고정하지 않았다** — 아래로 증축했는데 깊이가 그대로면 화면이 거짓말을 한다(지시에서 벗어난 유일한 지점이고, 그 이유가 D2 자체다).
2. **PM 이 "지워도 된다"고 한 임시 분류표를 남겼다.** 60장 전부 파일에 `acts` 가 있어 지금은 한 장도 타지 않는다. 남긴 이유는 안전망이다 — `acts` 없는 `dino_*` 카드가 새로 들어오면 표가 없을 때 1막으로 샌다. 그 사고가 dev_S3 R7 이었다. 주석에 "현재 0장이 탄다"를 명시했다.
3. **정수실 색을 청록이 아니라 크림으로 했다.** `REF_CROSS_SECTION §5` 는 "연한 청록까지" 허용하지만 더 최신인 `REF_ART_FLAT_FOLK §5`(2026-09-26)가 **청록은 물에만**이라고 못 박는다. 최신 문서를 따랐다. 물이 화면에서 유일한 차가운 것이어야 대비가 산다.
4. **사운드 3건을 미뤘다**(§5). 오디오 계층이 없어 이번 스프린트 안에 검증까지 갈 수 없다. PM 이 허용한 범위.

## 7. 02_DEV §5 자가 검수 5문항

**1. 새 숫자가 화면의 무엇으로 보이는가?**
- `act`: 좌상단 배지 「1막 · 심해 유리돔」, 그리고 **오늘 오는 카드의 종류 자체**가 바뀐다(1막에서 공룡이 오지 않는다).
- 깊이: 왼쪽 아래 띠 + 구역 이름(무광층 → 해구 문턱), 방 상세의 「3층 · 깊이 120m」, 그리고 아래로 지을수록 화면이 검게 내려간다.
- 공기: 띠 1개(값 고정, §6 이탈 1).
- 스팟 좌표: 물속 등불 표식의 **위치**(깊은 곳일수록 아래).
- 아직 화면이 없는 숫자는 `far_call_sec` 하나이고 R4 에 적었다.

**2. 첫 3분 루프의 탭 수가 늘었나?**
0. `/base` 는 별도 URL 이고 index 의 스캔→카드→쪽지 도크를 건드리지 않았다. `/base` 안에서 증축은 **방 클릭 → 버튼** 2탭으로, index 의 증축 경로(3탭)보다 짧다.

**3. 같은 입력이면 같은 결과인가(시드)?**
그렇다. 사건 `uid|day`, 소문 `uid|spot|rumor`, 대사 `voice|seed|tag` 전부 유지했고 막 필터는 **후보를 줄일 뿐 시드 문자열을 바꾸지 않는다**. 주민의 방 배치도 난수가 아니라 슬롯 정렬 순서다(새로고침해도 같은 방에 있다). 시뮬은 `sim{n}|{day}` 고정 시드라 재현된다.

**4. 폰 가로 720px에서 손가락으로 조작 가능한가?**
390×844 세로로 확인했다(스크린샷). 거점 전체가 한 화면에 들어오고 가로 스크롤 0, 카메라 버튼 44×44, 증축 버튼 `min-height:44px`, 상세 패널은 폰에서 하단 시트로 바뀐다. 드래그 팬·핀치 줌은 `touch-action:none` + pointer 이벤트로 처리.

**5. 회귀 7항목 로그가 있는가?**
있다 — §4-3(스캔·건설·사건·주민·도감·소문/스팟 대조), §4-4(구버전 마이그레이션), §2(막별 추첨 시뮬 8,400회), §4-6(index·world 화면 회귀). 전부 실서버 HTTP 로그다.

## 10. 이 산출물이 게임을 더 재미있게 했는가 (TEAM 마지막 질문에 자답)
두 가지가 달라졌다.

**첫째, 1막이 1막이 됐다.** 어제까지 심해 방주에 육상 공룡이 찾아왔다. 세계가 30%쯤 거짓말을 하고 있었고, 그건 재미의 문제가 아니라 신뢰의 문제다. 지금은 4,200회를 돌려도 한 번도 새지 않는다. 그리고 이 구조 덕분에 육상 38장은 **버려지지 않고 3막에서 기다린다** — 콘텐츠를 지우지 않고 제자리에 놓은 것이다.

**둘째, 이 게임이 한 장으로 설명된다.** `dev_S4_base_1280.png` 한 장에 검은 물, 불 켜진 상자들, 그 안에서 움직이는 사람, 아래로 내려가는 빈 자리, 그리고 해구 쪽에 떠 있는 등불 하나가 있다. 설명 문장이 한 줄도 없다. P2 의 "30초 안에 이해되고"가 처음으로 스크린샷으로 성립했다(07 W6 의 이번 주 보여줄 것).

가장 아쉬운 것은 R3 다. 방은 다섯인데 사람은 셋이라 두 방이 비어 있다. 개미집의 쾌감은 "전부 뭔가 하고 있다"에서 오는데(REF §1-6) 지금 화면은 절반이 조용하다. 방을 늘리는 것보다 **사람이 느는 이유**를 만드는 것이 다음 재미다.
