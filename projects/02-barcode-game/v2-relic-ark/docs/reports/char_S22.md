## 3. 합성 규격 — 클라이언트 담당(aeb00832c0aeacab8)용
정본은 `static/art/chars/front/p2/meta.json` 의 `imprint_compose` 다(아래와 같은 내용).

**격자.** 모든 겹이 같은 셀(원화 64, `_x4` 256), 같은 3열 × 31행이다. **오프셋은 0**이다 — 행·프레임마다 위치가 이미 각 칸에 들어 있으므로 본체와 같은 (열, 행) 칸을 같은 자리에 그리면 된다. 행별 오프셋 데이터가 따로 필요 없게 만들었다.

**한 사람을 그리는 순서**(아래로 갈수록 위에 얹는다):
1. 본체 `src/<role>[_b].png`(체형 B 는 `_b`)
2. 머리 `hair/<role>_<body>/<hair>.png`
3. 얼굴: 머리가 `short` 가 아니고 얼굴이 `f0` 가 아니면 `faces/<role>_<body>/<hair>_<face>.png`, 아니면 `faces/<role>_<body>/<face>.png`(`combo_patch_rule`)
4. 잠수복 겹 `suit/<role>_<body>.png` — **원정(바깥)일 때만**
5. 각인 — 그 사람이 가진 것만, **별도 오프스크린 한 장**에 모은다:
   - 파일은 `imprints/role/<role>_<body>/<id>.png` 가 있으면 그것을 쓴다.
   - 없으면 몸 모양 폴더를 쓴다: 어른 A = `imprints/`, 어른 B = `imprints/b/`, 아이 A = `imprints/kid/`, 아이 B = `imprints/kid_b/`. 파일 이름은 `<id>.png` 다.
6. 5에서 모은 한 장을 `imprints/rolemask/<role>_<body>.png` 로 지운다(`globalCompositeOperation = 'destination-out'`, 같은 칸).
7. 지운 각인 한 장을 본체 위에 그린다(`source-over`).

**주의**
- 가림판은 **각인 한 장에만** 건다. 본체 캔버스에 걸면 모자·도구가 지워진다.
- 좌우 반전: 옆모습 행(오른쪽 원본)·방별 작업(왼쪽 원본)을 반전할 때는 1~7 전부에 같은 반전을 건다(셀 가운데 축).
- 배율: `_x4.png` 를 쓰거나 x1 을 NEAREST 정수 확대한다(`image-rendering: pixelated`). 방 ×3 화면이면 x1 × 3.
- 각인이 몸 앞 물건에 가려지는 프레임(132프레임)은 시트 칸이 이미 비어 있다. 클라이언트가 따로 할 일은 없다.
- `water_memory`(이마 젖은 머리)는 머리 위에 얹히도록 설계된 것이라 머리 패치 **다음**(5단계)에 그리면 맞다.
- 각인 위치는 체형 A/B/아이마다 다르다. 반드시 체형 폴더를 골라야 한다(역할만으로 고르면 틀린다).

### 6-1. 내 쪽 결함 하나 — 고쳤다
`imprints/rolemask/*.png` 를 **회색조(L) PNG** 로 냈었다. 브라우저 `destination-out` 은 알파만 보는데, 회색조 PNG 는 알파가 전부 255 라서 **모든 각인이 지워진다.** 규격(§3)은 "흰 판"이라고 했는데 파일 형식이 그와 달랐다.
- 32파일을 **흰색 RGBA(알파 = 가림 칸)** 로 다시 냈다. 내용은 같고 형식만 바뀌었다.
- 생성기도 고쳤다: 저장을 RGBA 로 바꾸고, 확인 합성이 알파를 읽게 했다. 다음 실행도 같은 파일을 낸다.
- 브라우저에서 같은 파일로 클라이언트 순서를 재현해 셌다. 가림판을 지난 뒤에도 각인이 남는다(예: 베일 28 → 23~27칸, 장비에 걸린 칸만 빠진다). 0이 되는 것은 설계상 먼 쪽 각인뿐이다: 옆모습의 목덜미·장갑·위팔, 뒷모습의 관자놀이·광대.

### 6-3. 읽히는가 — 판정
- **1280 기본 배율(z 0.5, 원화 1px ≈ 화면 1.5px)**: 거의 안 보인다. 각인 하나가 원화 3~6px라 화면에서 4~9px짜리 점 몇 개가 되고, 옷 무늬와 구별되지 않는다. 큰 베일만 겨우 보인다(`char_S22_base1280_crop.png`).
- **844 맞춤(z 0.36, ≈ 1.08배)**: 각인이 화면 1~3px. **픽셀로는 원리적으로 못 읽는다.**
- **방 ×3 이상(z ≥ 1)**: 읽힌다. 몸에 붙고 장비 밑으로 숨는다. 요리사 베일·목걸이와 정찰병 흉터가 보인다.
- 방 불빛 곱하기(`#fae6c8`)는 본체에도 똑같이 걸리고 흰빛에 가까워 대비를 거의 바꾸지 않는다. **원인은 틴트가 아니라 크기다.**
- 비교 그림 `char_S22_readability.png`: 각인 없음 / 지금 규격 / 제안 P2 를 네 배율에 나란히 놓았다.
  - P2 는 먼 거리용으로 각인을 굵게 하고 어두운 테를 두른 판이다.
  - ×3 에서는 조금 낫다. ×1.5·×1.08 에서는 여전히 안 보이고, 테가 얼굴에 닿을 위험이 있는 레이어가 하나 더 생긴다. **채택하지 않는다.**

### 6-4. 제안 — 먼 배율에서는 머리 위 표식
`imprints/pips.png`(9×9 × 12, 손으로 찍은 도트) · `pips_x2.png` · `pips.json`. 생성기는 `tools/gen_imprint_pips.py`.
- 각인마다 그 각인 색의 원 + 어두운 테 + 부위를 가리키는 작은 모양이다(흉터 사선·팔띠 두 줄·목걸이 이빨·고리·물방울·금·울림 물결 등).
- 규칙(`pips.json rule`):
  - **z < 1** 일 때만 머리 위에 가진 각인 1~3개를 가로로 늘어놓는다.
  - **화면 픽셀 ×2(18px) 고정**이다. 카메라 배율을 곱하지 않는다.
  - 방 불빛 틴트를 곱하지 않는다.
  - z ≥ 1 에서는 끈다. 그때는 몸 위 각인 레이어가 보인다.
- 목업 `char_S22_pips_mock1280.png` 는 1280 실화면 캡처 위에 얹은 것이다. 세 사람의 각인 셋이 색·모양으로 갈린다. 844 에서도 크기가 같으므로(화면 픽셀 고정) 똑같이 읽힌다.
- GROWTH_AND_MYTH §1 「외형이 바뀐다」: 가까이에서는 몸이 바뀌고(레이어), 멀리서는 표식이 그 사람이 겪은 일을 알린다.
