## 2. 스키마 설명

### 2-1. `data/imprints.json`

```
{ "_rules", "_match", "_effect_keys", "_role_evolution", "imprints": [ … 8종 … ] }
```

각인 1개의 구조:

| 필드 | 뜻 |
|---|---|
| `id` / `name` | `spore_mark` / 「포자의 표식」 |
| `crisis` / `crisis_ko` | 위기 **종류** 키. 주민의 `crises[]`에 이 키가 쌓이고, 한 번 쌓인 종류는 다시 겪어도 사람을 바꾸지 않는다 |
| `trigger` | `{type, event_ids[], id_prefixes[], factions[], tribes[], counter_tags[], flags[]}` |
| `visual` | `{keyword(영문 아트 지시), ko(외형 변화), line("{name}의 …" 연출 문장)}` |
| `effect` | 서버 효과. 숫자는 합산, `counter_bonus`는 태그별 자동 대항 확률 가산 |
| `cost` | `{ko(대가 설명), effect(대가의 수치 효과)}` — 능력과 대가를 **같이** 합산한다 |

**위기 판정(사건 카드 → 각인)** 은 단계 점수로 한다. `flags`(4) > `event_ids`·`id_prefixes`(3) > `factions`·`tribes`(2) > `counter_tags`(1). 같은 단계에서 여러 개가 맞으면 배열 앞선 것이 이긴다. 긍정 사건(`positive:true`)은 각인을 주지 않는다.

**부여 규칙** (`_rules`): 첫 경험만 · 같은 각인 1회 · 최대 3개 · 3개째에서 `role_evolved:true`(+`evolved_ko`) · 부상 여부 무관(죽지만 않으면 받는다).

8종 매핑 현황:

| 각인 | 지금 붙는 사건 | 비고 |
|---|---|---|
| 포자의 표식 | `infection`, faction `mycel`, 태그 `해독` | 동작 확인 |
| 빈 위장 | `famine`, 태그 `보존` | 동작 확인 |
| 지킨 자 | `raid_scavs`, `machine_patrol`, faction `scavs`/`machine`, 태그 `방어` | 동작 확인(`cold_snap`도 `방어`로 걸린다 — 의도된 폭) |
| 햇빛의 기억 | 태그 `탐사`, `surface_*`/`expedition_*`, flag `expedition_returned` | `tribe_greenhouse_threshold_guide` 실패 시 붙음 |
| 빈 자리 | flag `ally_crisis` — **사건으로 누가 다쳤을 때 안 다친 주민에게** | 서버가 flag를 만든다. 동작 확인 |
| 발자국 | `dino_*`/`saur_*`, flag `dino_escaped` | **아직 해당 사건 없음** |
| 갚은 자 | `tribe_flame_debt*`, `debt_*`, flag `flame_debt_cleared` | 동작 확인 |
| 물의 기억 | `spot_*`/`healing_*`, flag `healing_spot_found` | `on_counter.spot_clue`가 있으면 서버가 flag 생성 |

### 2-2. `data/events_schema.json`

`events.json`·`events_tribes.json` 공통. 배열 하나에 사건 카드 객체. 필수: `id, name, faction, severity, text, counter_tags, counter_room, on_fail, on_counter, timer_sec`. 선택: `tribe`, `positive`, `dialogue`, `note`.

- `id`: `^[a-z][a-z0-9_]{2,39}$`, **전 파일 통틀어 유일**. 접두어가 각인 판정에 쓰이므로 함부로 바꾸면 각인이 안 붙는다.
- `tribe` enum: `wayfarer, shelf, flame, white, archive, greenhouse, tower` (길손·진열대·불꽃·하얀·서고·온실·탑).
- `faction` enum에 `tribe, gardener, reader` 추가(클라이언트 `FAC_KO`도 같이 갱신).
- `counter_room` enum: `pantry, well, infirmary, library, rock, lot, null`.
- `on_fail`/`on_counter`(outcome): 자원 11종 + `injured`, `resident` + 통과형 `capture`(string), `free_pack`(int), `spot_clue`(string), `flag`(string)/`flags`(array). `additionalProperties:false`이므로 새 키가 필요하면 개발에 요청.

검증: `jsonschema`가 설치돼 있어 `events.json`(10장)·`events_tribes.json`(21장) 모두 통과 확인.

### 2-3. 신뢰 (최소형)

주민마다 `trust: {상대 id: 0~100}`, 시작 0. 사건 해결 시 방주 주민 **전원 쌍**에 `countered → +10`, `실패 → −5` (0~100 클램프). 대화·선물로는 오르지 않는다(`docs/TRUST_AND_COMPANIONS.md` §3). `public_state.trust = {주민id: {avg, to}}`로 노출.

## 4. PM 추가 요청 3건 처리 여부

1. **`FAC_KO`에 `tribe:'부족'` + `TRIBE_KO` 추가, 쪽지 머리말 부족 우선 표기** — 완료. `static/app.js` 상단에 `TRIBE_KO` 정의, 쪽지 헤더가 `ev.tribe`를 우선해 "불꽃 부족 · 심각도 2"로 출력(스크린샷 `dev_20260920_event_imprint.png`로 확인). `gardener`/`reader`도 미리 넣어 뒀다.
2. **`events_schema.json`에 `tribe` enum과 `capture`/`free_pack`/`spot_clue` 명시** — 완료. `tribe`는 7 슬러그 enum(선택), outcome에 `capture`(string)·`free_pack`(int)·`spot_clue`(string)·`flag`/`flags` 명시. `spot_clue`가 있으면 서버가 `healing_spot_found` flag를 만들어 「물의 기억」 후보로 쓴다.
3. **`load_events()` 병합** — 완료(확인 요청대로 유지). 추가로 필수 필드 누락 카드는 건너뛰고 `[storyteller] … 필수 필드 없음 […]`을 표준출력에 남기도록 방어 처리. 현재 21장 전부 통과.

첫 접촉 카드 1회 소모 플래그, `dialogue` `when` 훅은 지시대로 **손대지 않았다**(스프린트 2).

## 6. 미완 · 리스크

1. **예약 효과 필드** — `light_cap, power_cost, drifter_rate, night_production, production_penalty, morale_heal_others, self_morale_recover, hoard_risk, morale_cap, food_daily, dino_predict, spot_guide, night_watch`는 `role_effects()`에 **합산까지만** 되고 아직 게임 규칙에 물리지 않았다(일일 소비·사기 상한·원정·전기 구매 시스템 자체가 Phase 0에 없다). 규칙이 생기는 스프린트에서 연결해야 한다.
2. **각인이 전원에게 동시에 붙는다** — Phase 0에는 "그 사건에 나선 사람" 개념이 없어 방주 주민 전원이 같은 위기를 겪은 것으로 처리했다. 시작 3인이 사건 3번이면 전원 역할 진화라 성장이 너무 빠르다. 스프린트 2에서 **참여자 선별**(자동 대항한 주민·부상자·아이 우선 등)이 필요하다. 지금은 "계단이 실제로 보이는가"를 확인하기 위한 최대치 설정이다.
3. **「발자국」은 아직 트리거 사건이 없다** — 공룡 조우 카드(`dino_*`)가 나와야 붙는다.
4. **역할 진화 이름이 임시다** — `_role_evolution`의 8개 이름은 개발이 붙인 자리표시다. 성경상 "진화는 부족 신화에서 이름을 받는다".
5. **`cold_snap`(한파)이 「지킨 자」로 걸린다** — `방어` 태그 단계(1) 매칭 때문. 의미가 조금 헐겁다. 한파 전용 위기 종류를 만들거나 태그 매칭을 빼는 선택이 필요(표가 8종으로 고정돼 있어 지금은 열어 뒀다).
6. **신뢰가 UI에서 숫자 하나뿐** — 쌍(pair)별 값은 API로 나가지만 화면에는 평균만 보인다. 「함께 넘긴 자」 각인(사람 신뢰 전용)도 표 8종 밖이라 넣지 않았다.
