### 1-1. 개봉 연출(희귀도 사다리 다섯 칸)
뒷면(`card_back.png`)으로 날아옴 → 희귀도만큼 차오름(`charge_glow.png`를 `charge_tint`로 물들임) → 뒤집힘 → 기존 줄(얻은 것·선반·닦기·바다 무늬·첫 만남·가문·바람·상자·목소리)이 지금처럼 나온다.

| 희귀도 id | 화면 이름 | 차오름 | 실측(1280, 페이지 안 performance.now) | 실측(844, CPU 4배 느리게) |
|---|---|---|---|---|
| common | 흔함 | 없음(잠깐 멈춤) | 829 ms | 863 ms |
| uncommon | 쓸만함 | 은은한 빛 | 1029 ms | 1047 ms |
| rare | 귀함 | 센 빛 + 짧은 흔들림 | 1280 ms | 1320 ms |
| epic | 진귀함 | 센 빛 + 흔들림 + 옅은 빛살(청록) | 1546 ms | 1565 ms |
| legendary | 전설 | 긴 차오름 + 빛살 + 흔들림 + 등불색 번쩍(+ `sfx_lantern_on`) | 2029 ms | 2044 ms (상한 2.2 s 안) |
| (닦기) | — | 뒤집지 않음, 빛 한 줄 + 도장 | 699 ms | 750 ms |
| (건너뛰기) | — | 전설을 0.3 s에 탭 | 313 ms에 앞면·단추 | 356 ms |

- 움직임은 Web Animations의 transform·opacity만. 박·바다 무늬도 큰 자식 층을 transform으로 미는 방식(배경 위치 애니메이션 없음).
- 박(귀함·진귀함 `foil_rare.png`, 전설 `foil_legendary.png`)과 바다 무늬(`foil_sea.png`)는 L 마스크라 CSS mask가 안 먹는다 → **마스크를 multiply로 곱한 묶음을 screen으로 얹는다**(메타 draw_order 문구 그대로).
- 박은 마우스/손가락 위치를 따라 움직이고 카드가 살짝 기운다. 기울기 센서(deviceorientation)가 오면 그것으로(iOS 권한 창은 띄우지 않는다). 둘 다 없으면 천천히 저절로 움직인다.
- 닦기(같은 바코드를 다른 날 다시 찍음): 앞면이 바로 뜨고 빛이 한 번 지나가며 도장 「닦였습니다」(단계가 오르면 「닦였습니다 · 한 번 닦음」). **오늘 세지 않은 재스캔에는 「닦였습니다」를 찍지 않는다**(서버 polish.ko와 같은 규칙: 거짓 문장 금지) → 「오늘은 이미 닦음」 / 최대면 「윤이 남」.
- 찍기로 열린 상자: 기존 상자 문장은 그대로, 앞에 작은 상자 그림의 뚜껑이 들리고 「열림」이 톡 튄다.
- `prefers-reduced-motion: reduce`: 날아옴·뒤집기·차오름·빛 전부 없이 즉시 앞면, 박·물결·「열림」은 멈춘 그림.

### 1-2. 희귀도 틀이 나오는 곳 셋
찍기 카드, 선반 물건을 눌렀을 때의 카드(새 「누른 유물」 화면 — 지금까지는 토스트 한 줄뿐이었다), 도감(칸 테두리 색 + 박, 누르면 같은 카드). **희귀도 이름은 글자로 함께 나온다**(카드 설명 띠 첫 줄 「식품 · 귀함」, 도감 칸 이름표 `rmk`, aria-label). 틀 그림의 점 1~5개가 색 외의 두 번째 단서다.

## 4. 교본 적용
- **D2 모든 숫자는 화면의 무엇으로**: 희귀도가 틀·점·박·차오름 길이로 보인다. 닦기 단계도 도장으로.
- **D5 첫 3분 루프**: 탭 수 증가 0. 흔함은 0.8 s로 기존(약 1.15 s 뒤 단추)보다 빠르다. 전설도 2.0 s, 탭하면 즉시.
- **D6 결정성**: 연출은 서버 응답의 희귀도만 읽는다. 같은 바코드면 같은 카드·같은 연출.
- **D8 성능**: transform·opacity만, 메인 스레드 프레임 최악 24 ms(1280), CPU 4배에서 개봉 시간 오차 +2~5%. 
- **P3 감정의 가속도**: 흔함은 빠르게 넘기고, 드문 것일수록 「멈춤 → 차오름 → 터짐」의 대비가 커진다.
- **P1 원형**: 세트 수집·뒤지기(개봉 도파민, 벤치마크 표의 TCG 포켓 「개봉 도파민」).
- **P5**: 가챠 연출이지만 유료 뽑기가 아니다. 스캔은 무료이고 희귀도는 바코드로 정해진다.
- **TEXT_VOICE**: 새 화면 글은 이름표(「창고 보기」, 「열림」), 도장(「닦였습니다」·「오늘은 이미 닦음」), 안내(「아무 데나 누르면 닫힙니다」)뿐. 관리실 방송 문장은 서버 문장 그대로.
- **UI_SIMPLE §2-3**: 누른 것만 작은 카드로. 선반 탭은 토스트 대신 카드, 방 카드는 단추 하나로.
- **이탈**: 선반 물건 탭이 예전에는 토스트 + 창고 방 카드를 바로 열었는데, 이제는 유물 카드를 먼저 보이고 「창고 보기」로 방 카드를 연다(탭 1회 증가는 선반 → 방 카드 경로에만). 요구 2(선반에서 유물 카드)를 지키려면 둘 중 하나가 먼저여야 해서 유물을 앞에 두었다.

## 5. 자가 검수(02_DEV §5)
1. 새 숫자가 화면의 무엇으로 보이는가? 희귀도(서버 id)가 틀·점·글자·연출 길이로 보인다. 새 숫자는 없다.
2. 첫 3분 루프의 탭 수가 늘었나? 아니다. 개봉은 기다림 없이 탭으로 건너뛸 수 있고 흔함은 더 짧아졌다. 선반 → 방 카드 경로만 1탭 늘었다(§4 이탈).
3. 같은 입력이면 같은 결과인가? 그렇다. 연출은 응답의 희귀도·변형·닦기 값만 쓴다.
4. 폰 가로 720px에서 손가락 조작? 844×390에서 카드 왼쪽·글/단추 오른쪽, 단추 44px, 어디를 눌러도 건너뛰기·닫기.
5. 회귀 로그? §3: 실제 찍기·닦기·선반·도감·콘솔 0·중괄호 0·selfTest·API 차집합 불변. 건설·사건·주민 코드는 건드리지 않았다(그 화면 경로는 이번에 다시 돌리지 않았다).

07 자가 검수: 플레이어가 보는 새 그림은 S16-A 배경의 `tools/gen_cards.py` 절차 생성물(메타 `_note`: 생성 AI 없음)이라 공개표 추가 대상이 아니다. 보여 줄 클립 재료: 전설 개봉 스크린샷 연속(`dev_S16_ct_legendary_*`).

## 6. 미완·리스크
- **희귀도 한국어 이름과 카드 번호는 PM 결정 대기**(§2).
- 폰 가로(844×390)에서 카드 설명 띠 글자가 약 9.8 px로 작다. 카드 비율·틀 그림이 고정이라 더 키우려면 설명 띠를 2줄로 줄이거나 카드를 화면 높이 가득 써야 한다.
- 개봉 중에도 거점 캔버스는 계속 그린다. CPU 4배 느린 조건에서 메인 스레드 rAF가 약 40 fps(대부분 거점 그리기 몫). transform 애니메이션은 컴포지터에서 돌아 눈에 띄는 끊김은 없었지만, 실제 중급 폰 실측은 아직 없다. 필요하면 찍기 창이 열린 동안 거점 그리기를 멈추는 것을 다음에 검토.
- 실기 기울기 센서(안드로이드) 동작은 헤드리스로 확인하지 못했다.
- 플레이테스트 도구 `tools/playtest_lib.py ui_scan`은 찍고 2.7 s 뒤 `#rcFront` 글을 읽는다. 전설 연출(2.0 s)보다 길어 그대로 동작한다. 다만 카드 앞면 글 구성이 바뀌었다(태그 칩 대신 「갈래 · 희귀도」 줄).
- ★ 배포 전 제거 목록: `?cardtest=1` 시험대(`base_cards.js` §5, `base.js K_cardTest`), `window.ARKCARDS`.
