### 1-2. 이동 체계 — 길 계산과 그리기를 나눴다
**`movement.js`(맵 무관)** — 단위는 층(정수, 음수 가능)·가로 위치(m)·시간(초)뿐이다.
- `route(graph, from, to)`: 출발·도착·(엘리베이터×층) 정류장을 노드로 둔 다익스트라. 결과는 `walk`/`ride` 구간 목록. **엘리베이터 여러 대, 갈아타기, 격벽(`walls`: 그 층의 그 위치는 걸어서 못 지남)**까지 처리. 못 가는 곳이면 `jump`(D9 직진 폴백).
- `simulate(graph, moves, cars0)`: 여러 명의 시간표. 규칙은 넷.
  1. **걷기 시작할 때 부른다** — 사람이 문 앞까지 걷는 동안 차가 미리 온다.
  2. **가까운 쪽 먼저** — 다음에 태울 사람은 가장 빨리 태울 수 있는 사람(차가 4층에 있으면 0층보다 4층 사람 먼저).
  3. **같은 층·같은 방향끼리 정원만큼 같이 탄다**(정원 3 — 척추 폭 70px ≈ 1.9 m, 한 사람 0.6 m). 넘치면 다음 차. **문 잡아 주기 2초**: 이미 오고 있는 사람은 기다렸다 같이 간다.
  4. 같이 타고 **각자 층에서 내린다**(방향 순서로 들름, 정류 때마다 문 0.5 s).
- 자세: `walk → elevator_wait → elevator_ride → walk`. 기다리는 사람은 온 쪽 문 앞에 **줄을 선다**(뒷사람은 0.5 m씩 뒤에).
- `sample(plan, t)`, `carAt`: 시간 → {층(소수), 가로, 자세}. 엘리베이터 칸의 층도 시간의 함수로 준다.
- `createTraffic`: 화면이 쓰는 얇은 껍질. 이전 배차의 차 위치·빈 시간을 이어받아 **배치가 연달아 와도 차가 하나로 움직인다.** 움직이는 중에 또 옮기면 지금 자리에서 다시 출발.
- `selfTest()`: 아래 §2-1의 시험. 아무 페이지 콘솔에서 `ArkMove.selfTest()`로 다시 돌릴 수 있다.

**`base.js`의 배치 어댑터 `MOVE_ADAPTER`(맵마다 다름)** — 함수 셋: `graph()`(척추 = 엘리베이터 1대, 가로 0 m, 홀 -1층 ~ 맨 아래층) · `nodeOf(slot|'hall'|'out', i, n)` · `toWorld(floor, x)`.
- 서버 상태를 받을 때(`apply`) 사람의 자리(방·홀·밖)가 바뀌었으면 그 사람을 옮긴다. **배치의 정본은 여전히 서버**이고 이동은 연출이다. 새로고침하면 바로 그 자리. 연출이 실패해도 상태 반영은 이미 끝난 뒤다(try/catch + `console.error`, D4).
- 엘리베이터 칸은 척추 안의 얇은 틀 하나만 그렸다. 진짜 엘리베이터 그림은 새 맵이 정해진 뒤 그 위에 올린다(결정 로그 그대로).

### 1-3. 방 안의 일
- 배치된 사람은 **그 방의 작업 동작**(`work_<방>` → 없으면 `work` → `idle`)을 반복한다. **10~20초에 한 번**(사람마다 주기가 다름, id 해시로 결정적) 2.4초 동안 **쉬거나 방 안에서 몇 걸음 옮긴다**(`roomLife`). 불 꺼진 방에서는 손을 놓고(idle), 부상자는 `hurt`.
- 막 도착한 사람은 1.2초에 걸쳐 제 자리로 걸어 들어간다(도착 순간 순간이동 없음).
- **클립은 `front/p2/meta.json`의 rows·frames·anim_seconds에서 읽는다.** 시트에 그 행이 실제로 있을 때만 쓰고 없으면 사슬을 따라 내려간다. 캐릭터 담당이 오늘 넣은 `work_generator`·`work_storage`·`elevator_wait`·`elevator_ride`를 **코드 수정 없이 자동으로** 쓰고 있다(`dev_S11_6_room_work.png`: 창고는 상자, 발전실은 렌치).

## 3. 어댑터만 바꾸면 새 맵에 붙는다 — 어떻게 보장했나
1. **경계가 코드에 있다.** `movement.js`에는 `rectOf`·`cam`·`px`·`slot`이라는 말이 한 번도 나오지 않는다. 입력은 `{floor, x}`와 엘리베이터 목록뿐이고, 출력도 `{floor, x, pose}`다. 화면에 닿는 것은 `base.js`의 `MOVE_ADAPTER` 세 함수가 전부다.
2. **지금 맵에 없는 모양을 시험으로 먼저 돌렸다.** 지금 척추 맵은 엘리베이터 1대뿐인데, 단위 시험은 **엘리베이터 둘(가로 0 m·20 m), 일부 층만 다니는 엘리베이터와 갈아타기, 격벽으로 막힌 층**을 돌린다. 네 컨셉의 형태가 여기에 들어간다:
   - M2 절벽 · M4 수몰 탑: 층이 많고 통로가 한두 개 → `shafts` 1~2개
   - M1 침몰선: 갑판이 칸막이로 나뉨 → `walls` + 칸마다 다른 엘리베이터/계단 → 갈아타기
   - M3 고래 낙하: 가로로 긴 등뼈 → 같은 층 긴 걷기 + 짧은 수직 통로 여럿
3. **맵이 정할 값은 전부 어댑터 쪽에 있다**: 통로 위치·층 범위·정원·속도·문 시간·줄 서는 거리(`doorGap` — 통로 폭이 맵마다 달라 엘리베이터마다 받는다)·걷기 속도. `movement.js`의 `DEF`는 기본값일 뿐이다.
4. **새 맵에서 할 일**: `MOVE_ADAPTER.graph()`에 통로를 적고, `nodeOf()`에 방이 몇 층 어디인지, `toWorld()`에 층·가로를 화면 좌표로. 그리고 `drawCars()`의 틀 그림을 그 맵의 엘리베이터 그림으로. `movement.js`·`trackMoves`·방 안의 삶·클립 선택은 그대로다.
5. **남은 결합 하나(정직하게)**: 가로 화면에서 사람이 왼쪽으로 걸을 때 옆모습 반전이 필요해지면 `sample()`이 이미 돌려주는 `facing`을 `drawPerson`이 써야 한다. 지금 도트는 정면이라 쓰지 않았다.

## 4. 적용한 교본 원칙
- **D2 모든 숫자는 화면의 무엇으로 보인다**: 능력치 숫자가 그 방의 등불색 칸·특이점 밑줄·드래그 중 숫자로 **배치 판단의 근거**로 보인다. 엘리베이터 대기도 숫자가 아니라 문 앞 줄로 보인다. — **이탈**: RESIDENT_STATS §5의 "숫자를 크게 쓰지 않는다"는 사용자 지시로 철회됐다(DECISIONS 2026-10-03). 숫자는 크게 쓰되 특이점 문장은 그대로 주인공으로 남겼다.
- **D1 규칙은 적게**: 이동 규칙 넷(먼저 부르기·가까운 쪽 먼저·같은 방향 정원만큼·문 잡아 주기)으로 줄 서기·같이 타기·갈아타기가 모두 나온다.
- **D4 실패는 서사, 막힘은 버그**: 이동 계산이 실패해도 상태 반영은 끝난 뒤이고 에러는 콘솔에 남는다. 작업 중 실제로 한 번 이 장치가 숨은 결함(여러 층 정차 시 null)을 잡았다 → 고치고 시험 3c로 막았다.
- **D6 결정성**: 시간표와 방 안의 삶이 id 해시로 결정적이다(시험 7).
- **D7 데이터가 규칙을 든다**: 자세는 `meta.json` rows에서 읽는다 — 캐릭터 담당의 새 행이 코드 수정 없이 켜졌다.
- **D9 길 찾기는 단순 그래프, 실패 시 직진 폴백**: 다익스트라 + `jump` 폴백.
- **W2 작게 만들고 눈으로 확인**: 연속 스크린샷과 배차 기록으로 확인했고, 보면서 셋을 고쳤다(먼저 부르기·가까운 쪽 먼저·문 잡아 주기, 줄 자리를 척추 밖으로).
- **P3 감정의 가속도 / 공통 §3-2 원형 '둥지 만들기·키우기'**: 개미집 관찰의 쾌감이 생긴다 — 내가 옮긴 사람이 걸어가서 차를 기다리고 내려가서 일한다.

## 5. 자가 검수 5문항(02_DEV §5)
1. **새 숫자가 화면의 무엇으로 보이는가?** 능력치는 칩 숫자 + 그 방에 유리하면 등불색 + 특이점 밑줄 + 갈 곳 목록/드래그 중 숫자. 이동 시간은 걷기·줄·칸의 움직임으로.
2. **첫 3분 루프의 탭 수가 늘었나?** 늘지 않았다. 배치는 여전히 드래그 한 번(또는 탭-탭)이고 서버 반영은 즉시다. 이동은 기다리지 않아도 되는 연출이다(배치 효과는 놓는 순간 적용).
3. **같은 입력이면 같은 결과인가?** 그렇다. 시간표·방 안의 삶 모두 결정적(시험 7). 서버 판정은 바뀌지 않았다.
4. **폰 가로 720px에서 손가락으로 조작 가능한가?** 844×390에서 숫자 줄이 한 줄(28px), 갈 곳 버튼은 기존 44px 그대로. 이동 중인 사람은 잡을 수 없다(도착하면 다시 잡힌다).
5. **회귀 7항목 로그가 있는가?** §2-3. API 7항목 + 화면 회귀(습격·찍기·선반·열쇠) + 콘솔 에러 0.

## 6. 미완·리스크
- **이동 중에 습격 판정이 나면** 판정은 서버 기준(이미 그 방에 있음)인데 화면에서는 아직 걸어가는 중이다. 최대 약 15초 차이. 지금은 연출로 허용했고, 거슬리면 "접촉" 버튼을 누를 때 이동을 빨리 감기로 끝내는 방법이 있다.
- 정원 3·한 층 0.9초·문 0.5초·걷기 1.3 m/s는 개발 초안. 사람이 많아지면(10명 이상) 대기가 길어질 수 있다 — 새 맵에서 통로를 둘 이상 두는 것으로 푸는 것을 권한다.
- 가는 길에 다른 층에서 같은 방향 손님을 태우는 것(중간 승차)은 하지 않는다. 체계가 맞는지가 이번 목적이라 단순하게 뒀다.
- 엘리베이터 칸은 임시 틀 그림이다(새 맵 확정 후 그 맵의 그림으로).
- `ROOM_STAT` 12종 표는 개발 초안이다(밸런스 확인 요청).
- ★ 검수용 읽기 창 `ARKBASE.moving()/car()/clips()/moveLog()`를 열었다 — 배포 전 제거 목록.
