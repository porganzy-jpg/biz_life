## 1. 게임 한 장 요약

**한 문장**: 깊고 검은 물속 유리돔에서 살아남으며, 현실의 바코드를 찍어 바다가 200년간 보관한 물건을 건져 올리고, 해구 쪽으로 내려가며 방주를 키우는 게임.

**3막 구조**

| 막 | 무대 | 상태 |
|---|---|---|
| 1막 | 심해 유리돔 (무광층) | **지금 만드는 중** |
| 2막 | 침수 지하철 터널 | 설계만. 카드 4장 |
| 3막 | 지상 쇼핑몰 잔해, 일곱 부족 | **이미 동작함**(스프린트 1~2 자산) |

**핵심 루프 다섯 동사**: 보다 → 나가다 → 돌아오다 → 커지다 → 찾아오다.
`docs/SCRIPT_first_10min_deep.md`가 이 다섯을 10분 안에 한 바퀴 돌린다.

**세 개의 기둥**
1. **거점 관찰과 증축** — 개미집을 들여다보는 쾌감. 성장 방향은 **아래**(해구 쪽).
2. **바코드 = 유물** — 현실의 물건을 찍으면 결정론적으로 같은 유물이 나온다. 이 게임만의 훅.
3. **대항 카드** — 밤마다 오는 사건을 카드와 방과 사람으로 막는다.

## 3. 방법론 — 이 프로젝트가 실제로 굴러가는 방식

이 방식이 두 스프린트 연속으로 통했다. 바꾸지 말 것.

### 3-1. 여섯 에이전트와 파일 소유권
| 에이전트 | 소유(쓰기) |
|---|---|
| PM | `docs/TASKS.md`, `docs/DECISIONS.md`, `docs/reports/` |
| 시나리오 | `docs/*.md`(성경), `data/` **내용** 파일 |
| 개발 | `server.py`, `engine/`, `static/*.js|css|html`, `data/*_schema.json` |
| 배경 | `tools/blender_iso|scenes|section.py`, `art_raw/`, `static/art/`(배경), `static/models/`(방·씬) |
| 캐릭터 | `tools/blender_chars*|render_sprites.py`, `static/art/chars`, `static/models/chars` |
| 사운드 | `audio/`, `tools/gen_audio*.py`, `static/audio/` |

**규칙 셋**
1. 남의 파일은 **읽기만**. 고쳐야 하면 `docs/TASKS.md` 요청함에 한 줄. PM이 중계한다.
2. 개발이 데이터 내용을 바꿔야 하면 파일을 고치지 말고 **런타임 우선 병합**(파일이 오면 파일이 이긴다). 이 기법으로 충돌 0건을 유지했다.
3. 스키마는 개발이, 값은 시나리오가.

### 3-2. PM 검수는 읽는 게 아니라 다시 해 보는 것
보고서를 믿지 않는다. 실제로 한 것들:
- 서버에 직접 요청해 1막 카드 풀에 육상 카드가 섞이는지 확인(0건)
- GLB의 JSON 청크를 파싱해 뼈·클립·정점 높이 확인
- 렌더 이미지를 직접 열어 보고 명도·색·실루엣 판정
- 오디오의 스펙트럼·포락선·자기상관을 계산해 안/밖 대비 판정
- Playwright로 화면을 열어 콘솔 에러와 레이아웃 확인

**이 검수로 잡은 실제 결함**: 공룡 카드 미병합, 각인이 전원에게 붙던 밸런스 결함, 소문 4곳이 열리는 순간 읽을 줄이 0이던 문제, 파사드 방위 반대, 물 z-파이팅.

**PM도 틀린다 — 두 번 겪었다.**
- 오디오 1차 검수에서 광대역 지표로 재는 바람에 "안 고쳐졌다"고 판단할 뻔했다. 저역이 에너지의 90%라 디테일이 안 잡힌 것.
- 데이터 검수에서 세 건을 결함으로 잡을 뻔했다. 파일이 중첩 구조인데 최상위만 봤고, 금지어가 걸린 곳이 **그 단어를 금지한다고 적어 놓은 규칙 필드**였다.

- 화풍 레퍼런스를 **검색 썸네일만 보고** 원리를 뽑았다. "얼굴은 최소, 코·입 없음"이라고 썼는데 실제 원고에는 눈썹·입·주근깨·홍조가 다 있었다. 그 한 줄이 캐릭터를 인형으로 만들었다.

→ **검수 규칙 넷**: (가) 측정이 기대와 다르면 대상이 아니라 측정을 먼저 의심한다. (나) 스캔 전에 파일 구조를 먼저 확인한다. (다) 금지어가 걸리면 그 위치가 규칙·주석 필드인지 먼저 본다. (라) **레퍼런스는 원본을 본다. 썸네일·검색 결과로 원리를 뽑지 않는다.**

### 3-3. 교본
`docs/curriculum/` 8편. 모든 에이전트가 자기 직군 교본 + `00_COMMON` + `07_AI_GAMEDEV`를 먼저 읽고, 보고서에 적용 원칙을 번호로 인용한다. 이탈은 사유를 적으면 인정한다(M3).

### 3-4. 스프린트 리듬
보드 작성 → 병렬 착수 → 완료 즉시 검수 → 통합 → 회고 3줄 → 다음 보드.
한 스프린트는 반나절~하루, 목표는 한 문장.

## 4. 화면 설계

### 4-1. 거점 단면 (1막 본 화면) — `/base`
**시점**: 정면 직교, 원근 없음. 거점 전체가 한 화면에.
**구조**: 맨 위 돔 → 아래로 유리 척추(승강 통로) → 층마다 좌우로 방. 성장 방향은 **아래**.
**세로축**: 화면 위부터 광층 → 박광층 → 무광층(거점) → 해구 문턱 → 해구.
**규칙**: 최대 건설 깊이 180m, 해구 210m. **거점은 해구에 닿지 못한다**(DECISIONS 2026-09-26). 마지막 구간은 잠수복으로 걸어서 간다.
**참조 그림**: `art_raw/deep/section_hero.png`, `section_zoom.png`

**UI 배치**(레퍼런스 §1-9: UI는 가장자리에만)
- 상단: 자원 막대, 날짜, 막 표시
- 우측 세로: 깊이 구역 이름
- 하단: 공기 띠·깊이 띠, 줌 버튼
- 화면 가운데는 **언제나 거점**

### 4-2. 원정 (바깥) — 아이소 3D 재사용
거점 밖은 45° 아이소 3D. `world.html`의 지형·안개·발견 연출을 그대로 쓴다.
**에어락이 두 시점의 전환점**이고, 그 순간 리더의 목소리가 끊긴다(오디오 사양 확정됨).

### 4-3. 스캔
현재 `/`에 구현되어 있다. `BarcodeDetector` API + 후면 카메라, 미지원 브라우저는 숫자 입력 폴백. **거점 화면에 이 기능을 옮겨야 한다.**

### 4-4. 사건 카드
밤에 쪽지가 도착하고, 대항 카드/방/사람으로 막는다. 현재 `/`에만 있다.

## 5. 아트 바이블 (요약, 원문은 `docs/refs/`)

**전체 형식(2026-10-01 확정)**: **2.5D — 배경은 3D 렌더, 캐릭터는 도트.** 해상도 대비를 의도적으로 쓴다. 성립 조건 다섯은 `DECISIONS.md` 참조(특히 **캐릭터가 방의 등불색을 받아야 한다** — 이걸 빠뜨리면 스티커로 보인다).

**목표 화풍**: 평면 민속화풍. 원리 12가지는 `REF_ART_FLAT_FOLK.md`. ⚠️ 그 문서 §0의 정정(얼굴을 전부 그린다·따뜻한 중간 명도·거친 결)을 먼저 읽을 것.
핵심 다섯: 음영 2단 / 극단적 명도 대비 / 방마다 고유 색 / 장식 무늬가 디테일을 대신함 / 손으로 그은 흔들리는 선.

**팔레트**
- 실내·사람: 크림·뼈, 황토, 번트오렌지, 적갈, 숯검정, 탁한 올리브

- 화면에서 가장 밝은 것은 **언제나 방 안의 등불**

**파이프라인** (이 순서를 지킬 것)
1. 자세·일관성은 **3D에서**(기존 GLB). 새로 그리지 않는다.
2. 표면은 Blender 비사실 렌더(2단 램프 + Freestyle 노이즈 선 + 종이 결).
3. 장식 무늬는 후처리 레이어. 역할마다 다른 무늬 → 70px에서 구분된다.
4. 생성 AI는 카드 그림·초상 같은 한 장짜리에만. 캐릭터 통짜 생성 금지(일관성 함정).

**소재 번역**: 털 목도리 → 잠수복 목 실링 / 새 두개골 → 구식 잠수 헬멧 / 옷단 문양 → 기운 자국·따개비.

**하지 않을 것**: 레퍼런스 작품의 캐릭터·투구 형태·문양을 그대로 옮기지 않는다. 생성 AI 프롬프트에 작가명·작품명 금지.

## 6. 시스템 사양

### 6-1. 바코드 → 유물 (완성)
EAN-13/UPC-A/ISBN 체크섬 검증 → 국가·제조사 코드 파싱 → **결정론적 시드**로 희귀도·이름·플레이버 생성. 같은 바코드는 언제나 같은 유물.
희귀도 문턱 990/950/850/600 → 1/4/10/25/60%. 재스캔 감쇠 [1.0, 0.5, 0.1, 0].
화면에 뜨는 제조 가문은 **창작 이름**, 실제 상표는 숨김 필드로만(카테고리 판정용).

### 6-2. 사건과 막 (완성)
카드에 `acts` 배열(1 심해 / 2 터널 / 3 지상 / [1,2,3] 공용). 방주 상태의 `act`로 풀을 거른다.
대항: 역할 태그 ∩ 사건 태그, 또는 카드, 또는 방.

### 6-3. 각인 = 계단식 성장 (완성)
**처음 겪는 종류의 위기를 넘겼을 때만** 외형과 능력이 변한다. 각인 3개 → 역할 진화(부족 신화에서 이름을 받는다).
참여자는 **사건에 나선 1~2명**만(hero → 배치 → 역할 태그 → 카드 태그 → 시드 난수).

### 6-4. 스팟과 소문 (완성)
스캔 카테고리 누적으로 스팟 단서가 해금된다. 12곳이 8개 카테고리에 흩어져 있어 **한 종류만 찍으면 안 열린다**. 발견이 목적이고 거주는 불가.
