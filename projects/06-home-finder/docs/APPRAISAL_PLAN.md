# 매물 투자 심사 엔진 (Property Underwriting Engine) — 기획서

**작성일**: 2026-08-08
**목표**: 서울 지역 주택/상가 매물의 **주소·희망가·특이사항**을 입력하면,
현재가치·미래가치·총비용·수익률을 계산해 **"이 가격에 사는 것이 경제적으로 합리적인가"** 를 판정한다.

---

## 0. 왜 새 엔진인가 (기존 HomeFinder와의 관계)

| 구분 | HomeFinder (기존) | 심사 엔진 (신규) |
|------|------------------|-----------------|
| 목적 | **탐색(Discovery)** — 많은 매물 중 고르기 | **심사(Underwriting)** — 지목한 1건이 살 만한가 |
| 입력 | 필터 조건 (예산/지역/면적) | 특정 물건 (주소/가격/조건) |
| 출력 | 매물 리스트 + 점수 | 밸류에이션 리포트 + 매수 판정 |
| 평가법 | 거래사례비교법 1종 | 감정평가 3방식 + DCF |
| 시간축 | 현재 시점 | 보유기간 N년 현금흐름 |

**결론**: HomeFinder **내부 서브시스템(`appraisal/`)으로 추가**한다.
이 엔진은 실거래 DB에 전적으로 의존하는데, 그 DB·수집기·스케줄러·API키가 전부 HomeFinder에 있다.
별도 프로젝트로 분리하면 DB 동기화 문제부터 생긴다.

### 재활용 자산
- `models/transaction.py` — 실거래 이력 테이블 (4,369건+)
- `collectors/molit_collector.py` — 국토부 API 연동 패턴 (`BaseCollector` 상속)
- `services/price_analyzer.py` — 거래사례비교법 3단계 매칭 (→ 방식①의 기반)
- `.env` — `PUBLIC_DATA_API_KEY`(64자), `KAKAO_REST_API_KEY`(32자) 보유
- FastAPI + SQLite + APScheduler 인프라

### 신규 필요
- 상업용 실거래·임대 데이터 (상가는 비교군이 성립 안 됨 → 수익환원법 필수)
- 총비용/세금 모델 (취득세·보유세·양도세)
- 미래가치 추정 (인구·공급·상권·교통)
- 의사결정 레이어 (NPV/IRR vs 기회비용)

## 1. 데이터 소스 설계 — "어디서 가져오는가"

### 1-1. 현재가치 축

| 데이터 | 소스 | 상태 | 용도 |
|--------|------|------|------|
| 아파트/연립/단독 매매 실거래 | 국토부 RTMS (PublicDataReader) | ✅ 연동됨 | 주택 비교사례 |
| **상업업무용 매매 실거래** | 국토부 RTMS 비주거 (같은 키) | 🔨 신규 | 상가 비교사례 |
| **개별공시지가** | VWorld / 국토부 | 🔨 신규 (키 발급) | 원가법 토지가 |
| **건축물대장** | 국토부 건축물대장 API (같은 키) | 🔨 신규 | 연면적·용도·사용승인일(노후도) |
| **토지이용계획** | VWorld | 🔨 신규 | 용도지역·규제 |

### 1-2. 수익 축 (상가 핵심)

| 데이터 | 소스 | 상태 | 용도 |
|--------|------|------|------|
| **상업용 임대료·공실률·투자수익률** | 한국부동산원 상업용부동산 임대동향조사 | 🔨 신규 | Cap Rate 기준값 |
| **상권 유동인구·업종·점포수** | 소상공인시장진흥공단 상권정보 API | 🔨 신규 | 상권 활성도 |
| 주택 전월세 실거래 | 국토부 RTMS 전월세 | 🔨 신규 | 주택 임대수익률 |

### 1-3. 미래가치 축

| 데이터 | 소스 | 상태 | 용도 |
|--------|------|------|------|
| 인구·세대수 추이 | 행안부 주민등록 / KOSIS | 🔨 신규 | 수요 추세 |
| 입주 예정 물량 | 청약홈 (기존 collector) + 부동산원 | ♻️ 확장 | 공급 충격 |
| 지하철역·승하차 | 서울열린데이터 (기존 collector) | ♻️ 재활용 | 교통 접근성 |
| 개발 호재 (재개발·GTX 등) | 반자동 (사용자 입력 + 도시계획) | 🔨 신규 | 시나리오 조정 |

### 1-4. 할인율 축 (기회비용) — **일반적으로 놓치는 부분**

| 데이터 | 소스 | 용도 |
|--------|------|------|
| 국고채 3년/10년 금리 | 한국은행 ECOS API | 무위험수익률 |
| 주담대·상가담보대출 금리 | ECOS | 레버리지 비용 |
| 소비자물가지수 | ECOS/KOSIS | 실질수익률 환산 |

> **핵심**: "시세보다 싸다"는 판단만으로는 부족하다.
> 그 돈을 예금·채권·지수에 넣었을 때보다 나은지 비교해야 "경제적으로 합리적"이라 말할 수 있다.

## 2. 평가 엔진 아키텍처

```
[입력] 주소 · 희망매수가 · 유형(주택/상가) · 특이사항(층/전면/노후/임차현황)
   │
   ├─▶ [A] 정규화 · 식별
   │      주소 → 법정동코드 · PNU · 좌표 (Kakao Geocoding)
   │      → 건축물대장 조회 (연면적/용도/사용승인일)
   │
   ├─▶ [B] 현재가치 — 감정평가 3방식
   │      ① 거래사례비교법  : 실거래 comparables (기존 PriceAnalyzer 확장)
   │      ② 수익환원법      : NOI ÷ Cap Rate        ← 상가 주력
   │      ③ 원가법          : 토지(공시지가×배율) + 건물(재조달원가−감가)
   │      → 유형별 가중결합 → 추정 적정가 [하한 ~ 상한]
   │
   ├─▶ [C] 총소유비용(TCO) · 현금흐름
   │      초기: 취득세 · 중개보수 · 법무 · 수선
   │      연간(-): 재산세 · 종부세 · 관리비 · 수선충당 · 공실손실
   │      연간(+): 임대료 · 보증금 운용수익
   │      금융: LTV/DSR 한도 · 원리금 상환
   │
   ├─▶ [D] 미래가치 — 시나리오 3종 (낙관/기준/비관)
   │      성장률 g ← 인구·세대 추세 + 공급물량 + 상권/교통 + 물가
   │      → N년 후 매각가 − 양도세 − 중개보수
   │
   └─▶ [E] 의사결정
          NPV · IRR (할인율 = 요구수익률)
          vs 대안투자(예금/국고채/지수)
          → 판정 + 근거 + 리스크 + **협상 목표가**
```

### 유형별 가중치 (방식 결합)

| 자산 유형 | 비교법 | 수익환원 | 원가법 | 이유 |
|-----------|-------|---------|--------|------|
| 아파트 | 0.80 | 0.10 | 0.10 | 동일 규격 대량 거래 |
| 단독/다가구 | 0.40 | 0.25 | 0.35 | 개별성 큼, 토지비중 큼 |
| **상가(집합)** | 0.25 | **0.65** | 0.10 | 수익이 가치를 결정 |
| **상가(건물)** | 0.15 | **0.60** | 0.25 | 수익 + 토지가치 |

## 4. ⚠️ 블로커 — 공공데이터포털 API 활용신청

보유 중인 `PUBLIC_DATA_API_KEY`의 실제 권한을 테스트한 결과:

| 엔드포인트 | 상태 |
|-----------|------|
| 아파트 매매 | ✅ 정상 (강남구 202605 → 461건) |
| 토지 매매 | ✅ 정상 (44건) |
| **상업업무용 매매** | ❌ **403 (미신청)** |
| 오피스텔 매매 | ❌ 403 (미신청) |
| 단독다가구 매매 | ❌ 403 (미신청) |

**공공데이터포털은 API마다 별도 활용신청이 필요하다.** 키가 만료된 게 아니라
해당 오퍼레이션을 신청하지 않은 상태다.

### 조치
1. https://www.data.go.kr 로그인
2. "국토교통부_상업업무용 부동산 매매 신고 자료" 검색 → 활용신청
   (개발계정은 통상 즉시~1시간 내 승인)
3. 승인 후: `python collect_commercial.py 12` 실행

### 함정 기록
`PublicDataReader`는 403을 **예외로 던지지 않고 빈 DataFrame을 반환**한다.
그대로 두면 권한 문제가 "성공 0건"으로 위장된다 — 토지 수집기에서 실제로 겪었던 버그.
`commercial_collector`는 전건 빈 응답(3건 이상)을 `RuntimeError`로 승격시켜 방지한다.

## 5. 남은 판단 이슈

**요구수익률 10%는 현재 한국 상가시장에서 사실상 통과 불가 허들이다.**
국내 상가 Cap Rate가 4~5%대이므로, 10%를 요구하면 협상 목표가가 호가의 50% 수준으로 산출된다.
데모에서 12억 호가 물건의 목표가가 6.47억(-46%)으로 나온 것이 그 예다.

현실적 대응은 셋 중 하나:
1. 요구수익률을 6~7%로 하향 (`--required 0.07`)
2. 급매·경매·공실 정상화(밸류애드) 물건으로 대상을 좁힘
3. 상가 대신 다른 자산군 검토

엔진은 세 경우 모두 그대로 쓸 수 있다 — 파라미터만 바꾸면 된다.
